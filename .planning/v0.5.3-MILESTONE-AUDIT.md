## Phase 78 gap fix

A cooldown's buff now follows its live aura. A buff already up at login/reload, after an add or
edit, or stacked (two flasks, an engineering extension) shows its real remaining time. It goes
through the cooldown-buff half of `ns:RefreshAuraStates`, which shares `ReadWatchedList`,
`SyncProcToAura` and `ns:FillCooldownBuffProc` with the reminder half and the cast path. The typed
Duration is never written from a read (user decision 2026-10-22).

The user confirmed the flask and engineering-item cases in game. Commits: `838e93c`, `09f36aa`,
`469ff35`. `5533775` closes audit warning 1 (below).

## Integration (gsd-integration-checker, 2026-10-23)

All four flows are wired:
1. Spell cooldown: dialog → cast → yellow buff → end (expiry, readable aura loss, reset-on-cast,
   edit, hide) → grey cooldown.
2. Bag item: moved out of Suggested → buff-only edit → use → buff on the item's own icon.
3. Reload/login with the aura up → read-start and expiry follow, with the typed Duration untouched.
4. Aura-read gate: `node scripts/aura-read-gate.js` passes, and so does its 30-case selftest.
