**Three requirements changed meaning rather than status**, by user decision on 2026-09-22, and their
original text is struck through in place rather than deleted:

- **`CD-02` reversed.** A cooldown tracker runs on the duration the user typed, timed from the
  observed cast — not on the game's own duration handle. Reported as "the TBT CD is being overwritten
  by the actual CD"; the investigation found the typed value had never been used for any spell the
  client knows, and the racial appeared to work only because 3m is genuinely its cooldown. Accepted
  cost: haste, CDR and resets make the displayed time wrong. Merged CDM slots keep the engine handle
  and are unaffected.
- **`ADD-01` and `ADD-02` superseded.** Both were dropped as *controls*. The add dialog's type now
  comes from the active tab and says so in its title, and every new tracker lands in Not Displayed.

**One requirement was recorded PARTIAL for most of the milestone and is now closed:** `STEAL-04`.
The PARTIAL note said merged buff icons draw no sweep, which was true of every route that *reads* the
aura and false of the one that ships — the engine draws them via `AuraContainer`
(`MergeMode.lua:809`), recorded as pass in `43-FOREVER-E2E-PASS.md`.

### Cooldown Tracking

- [x] **CD-01**: User can register a spell cooldown as a tracker, choosing "cooldown" rather than "buff" when adding it
- [x] **CD-02**: A cooldown tracker displays as an icon with a sweeping cooldown animation driven by ~~the game's own duration handle, so it stays correct in combat and follows cooldown reduction live~~ **the duration the user typed, timed from the cast TBT saw** (REVERSED by user decision 2026-09-22 — see the note below)
- [x] **CD-03**: A cooldown tracker on a multi-charge spell shows the current charge count and recharges correctly
- [x] **CD-04**: A cooldown tracker works for spells the Blizzard CDM does not support
- [x] **CD-05**: A cooldown tracker renders correctly in preview mode alongside buff trackers
- [x] **CD-06**: Cooldown trackers persist across sessions, and an existing buff-only database migrates without loss

**CD-02 was reversed on 2026-09-22, by user decision, after play-testing.** The original wording is
kept struck through above rather than rewritten, because the reasoning behind it is still true and
should not have to be rediscovered: the game's handle is exact and follows cooldown reduction, where
a typed number cannot, so haste, CDR and reset procs now make the displayed time wrong.

It was reversed because deferring to the game made the typed value do **nothing at all** for any
spell the client already tracks — which is how it was reported: "I'm setting a higher then actually
is CD for a skill (that is on CDM) but the TBT CD that shows is being overwritten by the actual CD".
A player who types a duration for a spell the game knows is telling TBT something the game does not:
an internal cooldown, a "do not use again yet" reminder, a pull timer.

Merged CDM slots are NOT affected — they carry no typed duration and keep the real handle. So the
Phase 43 check for this requirement is the opposite of what the table below says: verify the
displayed time matches the TYPED value and ignores cooldown reduction, and that a merged Essential
or Utility slot still follows the game.

### Merge Mode

**Renamed from "CDM Steal Mode" on 2026-09-21** (user decision — the feature is a merge of the custom and Blizzard trackers, which is what the player gets; "steal" described what happens to Blizzard's UI). The display name, the description, every Lua identifier and the file name all say Merge Mode as of that date; `MergeMode.lua` was `StealMode.lua`, and `ns.db.mergeMode` was `ns.db.stealMode` (no migration was needed — the key had never shipped, the last tag being v0.3.0).

**The `STEAL-*` requirement IDs deliberately keep their spelling.** They are stable identifiers, referenced across the committed phase documents under `.planning/phases/40-cdm-steal-mode/` and resolved by GSD phase lookups; renaming them would break that traceability to buy nothing, since no player ever sees an ID. Read `STEAL-nn` as "Merge Mode requirement nn". The phase directory name is unchanged for the same reason.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Injecting TBT items into Blizzard's CDM containers | Measured closed 2026-09-20. Five variants, including one using zero Blizzard Lua, all taint the CDM; the taint is sticky and clears only on `/reload`. TBT mirrors into its own containers instead |
| Per-category steal toggle | User decision 2026-09-20 — all-or-nothing keeps the renderable state space small in the first cut |
| Racials beyond Eureka! | User decision 2026-09-20 — each racial is an individually-specified special case; the next minor milestone completes the catalog |
| Reading aura data directly through `C_UnitAuras` under restriction | Hard-errors for tainted callers, both enumeration and ID-based. A cached instance ID does not help. Closed, not deferred |
| Extracting secret values via `C_CurveUtil` curves | Measured 2026-09-20 — curve results are secret even from an addon-built curve. Curves relocate a comparison into the engine; they do not extract data |
| Two flavour-pure zips | Reversed 2026-09-20 by the single-TOC / single-zip decision |
| Retiring the Trinket and Pot meta-trackers | User decision 2026-09-20 — they keep custom durations and bar display, and META-01 already hides them on Forever. Only the public copy changes |
| Probing the secret-value API on retail | Skipped by user decision 2026-09-20 to save time. Retail work in this milestone is a validation pass (`VER-10`), not a probe |
| Runtime flavour branching beyond `ADD-03` | `ADD-03` is the one sanctioned flavour check. Everything else stays on data-absence / capability checks |
