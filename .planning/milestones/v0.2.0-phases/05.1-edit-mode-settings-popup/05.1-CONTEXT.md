# Phase 5.1: Edit Mode Settings Popup - Context

**Gathered:** 2026-03-29
**Status:** Ready for planning

<domain>
## Phase Boundary

When Edit Mode is active and TBT containers are enabled, clicking a container selects it with a yellow/selected highlight and opens a settings popup. The popup provides CDM-like settings (orientation, growth direction, scale, padding, visibility, bar width) per container. Settings persist in TerribleBuffTrackerDB and replace the hardcoded display defaults in Display.lua.

</domain>

<decisions>
## Implementation Decisions

### Selection & highlight
- **D-01:** Clicking a TBT container in Edit Mode selects it with a yellow/selected NineSlice highlight using `editmode-actionbar-selected` atlas (matches CDM's own selected state).
- **D-02:** Only one container can be selected at a time. Clicking another container switches selection. Clicking outside both containers deselects.
- **D-03:** Selection coexists with the existing drag behavior — clicking selects, click-and-hold starts drag. The selection highlight shows on click (OnMouseUp after a non-drag click).

### Settings popup content
- **D-04:** Full CDM-like settings per container type:
  - **Bars container:** Orientation (Vertical/Horizontal), Growth direction (dropdown), Bar width (slider), Scale (slider), Padding (slider), Visibility (dropdown: Always/In Combat/Hide When Inactive)
  - **Buffs container:** Orientation (Vertical/Horizontal), Growth direction (dropdown), Scale (slider), Padding (slider), Visibility (dropdown: Always/In Combat/Hide When Inactive)
- **D-05:** Settings controls use Blizzard UI templates — dropdowns, sliders, checkboxes matching the CDM Edit Mode settings popup style.

### Popup visual style
- **D-06:** Match CDM's own Edit Mode settings popup style and visual treatment.
- **D-07:** Popup appears anchored to the selected container (e.g., to the right or below).
- **D-08:** Popup hides when Edit Mode exits or container is deselected.

### Settings persistence
- **D-09:** Per-container settings stored in `ns.db.containerSettings.bars` and `ns.db.containerSettings.buffs` — each container has its own independent settings.
- **D-10:** Settings replace the hardcoded `cachedBarSettings` and `cachedIconSettings` in Display.lua. Display.lua reads from `ns.db.containerSettings` instead of hardcoded values.
- **D-11:** Default values for fresh installs match the current hardcoded CDM-matching defaults so existing behavior is preserved.

### Claude's Discretion
- Exact slider ranges (min/max for scale, padding, bar width)
- Popup frame size and anchor point relative to container
- How to detect click vs drag (threshold or OnMouseUp timing)
- Whether to show a preview of setting changes in real-time

</decisions>
