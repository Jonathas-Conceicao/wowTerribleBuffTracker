# Phase 2 — UI Design Contract: Edit Mode Containers

> Visual and interaction contract for the two independently movable TBT containers
> registered with WoW's Edit Mode system. Generated by gsd-ui-researcher.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (WoW Lua addon — no web framework) |
| Preset | not applicable |
| Component library | Blizzard CDM atlas textures (existing; see Display.lua) |
| Icon library | Blizzard atlas: `UI-HUD-CoolDownManager-*` |
| Font | Blizzard font objects: `NumberFontNormal` (existing), `GameFontNormal` (drag label) |

---

## Spacing Scale

All values are WoW frame units at 1x scale (equivalent to screen pixels at 100% UI scale).
Must be multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon inner gap, drag handle border inset |
| sm | 8px | Edit Mode label offset from container edge |
| md | 16px | Container minimum padding around content |
| lg | 24px | Minimum touch target for drag handle height |
| xl | 32px | Minimum container width when empty |

Exceptions:
- `BAR_PADDING_OFFSET = -2` and `ICON_PADDING_OFFSET = -4` are inherited from existing CDM-matching logic; do not change these values — they are not spacing tokens, they are CDM visual compensations.
- Drag handle overlay height is 24px (lg token) regardless of container scale to remain hittable.

---

## Typography

All font objects are Blizzard globals. Do not use custom fonts.

| Role | Font Object | Size | Weight | Line Height |
|------|-------------|------|--------|-------------|
| Edit Mode container label | `GameFontNormal` | 12px (Blizzard default) | Bold | 1.2 |
| Bar name text | `NumberFontNormal` | ~12px (Blizzard default) | Normal | n/a (single line) |
| Bar timer text | `NumberFontNormal` | ~12px (Blizzard default) | Normal | n/a (single line) |

Notes:
- Typography is not configurable in this phase. All text uses Blizzard font objects already established in Display.lua.
- The Edit Mode drag label ("TerribleBuffTracker") displayed on the drag handle uses `GameFontNormal` with white text (`1, 1, 1, 1`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `0, 0, 0, 0` (transparent) | Container background — containers are visually transparent when not in Edit Mode |
| Secondary (30%) | `0, 0, 0, 0.5` (semi-transparent black) | Drag handle background during Edit Mode only |
| Accent (10%) | `0.2, 0.6, 1.0` (CDM blue) | Active bar fill (existing); Edit Mode selection highlight border |
| Destructive | n/a | No destructive actions in this phase |

Accent reserved for:
- Active status bar fill (inherited from existing `GetBarColor` — fraction > 0.3 threshold)
- Edit Mode drag handle border (1px solid, alpha 0.8) to signal "this element is movable"

Edit Mode state colors:
- Drag handle background: `0, 0, 0, 0.5`
- Drag handle border: `0.2, 0.6, 1.0, 0.8` (CDM accent blue at 80% alpha)
- Drag handle label text: `1, 1, 1, 1` (white)
- When a container has no visible items (empty): drag handle still renders at full opacity — do NOT hide the handle when empty, as that would make the container undiscoverable in Edit Mode.

## Default Positions (Fresh Install)

Source: CONTEXT.md D-06 (hardcoded defaults, no CDM copy).

| Container | Point | x | y | Notes |
|-----------|-------|---|---|-------|
| `TBTBarContainer` | `CENTER` on `UIParent` | 300 | 0 | Right-center of screen; avoids overlapping default CDM position |
| `TBTBuffContainer` | `CENTER` on `UIParent` | 300 | -80 | Below bar container at default 1.0 scale |

"Fresh install" detection: `ns.db.editModePositions == nil` (CONTEXT.md D-07).

After the user saves a position via Edit Mode, `editModePositions` is non-nil and these defaults are never reapplied.

## DB Schema: editModePositions

Source: CONTEXT.md — Claude's Discretion area.

```lua
-- TerribleBuffTrackerDB.editModePositions (added in Core.lua ADDON_LOADED)
{
    bars = {
        point         = "CENTER",   -- string, WoW anchor point constant
        relativeTo    = "UIParent", -- string, GetName() of anchor frame
        relativePoint = "CENTER",   -- string
        x             = 300,        -- number, horizontal offset
        y             = 0,          -- number, vertical offset
    },
    icons = {
        point         = "CENTER",
        relativeTo    = "UIParent",
        relativePoint = "CENTER",
        x             = 300,
        y             = -80,
    },
}
```

Key: always use `"UIParent"` as the `relativeTo` string for Edit Mode containers.
Reason: PITFALLS.md Pitfall 5 — `ConvertToAnchorInfo` uses `GetName()`; parenting to CDM frames would re-introduce CDM coupling.

## Edit Mode Interaction Contract

### States

| State | Visual | Interaction |
|-------|--------|-------------|
| Normal (Edit Mode inactive) | Container transparent, no handle visible, bars/icons render normally | `SetMovable(false)`, `EnableMouse` only on tooltips |
| Edit Mode active | 24px drag handle appears at top of each container; semi-black background with blue border; "TerribleBuffTracker" label centered | `SetMovable(true)`, `EnableMouse(true)` on container, drag handle captures `OnMouseDown`/`OnMouseUp` |
| Dragging | Container follows cursor; drag handle remains attached at container top | `StartMoving()` on `OnMouseDown "LeftButton"`, `StopMovingOrSizing()` + position save on `OnMouseUp` |
| Empty container in Edit Mode | Same as Edit Mode active — drag handle visible, container body shows nothing beneath handle | Never hide the handle due to empty content |

### Sidebar Checkbox

- Label: `"TerribleBuffTracker"` (CONTEXT.md D-05)
- Toggle controls: both `TBTBarContainer` and `TBTBuffContainer` visibility together (single checkbox, not per-container)
- Checkbox state persists in `ns.db.tbtVisible` (boolean, default `true`)
- When unchecked: both containers `Hide()` immediately; handle also hidden (whole container is hidden)
- When re-checked: both containers `Show()` immediately; re-enters current Edit Mode state

### Position Save Trigger

- Positions are saved in `EventRegistry "EditMode.Exit"` callback (not on `OnMouseUp`)
- Reason: user may drag multiple times before saving; only commit on Exit to match Blizzard pattern
- On `OnMouseUp` after drag: call `StopMovingOrSizing()` only — do not write DB
- On `EditMode.Exit`: read `barContainer:GetPoint(1)` and `iconContainer:GetPoint(1)`, write to `ns.db.editModePositions`

### CDM Hook Guard (Pitfall 9)

When `ns.db.editModePositions` is non-nil (user has set a position):
- `HookViewerLayout` callbacks must NOT re-anchor containers to CDM frames
- `SnapshotSettings()` still runs (reads CDM bar width, scale, alpha) but does not touch container position
- Guard condition: `if not ns.db.editModePositions then ... end` wraps any CDM-relative anchor calls
