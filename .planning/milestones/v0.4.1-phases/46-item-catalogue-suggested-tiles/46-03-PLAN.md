<objective>
Render the catalogue. Add a charge-count fontstring to the shared Suggested/tracked tile factory,
then append an item tile loop to the Cooldowns tab's Suggested branch, after the racial tiles.

Purpose: ITEM-03 in full — "a Suggested consumable tile shows the item's own icon and the number the
player currently holds". ITEM-10 continues: the count and icon come from cached values that were
already `issecretvalue()`-guarded at scan time, so an unreadable value degrades the tile rather than
erroring, on either flavour.

Output: visible item tiles. This is the last code plan of the phase.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Catalogue cache -> render path | Values were `issecretvalue()`-guarded at scan time (Plan 01). A rejected value is stored as nil, so the render path's only obligation is to hide the affected detail rather than re-guard. |
| SavedVariables -> render path | `ns.db.trackedBuffs` membership is read to skip already-tracked items. Read-only this phase. |
| Pooled frame state -> new tile | A recycled frame carries the previous tile's field values. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-08 | Information Disclosure (wrong data shown) | pooled tile recycling | mitigate | `chargeCount` cleared and hidden in the `section.itemPool` reset function on every `ReleaseAll()`, plus an unconditional `SetText`+`Show` or `Hide` on every item tile every pass. Both acquisition paths (recycled and freshly created) start hidden. |
| T-46-09 | Tampering | unreadable icon or count | mitigate | Icon falls back to `134400`; a nil count hides the fontstring. The tile still renders. Degrade, never error, never a stale value. |
