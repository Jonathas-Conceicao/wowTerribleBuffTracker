Add one shared helper and route three existing walks through it. All three are milestone-introduced

1. **Define `function ns:RacialDefInList(defs, spellID)`** in `Providers.lua`, immediately above
   `ns:RacialDefForSpellID`. It walks `ipairs(defs)` and returns the first def whose `def.spellID ==
   spellID`, or nil. It allocates nothing and takes the list as a parameter — the list a caller walks
   is the thing that actually differs between the three, so it must stay the caller's choice.

   **On `ns`, not a file-local.** A `local function` is an upvalue only to functions declared after
   it, and this project has shipped that bug five times; `ns:` resolves at call time, so declaration
   order stops mattering. Say this in the helper's comment.

2. **`ns:RacialDefForSpellID(spellID)`** becomes a single `return
   ns:RacialDefInList(ns:RacialDefsForPlayer(), spellID)`. Keep its existing comment about being
   ungated by flavour.

3. **`ns:RacialCooldownSeed(spellID)`** calls `ns:RacialDefInList(ns:RacialSuggestions(), spellID)` and
   then applies its own `def.cooldown` field test, returning the def only when that field is set.
   **It must keep walking `ns:RacialSuggestions()`, NOT `ns:RacialDefsForPlayer()`.** `RacialSuggestions`
   returns `EMPTY_RACIAL_DEFS` on retail; substituting the ungated list would start seeding racial
   cooldown tiles on retail, which is a behaviour change and out of bounds for this phase. Add a
   one-line comment at the call recording that the gated list is deliberate.

4. **`ns:IsRacialKeyVisible(key)`** replaces its inline `for _, def in ipairs(rawDefs)` walk with
   `ns:RacialDefInList(ns:RacialDefsRaw(), spellID)`, returning true when it finds one. **It must keep
   using the RAW list** for the reason its own comment already gives — visibility is a question about
   race membership, not about client spell data, and it must not depend on a memo that can still be
   empty this session. Everything after that walk (the `racialSpellOwners[spellID]` test and the two
   remaining returns) is unchanged.

5. **`ns:ConditionalCooldown` is already reduced** to `ns:RacialDefForSpellID` plus a field test. Do
   not touch it.

**Leave the three key parsers in `Core.lua` alone.** `ns:CooldownKeySpellID` (`Core.lua:493`),
`ns:ItemKeyItemID` (`:519`) and `ns:RacialKeySpellID` (`:546`) are NOT unified, and `Core.lua` is not
in this plan's `files_modified`. Record this decision and its reason in the SUMMARY: `cd:` predates the

three clear five-line functions. CONTEXT.md's recorded default is to leave all three unless `cd:` can
be unified without touching its behaviour; this is that call, made and written down.

  <action>
**Part A — close the one confirmed avoidable allocation.**

`ns:IsRacialKeyVisible` is called once per entry in `ns.db.trackedBuffs`, per container, per render
pass, from both `Display.lua:1969` and `Display.lua:2238`. Its first line runs
`ns:RacialKeySpellID(key) or ns:CooldownKeySpellID(key)`, and each of those is a `string.match` with a
`(%d+)` capture — which allocates a fresh capture string every time the key matches, i.e. on every
racial and every cooldown tracker, twenty times a second.

Add a module-level memo in `Providers.lua`, declared near the other module-level racial tables:
a table (suggested name `racialGateKeyIDs`) mapping the DB key to the parsed spellID, or `false` when
the key parses as neither. In `ns:IsRacialKeyVisible`, read the memo first; on a miss, compute
`ns:RacialKeySpellID(key) or ns:CooldownKeySpellID(key) or false`, store it, and carry on. Treat a
stored `false` as the existing "not a racial-shaped key at all" early return.

Why this is safe, and say so in the comment: the parse is a pure function of the key STRING — same key
in, same answer out, forever — so unlike a memo of the visibility ANSWER it can never go stale against
`ns:RacialDefsRaw()`'s fill state or against the player's race. Do NOT memoise the visibility answer
itself; that is the thing the function's existing comment warns against. Growth is bounded by the
number of distinct tracker keys the session ever sees. Never `wipe()` it — a wipe would only re-pay the
cost it exists to avoid.

Do not add the memo inside `Core.lua`'s parsers. `cd:` is pre-existing and protected, and the memo
belongs at the caller that made it hot.

**Part B — audit, and record. No other code change unless a finding clears the bar.**
