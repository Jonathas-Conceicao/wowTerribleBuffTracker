<objective>
Make the drop real. Teach `AddSuggestedTracker` about `item:` keys (ITEM-04), widen
`ns:GetTrackerCategory` so a tracked item files under Cooldowns (silent-failure trap 1a), and wire
the two already-registered events that keep it correct out of combat (ITEM-07).

Purpose: Phase 46 deliberately left dragging an item tile a documented no-op (its gate G7). This
plan is what turns that no-op into a created entry, and it is where the icon trap — an item entry
has no `spellID`, so `ApplyCachedIcon` can only ever resolve `entry.iconOverride` — gets closed at
the one moment it can be, creation time.

Output: an `ns.db.trackedBuffs["item:<itemID>"]` entry with `trackerType = "item"`, `itemID`,
`iconOverride` and a seeded cooldown, filed under the Cooldowns category, plus the combat-end and
bag-cooldown wiring. **The tile still will not render after this plan** — `Display.lua`'s dispatch
gate is Plan 03's.

Decision IDs are defined in `47-01-PLAN.md`'s objective table. This plan implements **D-05**
(seed the cooldown at tracker creation), consumes D-02 and D-03's helpers, and is bound by **D-06**
(`Core.lua`'s debug cast/item log at `Core.lua:1164-1332` is protected and must not be touched).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Drag/drop input → `ns.db.trackedBuffs` | A dropped tile's `key` is an opaque string supplied by the Suggested render loop. `ns:ItemKeyItemID` is the only parser that admits it, and it accepts nothing but `^item:(%d+)$`. |
| WoW client API → TBT Lua | Not crossed in this plan. `CDMTab.lua` makes no `C_Item` read; every guarded read is delegated to `Providers.lua` (Plan 01). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-05 | Tampering (a malformed key creating a junk DB entry) | `AddSuggestedTracker` | mitigate | `ns:ItemKeyItemID`'s anchored `^item:(%d+)$` pattern plus the existing `ns:GetDisplayInfoForKey` nil check; a key that resolves to neither a cooldown spell, a suggested key nor an itemID still returns having created nothing. |
| T-47-06 | Information disclosure (a wrong icon or tooltip implying the wrong item) | item entry `spellID` field | mitigate | `spellID` stays `nil` for an item entry, so `ApplyCooldownSlot` cannot resolve a spell icon or a spell tooltip for it; `iconOverride` carries the item's own icon. Asserted by Task 2's gate. |
| T-47-07 | Denial of service (a dropped tracker that never becomes visible) | `ns.trackerGeneration` staleness | mitigate | `ns:MarkTrackersDirty()` at the end of `AddSuggestedTracker`. |
| T-47-08 | Tampering (of a protected, unrelated feature) | `Core.lua`'s debug cast/item log | mitigate | D-06. Enforced by a diff-scoped gate rather than a whole-file grep, because the block legitimately contains the very tokens a naive gate would forbid. |
| T-47-SC | Tampering | npm/pip/cargo installs | accept | Not applicable — no package manager in this project (`47-RESEARCH.md` § Package Legitimacy Audit). |
