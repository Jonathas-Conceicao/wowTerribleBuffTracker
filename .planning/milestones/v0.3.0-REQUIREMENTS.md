# Requirements: TerribleBuffTracker — v0.3 WoW Forever compatibility

**Defined:** 2026-09-18
**Core Value:** Players can see countdown timers for buffs/cooldowns that the game no longer surfaces automatically.

**Milestone scope:** Metadata and tooling only. One TBT package loads and runs correctly on both WoW Midnight retail (Interface 120100) and WoW Forever beta (Interface 16001). No new user-facing features. One Lua change is in scope as a parity fix (PAR-01), explicitly approved by the user.

**REQ-ID numbering** continues nothing — v0.3 opens five new categories (TOC, INST, PAR, VER, DIST). Previous milestones used PROV/LIFE/DISP/DATA/ICON prefixes, all closed.

## v0.3 Requirements

### Flavor Metadata (TOC)

- [x] **TOC-01**: TBT loads on WoW Midnight retail from `TerribleBuffTracker_Mainline.toc` at Interface 120100, with existing installs and their SavedVariables unaffected
- [x] **TOC-02**: TBT loads on WoW Forever beta from `TerribleBuffTracker_Camelot.toc` at Interface 16001
- [x] **TOC-03**: Both TOC files declare an identical file list — one shared Lua/XML source set, no flavor-forked source files
- [x] **TOC-04**: The committed `_Camelot` filename uses the exact capitalisation the packager and client require, verified through `git ls-files` rather than a Windows file browser
- [x] **TOC-05**: A local pre-tag guard rejects a TOC whose `## Interface:` value falls outside its flavor's expected range, rejects the two TOCs' file lists having drifted apart, and rejects a `.pkgmeta-<flavor>` file that does not ignore exactly the other flavor's TOC

### Install Tooling (INST)

- [x] **INST-01**: `scripts/install.bat` installs to every WoW client present on the machine, taking no arguments
- [x] **INST-02**: `install.bat` skips client folders that are not present, without reporting failure
- [x] **INST-03**: `install.bat` exits nonzero with a clear message when zero clients were installed to
- [x] **INST-04**: `install.bat` copies both TOC files alongside the shared file set, so each client can select its own

### Cross-Flavor Parity (PAR)

- [x] **PAR-01**: When no equipped trinket or bagged potion resolves, the Trinket and Pot at-rest tiles show nothing rather than a hardcoded retail item's icon and name — a flavor-agnostic guard in `TrinketProviderMixin` / `PotProviderMixin` `RefreshAtRest`, which also corrects the retail empty-bags case
- [x] **PAR-02**: Any Forever-only Lua error found during verification is fixed with a narrow defensive read, never a flavor branch or a new feature
  - **Found 2026-09-18:** the Lust Suggested tile shows no tooltip on Forever. `LustProviderMixin:GetDisplayInfo` always returns a numeric `spellID` (2825 default), so `ShowBuffTooltip` calls `GameTooltip:SetSpellByID` on a spell that does not exist on Forever and the tooltip renders empty. Fix: verify the spell resolves before taking the `SetSpellByID` branch.

### In-Game Verification (VER)

- [x] **VER-01**: **Blocking gate** — after the TOC rename, a real retail client still loads TBT, prints its load line, and `/tbt` still opens; verified before any Forever work proceeds
- [x] **VER-02**: TBT loads on a Forever beta character with no Lua error at `PLAYER_ENTERING_WORLD`
- [x] **VER-03**: TBT attaches to the Cooldown Manager on Forever, and the TBT tab injects into CDM settings with all four sections rendering
- [x] **VER-04**: A cast of a user-added spell starts a timer on Forever — confirms `UNIT_SPELLCAST_SUCCEEDED` delivers a usable spellID, which TBT's entire detection strategy rests on
- [x] **VER-05**: Timer bars and buff icons render on Forever matching CDM's own atlas-based visuals
- [x] **VER-06**: Edit Mode works end-to-end on Forever — enter/exit, container drag, settings popup, and position persistence across `/reload`
- [x] **VER-07**: Entering combat on Forever produces no uncaught Lua error from any aura read; the secret-value gate behaves as it does on Midnight
- [x] **VER-08**: Forever's degraded-state behavior is recorded against a named beta build — which of the Trinket, Pot and Lust tiles are empty, and whether PAR-01's guard renders nothing or a placeholder

### Packaging & Distribution (DIST)

- [x] **DIST-01**: Two packager config files exist — `.pkgmeta-mainline` and `.pkgmeta-camelot` — each carrying `package-as`, the manual-changelog config and the shared ignore list, and each additionally ignoring the *other* flavor's TOC; the original single `.pkgmeta` is removed
- [x] **DIST-02**: `release.yml` runs the BigWigs packager once per flavor via a job matrix, passing `-m .pkgmeta-<flavor>` and a `-n` name template containing `{game-type}`
- [ ] **DIST-03**: One pushed tag produces two distinctly-named zips — a retail one and a forever one
- [ ] **DIST-04**: Each zip contains only its own flavor's TOC, verified by unzipping both artifacts
- [ ] **DIST-05**: Both matrix jobs publish to the same GitHub release without racing, clobbering, or dropping each other's asset
- [ ] **DIST-06**: Each job's game version tag is correct — retail tagged for Midnight, forever tagged for Forever — confirmed by reading the CI log in full for game-version-match warnings, not just checking for a green status
- [ ] **DIST-07**: `RELEASE_NOTES.md` generation still produces correct notes when run once per matrix job
- [x] **DIST-08**: `CHANGELOG.md` documents Forever support, naming the tested beta build and interface number

### Forever Testing Enablers (TOOL, META) — added 2026-09-18

Approved mid-milestone. v0.3 was scoped parity-only; these two widen it deliberately because Forever
testing is blocked without the first, and the second is what the user asked for in place of a
flavor guard the locked constraints forbid.

- [x] **TOOL-01**: Mousing over a spell anywhere in the game UI appends its spell ID to the tooltip, from one shared implementation that works on both Midnight and Forever with no flavor branch
- [x] **META-01**: A Suggested meta tile (trinket / pot / lust) is hidden when none of its catalog spells resolve on the current client — data-driven, no flavor detection, and retail behaviour for an unequipped-but-resolvable catalog is unchanged

### Documentation (DOC)

- [x] **DOC-01**: `CLAUDE.md` lists `BigWigsMods/WoWUI` branch `forever-beta` as an API/style reference alongside `wow-ui-source`, and records the Forever install path and interface number

## Out of Scope

| Feature | Reason |
|---------|--------|
| Any new user-facing feature | User was explicit: v0.3 is metadata and tooling only. Parity fixes only. |
| Flavor-forked Lua or XML source files | Locked constraint — one shared source set. Forking is the failure mode this milestone is designed to avoid. |
| `WOW_PROJECT_ID` runtime flavor branching | Research found no Forever difference that needs it; every known difference is already handled by data-absence checks. Premature machinery. |
| Retaining the unsuffixed `TerribleBuffTracker.toc` as a rollback net | User chose a clean two-TOC rename. Raises the stakes on VER-01, which is why VER-01 is a blocking gate. |
| Re-enabling `CF_API_KEY` / `WAGO_API_TOKEN` | Deliberately off today; GitHub releases only. Enabling them is its own decision, not a side effect of flavor support. |
| A single multi-flavor zip tagged for both game versions | The packager's own recommended path for split TOCs, and it needs no CI changes — but the user chose two flavor-pure zips so each client's download carries only its own TOC. Cost is accepted knowingly. |
| Changing TBT's detection strategy if `COMBAT_LOG_EVENT_UNFILTERED` turns out available on Forever | Recorded as an observation only. A detection rewrite is a milestone of its own. |
| Reconstructing v0.2.5 / v0.2.6 phase artifacts | Both shipped outside GSD. Recorded in MILESTONES.md; history is not retrofitted. |
| Phase 999.1 (Edit Mode click-release selection) | Pre-existing backlog item, unrelated to flavor support. Promote separately. |
