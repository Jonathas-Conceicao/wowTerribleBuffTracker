<objective>
Make a running buff timer's icon show its remaining time in the aura countdown format, as the CDM's
buff icons do, while every real cooldown keeps the cooldown format (BUFFTIME-01, BUFFTIME-02), and
change nothing else (BUFFTIME-03). End with the user's in-game check on Midnight retail (VER-14).

Purpose: TBT's icons draw every sweep through a CooldownFrameTemplate (CreateTimerIcon, Display.lua
:518-538) and never set the countdown format, so the cooldown format rounds hours up: a buff with a
little over 1h left reads "2h". Blizzard's CDM sets `SetUseAuraDisplayTime(true)` on its buff icons
(wow-ui-source Blizzard_CooldownViewer/CooldownViewer.lua:1397, CooldownViewerBuffIconItemMixin:OnLoad,
set once and never re-set: the flag lives on the Cooldown widget and survives CooldownFrame_Clear)
and switches it per state on its cooldown items through `self.cooldownUseAuraDisplayTime` (true in the
aura arms :877, :895; false in the cooldown arms, e.g. :924; applied at :1150 just before
CooldownFrame_Set). TBT copies that per-state switch.

Output: Display.lua only. One new file-local helper `ApplyCountdownFormat(icon, auraTime)`, two call
sites, and the updated ApplySwipeLook comment. Plus this plan's SUMMARY.

Design choices (planner's calls left open by CONTEXT.md):
- D-02: a SEPARATE helper, not folded into ApplySwipeLook. ApplySwipeLook's `aura` is "the yellow
  cooldown-buff look", true only for a cooldown slot's own buff; the countdown format is true for
  EVERY timer-branch icon (buff tracker, reminder, Trinket/Pot too). Different flags, different stamps.
- D-04: re-issue on change. When the stamp moves, the helper nils `icon._lastStart`,
  `icon._userCdState` and `icon._cdGen`, exactly as ApplySwipeLook does, so whichever branch owns the
  icon re-issues SetCooldown under the new format in the same pass. Blizzard also sets the format
  before CooldownFrame_Set (:1150-1151). Costs nothing when the stamp is unchanged.
- The stamp `icon._auraTime` is NOT reset in ClearCooldownStamps (unlike `_auraLook`). It records the
  Cooldown widget's real state, which `cooldown:Clear()` does not touch (Blizzard's buff icon relies on
  exactly that, :1397). A fresh pooled icon starts with the stamp nil, so its first draw always asserts.
- Upvalue order (project memory: the file-local upvalue-order trap, hit 5 times): the helper is declared
  directly after ApplySwipeLook's `end` (~:913), above ApplyCooldownGrey (~:923). Both callers,
  ApplyCooldownSlot (~:1191) and RenderIconContainer (~:1578), sit below it.

Pooled-icon paths, traced in Display.lua (every path that draws a sweep reaches a call):
1. RenderIconContainer `elseif timer then` (~:1718-1780): the only `SetCooldown(timer.startedAt,
   timer.duration)` (:1777). Gets `ApplyCountdownFormat(icon, true)`. Covers buff trackers, reminders
   with their buff running, Trinket/Pot procs, a cooldown slot's own buff (Phase 74/76), and the preview
   demo procs BuffEngine builds while the CDM config is open (D-01: every timer-branch icon is true).
2. RenderIconContainer `elseif ns:IsCooldownSlotEntry(entry)` (~:1781-1796) calls ApplyCooldownSlot,
   which is the ONLY caller of both real-cooldown drawers:
   - ApplyUserCooldown (~:1139) -> `icon.cooldown:SetCooldown(startedAt, duration)` (:1173);
   - ApplyCooldownHandle (~:992) -> `icon.cooldown:SetCooldownFromDurationObject(handle)` (:1019).
   `ApplyCountdownFormat(icon, false)` goes in ApplyCooldownSlot right after `ApplySwipeLook(icon,
   false)` (:1203), so both drawers are covered and run after the stamps are nilled.
3. Paths that draw NO sweep and need no call: the reminder/placeholder branch (~:1797-1838, only
   `cooldown:Clear()`), ShowMergedPlaceholderIcon (~:1561, only `Clear()`), the Merge Mode re-anchor
   branch (Blizzard's own frame; the TBT icon is hidden), the fail-closed `entry.isMerged` arm (hidden).
   When one of these icons later draws a sweep it goes through path 1 or 2, which asserts the format.
4. Bars (CreateTimerBar ~:425, RenderBarContainer ~:1321) have no Cooldown widget; their text is
   FormatTime (:401), untouched (D-05). No other file creates a Cooldown frame or calls SetCooldown
   (grep of *.lua confirms: Display.lua only).
