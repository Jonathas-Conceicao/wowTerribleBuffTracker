# Requirements: TerribleBuffTracker v0.2.4

**Defined:** 2026-04-19
**Core Value:** Players can see countdown timers for buffs/cooldowns that the game no longer surfaces automatically.

## Milestone v0.2.4 Requirements

Internal refactor: unify buff detection and display through a SpellProvider/ActiveProc abstraction. No user-facing feature additions. All existing behavior must survive intact.

### Provider Abstraction

- [x] **PROV-01**: All four buff types (user-created, trinket, pot, lust) implement a common SpellProvider interface with GetEventInterests, OnTrigger, GetPreviewInfo, GetAtRestInfo methods
- [x] **PROV-02**: BuffEngine routes events to providers by declared event interest instead of hardcoded branches; no event-specific `if/elseif` chains in BuffEngine
- [x] **PROV-03**: ActiveProc is a plain normalized table shape ({key, icon, duration, label, expiresAt, source} + optional castSpellID/lustBuffID) consumed uniformly by Display and CDMTab
- [x] **PROV-04**: `ns.GetDisplayInfoForKey(key)` dispatch helper returns display info (icon, label, duration, spellID) for any provider key — single call site replaces all duplicated icon resolution chains. Base mixin contract collapses `GetPreviewInfo` + `GetAtRestInfo` into single `GetDisplayInfo(key)`. At-rest cache migration (PROV-F3) pulled in — providers own their `RefreshAtRest()` method.

### Lifecycle & Detection

- [x] **LIFE-01**: BuffEngine maintains a single `activeProcs` table keyed by stable provider key; reproc replaces entry by key overwrite; expiry sweep removes finished procs
- [x] **LIFE-02**: Aura-scan cancellation (`ScanActiveTimersForCancellation`) reads `source`/`castSpellID`/`lustBuffID` from ActiveProc and preserves existing cancel-when-aura-absent behavior for all buff types
- [x] **LIFE-03**: Preview mode (`StartAllPreviewTimers`) produces correct non-zero duration preview procs for all buff types including trinket/pot (fixes current 0-second preview bug)

### Display Unification

- [x] **DISP-01**: Display.lua consumes only normalized ActiveProc shape — zero type-specific branches, zero metaSlot double-indexing, zero ResolveSuggestedSpellID calls
- [x] **DISP-02**: CDMTab.lua uses `ns.GetPreviewInfoForKey` for all icon and tooltip resolution; META_DESCRIPTIONS branch and parallel resolution chains removed
- [x] **DISP-03**: Tooltip rendering logic is consolidated into a single shared handler used by both Display (bars/icons) and CDMTab (settings grid)
- [x] **DISP-04**: Orphaned code removed after migration — metaSlot bridges, `ResolveSuggestedSpellID`, hardcoded `*_FALLBACK_ORDER` arrays, duplicated icon resolution functions

## Future Requirements

Deferred to v0.3+.

### Provider Extensions

- **PROV-F1**: Aura-based duration override — read actual remaining time from aura data if Blizzard unlocks it for tracked spells
- **PROV-F2**: Dynamic buff discovery — auto-tracking of buffs without requiring user to add spell IDs
- **PROV-F3**: ~~Provider-level RefreshCache()~~ — **PULLED INTO v0.2.4 Phase 20** as `RefreshAtRest()` method on each provider. `ns:RefreshMetaIcons` becomes thin wrapper iterating `ns.providers`.

## Out of Scope

Explicitly excluded from v0.2.4.

| Feature | Reason |
|---------|--------|
| SavedVariables schema change | DB compatibility is hard constraint — providers constructed from existing schema at runtime; `CURRENT_SCHEMA_VERSION` stays unchanged |
| New buff types / new providers | Refactor is structural only; adding new trackable categories (cooldowns, defensives, etc.) is future scope |
| Display visual changes | Bars, icons, tooltips look identical after refactor; zero user-facing UI deltas |
| New WoW APIs or external libraries | All patterns use existing Midnight built-ins verified against local Blizzard source |
| Table pooling for ActiveProc records | Proc count bounded by player cast rate (< 20); existing `wipe()` accumulator pattern in Display.lua covers actual hot path |
