Background worth reading before planning, all recorded in `.planning/ROADMAP.md`'s backlog entries
999.12, 999.13 and 999.14 (the backlog items this milestone promotes):

- User trackers are keyed by spell ID (`trackedBuffs[spellID]` for a buff, `"cd:<spellID>"` for a
  cooldown). Positions belong to containers; a tracker's order is the `layoutOrder` in its own entry.
  Runtime state keyed by the tracker key: `ns.activeTimers`, the proc / aliveBuffs / displayInfo
  pools, `ns.cooldownStarts`, `ns.cooldownOverrides`, and the rank index.
- Every user buff is already cancelled on aura loss, checking the aura by its **cast** spell ID
  (`Providers.lua` `UserSpellProviderMixin:OnTrigger`, `aliveBuffs`). A spell whose aura ID differs
  from its cast ID is therefore likely cancelled early today — DTRK-02 is the fix.
- `ns:ReadPlayerAura` asks `C_Secrets.ShouldSpellAuraBeSecret` first; `MergeMode.lua:519-528`
  records that predicate as over-conservative even out of combat. `C_Secrets.GetSpellAuraSecrecy`
  is the static per-spell answer SECR uses (`Enum.SecrecyLevel`: `NeverSecret` 0, `AlwaysSecret` 1,
  `ContextuallySecret` 2); Blizzard uses it the same way in `Blizzard_AuraContainerUtil.lua:23`.
- Override and rank families already exist (`ns:RebuildRankIndex`, `ns:ResolveRankFamily`); a
  cross-spell trigger should resolve through them rather than match a raw ID only.
- The racial `cancelOnAuraLoss` opt-in was removed on 2026-09-25 because an opt-in meant every
  racial that could end early became its own bug report — hence DTRK-04's default stays ON.

## v0.5.0 Requirements

### NAME — Naming scheme (backlog 999.13)

- [x] **NAME-01**: Every tracker kind has one canonical name from a single scheme — user buff, user
      cooldown, meta skill (Lust, racials, ...), meta item (trinket, pot, bag consumables), with user
      item reserved — used consistently for kind identifiers, provider names and constants in code
- [x] **NAME-02**: Saved data uses the canonical names (`trackerType` values and key prefixes); an
      existing v0.4.1 `TerribleBuffTrackerDB` is migrated on first load with every tracker, its
      container, order and settings preserved — verified by a real logout/login, never `/reload`

### EDIT — Editing trackers (backlog 999.12)

- [x] **EDIT-01**: User can open an edit dialog from the tile of any user-defined tracker (buff or
      cooldown) in the TBT tab
- [x] **EDIT-02**: The edit dialog opens prefilled with the tracker's current values and can change
      every input the add dialog accepts — spell ID, duration, "cover all ranks" on Forever, and every
      detailed-tracking option
- [x] **EDIT-03**: The add and edit dialogs are built from one shared field definition, so a field
      added once appears in both with no second change
- [x] **EDIT-04**: Changing a tracker's spell ID keeps its container and its place in the order and
      clears any running timer or cooldown state held for the old ID; an ID already tracked as the
      same kind is rejected with a message

### ADD — Input, General and Advanced settings alike

- [x] **ADD-04**: While a spell or aura ID is being entered, the dialog shows a live preview of it —
      icon and name — and hovering the preview shows the game's own tooltip for that spell; an ID the
      client does not know is shown as unknown
- [x] **ADD-05**: On a cooldown tracker, the duration field is filled in with the spell's cooldown
      whenever the game reports one, and the user can override it
- [x] **ADD-06**: The add/edit dialog shows the spell preview as a centered portrait at the top of the
      dialog, under the title and above the Spell ID box: a 50px icon (CDM essential size at 100%
      scale) with the CDM icon styling TBT's trackers use, the spell name centered beneath it, and the
      "secret?" badge on the icon's top-right corner. It replaces Phase 55's small 18px preview row.
      Added 2026-09-28 from in-game review of Phase 55, by user decision (layout B, 50px, CDM styling)
- [x] **ADD-07**: The add/edit dialog has two tabs, **General** and **Advanced**, built with Blizzard's
      `TabSystemTemplate` (text tabs hanging above the dialog; `TabSystemTopButtonTemplate`). The
      Advanced tab opens with every field PREFILLED with its default (aura ID = the spell's ID, "End
      when the aura is lost" checked, visibility Always, no cast rule). The visibility choice is a
      `WowStyle1DropdownTemplate` dropdown with three `CreateRadio` entries. There is **no saved
      "detailed" mode flag**: a tracker behaves as detailed only where an Advanced-tab value differs
      from its default. Added 2026-09-28 by user decision after reviewing the Phases 56-57 dialog
      mockup (the checkbox expander and the three checkboxes were rejected).
      **Superseded 2026-09-29**: the "visibility Always" default and the visibility dropdown were
      removed by REM-04 (Phase 57.2); the tabs were renamed General and Advanced (wording revised in
      Phase 58)

### REM — Buff reminders (Phase 57.2, added 2026-09-29 by user decision)

- [x] **REM-01**: The CDM settings have a third TBT tab, **Reminders**, beside Cooldowns and Buffs.
      It has its own undeletable base container, "Buff Reminders", which holds icons only, can be
      moved in Edit Mode, and has its own container settings. User containers can be created in
      this category. A tracker never moves across categories.
- [x] **REM-02** (revised 2026-09-29 by user decision): A reminder is its own tracker kind with
      exactly a buff tracker's fields and rules: Spell ID (portrait and secret? badge included),
      Duration with the live-aura suggestion, and "Cover all ranks" on Forever; Advanced holds the
      aura ID, "End when the aura is lost" and "Ends when you cast:". It is editable like any user
      tracker. Only its category, container, kind and display differ from a buff. A reminder saved
      with no duration runs no timer until one is edited in.
      _Revised 2026-09-29 (Phase 58): a reminder's "Ends when you cast:" became "Also satisfied by"
      (RALT-01, schema v11), and a reminder saved with no duration still gets a timer from a readable
      aura expiry (57.2-05 review WR-05)._
- [x] **REM-03** (revised 2026-09-29 by user decision): A reminder's icon shows while its buff is
      missing and hides while it is up. Casting its spell starts its timer and hides it. The timer
      ending, a readable read finding the aura gone (unless "End when the aura is lost" is off), or
      a cast rule shows it, in combat too. While the aura cannot be read (combat, M+, secret) the
      state is held: an unreadable read never counts as absent. A readable present aura with a
      readable expiry syncs the timer to it.
- [x] **REM-04**: The visibility option (DTRK-03) is removed from buff and cooldown trackers. A
      schema step turns each user buff saved with `visibility = "absent"` into a reminder that keeps
      its duration and rules (revised 2026-09-29), and drops every other `visibility` value. This is
      verified by a real logout/login.

### LOAD — Tracker load rule (Phase 57.3, branch `topic/visibility`, added 2026-09-29 by user decision)

- [x] **LOAD-01**: Every user tracker (cooldown, buff, reminder) has a "Load" setting on the Advanced
      tab: When known (default, stored as nil), Always or Never. It is a radio dropdown.
- [x] **LOAD-02**: Built-in trackers follow the same rule set with a fixed load the user cannot edit:
      racial buffs and cooldowns When known; Lust, trinket, potion and bag items Always.
- [x] **LOAD-03**: A tracker that isn't loaded gets no processing: no cast, aura or timer handling,
      and it never draws on screen or in preview. In the TBT tab it still shows, greyed out, and
      can be moved and edited.
- [x] **LOAD-04**: "Known" is re-evaluated when spells, talents or spec change and at login, with no
      per-frame work. It counts any rank on Forever and the base/override spell on retail. The
      race-based filter is removed, and Suggested offers the racials the character knows.

### MREM — Class buff meta reminders (Phase 57.4, added 2026-09-29 by user decision)

- [x] **MREM-01**: A new built-in reminder kind (the reminder counterpart of metaSkill), in
      `ns.REMINDER_KINDS`, behaves exactly like a user reminder with fixed data. It cannot be
      edited, and its load rule is fixed at When known.
- [x] **MREM-02**: On Forever, the Reminders tab's Suggested section offers the class buffs the
      character knows, from one data table that records class and name as comments. Dragging a
      tile creates the reminder. Retail offers none.
- [x] **MREM-03**: Every rank the character knows counts, resolved from the spellbook by name. A
      buff with no duration (Blood Pact) has no timer and follows the aura only.

### RALT — Reminder alternatives (Phase 57.5, added 2026-09-29 by user decision)

- [x] **RALT-01**: A reminder (user or built-in) has an "Also satisfied by" list instead of "Ends when
      you cast". It is hidden while its own buff or any alternative is present, or running from a
      cast, and shown only when none is. Buff trackers are unchanged.
- [x] **RALT-02**: Schema v11 moves each reminder's saved `endOnCast` list into the alternatives list;
      buff trackers keep theirs. Mirrored in scripts/migrate-dryrun.js with selftests; verified by a
      real logout/login.
- [x] **RALT-03**: The built-in blessings (Kings, Might, Wisdom, Salvation, Light) list each other as
      alternatives. Righteous Fury (25780, 30 min, paladin) is added, and Blessing of Sanctuary
      (removed from Forever) is dropped from the table.

### SECR — Secrecy visibility

- [x] **SECR-01**: TBT's own tooltips (tracker tiles and the dialog preview) show the spell's aura
      secrecy level next to its spell ID
- [x] **SECR-02**: The global spell/aura-ID tooltip line added by `TOOL-01` also shows the secrecy
      level
- [x] **SECR-03**: When an ID being added or edited has a secrecy level above `NeverSecret`, the
      dialog shows a small "secret?" badge whose tooltip explains what that level means for the
      tracker — e.g. that aura-driven behaviour will not update in combat or M+

### DTRK — Detailed tracking (backlog 999.14)

The concrete design of detailed tracking — layout, wording, what an "absent" tracker draws — is
settled in that phase's discussion, not here.

- [x] **DTRK-01**: A user-defined tracker has General settings and Advanced settings in the add/edit
      dialog; with every Advanced setting at its default it behaves exactly as before.
      **Superseded 2026-09-29**: there is no switch and no saved mode flag; Advanced options take
      effect wherever they differ from their defaults (ADD-07, schema v9)
- [x] **DTRK-02**: Detailed tracking accepts an aura ID that differs from the spell ID; the cast still
      starts the timer and everything aura-driven follows the aura ID. Default aura ID = spell ID
- [x] **DTRK-03**: A detailed tracker can be set to show always (default), only while its aura is
      present, or only while its aura is absent. **Superseded 2026-09-29 by REM-01..04**: the option
      is removed, and "absent" becomes the Reminders category
- [x] **DTRK-04**: A detailed tracker can opt out of ending when its aura is lost; the default stays ON
- [x] **DTRK-05**: A detailed tracker can list spells whose cast ends it ("aura A clears when skill B
      is cast"); this works in combat
- [x] **DTRK-06**: An aura that cannot be read — in combat, in M+, or because it is secret — is never
      treated as absent; aura-driven rules hold their last known state until a real read is possible
