# Phase 35.1: Config Panel - Context

**Gathered:** 2026-09-20
**Status:** Ready for planning
**Mode:** Decisions taken with the user up front, before the autonomous run
**Renumbered:** was Phase 39. Container create/delete lives here, so it must land before Phase 36.

<domain>
## Phase Boundary

A gear/settings square beside the `+` button on TBT's CDM tab flips the tab page into an addon-wide
config panel, and back.

In scope: the button, the panel, the page swap, the steal-mode toggle (persisted, inert until Phase 40),
and the create/delete container controls (whose *behaviour* is Phase 36's `CONT-04`/`CONT-05`, but whose
*home* is this panel).

Out of scope: per-container settings, which belong to each container's Edit Mode popup, not here.
</domain>

<decisions>
## Implementation Decisions

### Contents — deliberately minimal
Exactly two things, by user decision:
1. The steal-mode toggle.
2. Create and delete user containers.

Explicitly **not** included, having been offered and declined: a debug toggle, a reset-all-positions
button, and any global scale/opacity override. The last of those was declined partly because it would
interact with `CONT-06`'s per-container settings and double the styling paths to test.

### Placement and behaviour
- The gear sits **next to the existing `+` button** on the TBT tab header and reads as a button, with
  hover and pressed states — match whatever template the `+` already uses rather than inventing one.
- Clicking it **replaces the tracker list on the same tab page**. It is not a second window and not a
  new tab.
- A visible control returns to the tracker list, and the list comes back in the state it was left in
  (scroll position, expanded sections).
- The steal-mode value persists in `ns.db` and survives `/reload`. It is off on a fresh database.

### Steal mode is inert here
The toggle is built and persisted in this phase but does nothing yet — Phase 40 reads it. That is
deliberate sequencing, not an oversight: it lets the panel be built and tested without dragging the
taint-sensitive CDM work forward.
</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `CDMTab.lua` already owns the tab button injection, the content panel frame and the section rendering
  — the page swap is a show/hide of two children of the existing panel, not a new frame hierarchy.
- The Add dialog and delete-zone confirm flows already exist as patterns for the container create/delete
  dialogs.
- `ns:RefreshTBTSections` is the redraw entry point with eleven call sites; the swap back to the list
  should reuse it rather than duplicating render logic.

### Established Patterns
- The TBT tab anchors under whichever Blizzard CDM tab is bottom-most (v0.2.6 fix) — do not disturb that
  anchoring when adding a header button.
- TBT never uses `parentArray` on frames parented to CDM, to avoid tainting CDM's secure `TabButtons`
  iteration (see `CDMTab.xml`'s comment). The same caution applies to anything new added to the tab.

### Integration Points
- `ns.db` is the settings home; `ns.db.containerSettings` already holds per-container config, so the
  addon-wide flags want a sibling key rather than living inside it.
</code_context>
