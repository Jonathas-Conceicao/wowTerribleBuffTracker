# Phase 35.1 — Plan 02: Steal-Mode Toggle and the Phase 36 Seam

**Created:** 2026-09-21
**Requirements:** CFG-03

## Approach

**The key is `ns.db.stealMode`** — a flat boolean sibling of `ns.db.tbtVisible`, `ns.db.trackedBuffs`,
`ns.db.containerSettings` and `ns.db.editModePositions`. It is deliberately **not** inside
`containerSettings`: that table is per-container and Phase 36 will hand each container its own copy, while
steal mode is one addon-wide switch across all four categories (`STEAL-06` — there is no per-category
toggle anywhere, ever). `tbtVisible` is the existing precedent for exactly this shape, down to the
`if ns.db.X == nil then` defaulting idiom.

**No schema bump.** Seeding a missing key with a default is idempotent, so it lives where the data is read
— `Core.lua`'s `ADDON_LOADED` handler — not in a version gate. This is the split Plan 35-01 established:
destructive renames are version-gated in `BuffEngine.lua`, idempotent seeding is not.
`CURRENT_SCHEMA_VERSION` stays at 4 and `BuffEngine.lua` is not touched.

**Inert is a deliverable, not an omission.** Phase 40 owns every reader. This plan's strongest acceptance
criterion is a *negative* grep: `stealMode` appears in `Core.lua` and `CDMTab.lua` and nowhere else. Do not
hide a CDM frame, do not read `Enum.CooldownViewerCategory`, do not touch `ns.CONTAINERS[].cdmViewerGlobal`.

**The seam is named, anchored and hidden.** `ns.tbtConfigContainerSection` is an empty frame with a
`-- SEAM: Phase 36` comment block, sized to the content column and hidden while empty so the panel shows no
blank section in the meantime. It is the **last** element in the content stack and nothing anchors below
it, so Phase 36 can grow it to any height without displacing the steal-mode block above. `CONT-04`/`CONT-05`
behaviour — creating a container, deleting one, moving its trackers somewhere predictable — is explicitly
not implemented here.

**Checkbox state is re-synced on show, not just at build.** The page frame is built once but shown many
times, and Phase 40 may flip the flag from elsewhere; reading `ns.db` at show time is the same discipline
`ShowEditModePanel` already uses for `ns.tbtSidebarCheckbox` (`EditModeFrames.lua:664`).

## Tasks

1. **`Core.lua` — default the flag.**
   *Read first:* `Core.lua:70-130` (the `ADDON_LOADED` block: db creation, the `tbtVisible` default, the
   registry-driven `containerSettings` pass).
   Immediately after the `ns.db.tbtVisible` default block and before the `containerSettings` block, add:
   `if ns.db.stealMode == nil then ns.db.stealMode = false end`, preceded by a short comment stating that
   this is `CFG-03`, that it is addon-wide and therefore a sibling of `tbtVisible` rather than a
   `containerSettings` field, that it is written by the config panel in `CDMTab.lua`, and that **nothing
   reads it until Phase 40** (`STEAL-01`…`STEAL-08`). Do not bump `CURRENT_SCHEMA_VERSION`; do not open
   `BuffEngine.lua`.
   *Acceptance:*
   - `grep -n 'ns.db.stealMode == nil' Core.lua` matches.
   - `grep -c 'stealMode' Core.lua` == 3 (comment + nil check + assignment).
   - `grep -n 'ns.db.stealMode = false' Core.lua` appears **before** `grep -n 'containerSettings'`'s first
     hit in the same handler.
   - `git diff --name-only` does not list `BuffEngine.lua`, and
     `grep -n 'CURRENT_SCHEMA_VERSION = 4' BuffEngine.lua` still matches.

## Risks

- **`ns.db.stealMode` could be confused with a `containerSettings` field by Phase 40.** The comment in
  `Core.lua` names it addon-wide and names Phase 40 as the only reader. If Phase 40 wants per-category
  behaviour, it is contradicting `STEAL-06` and the requirement wins, not the code.
- **The seam being hidden could read as broken to a future maintainer.** Mitigated by the `SEAM: Phase 36`
  comment block, which is the grep target Phase 36's plan will use. Do not replace it with a visible empty
  section header — an empty header reads as a bug to the user.
- **A `nil` from `GetChecked`.** Coerced with `and true or false` so `ns.db.stealMode` is only ever a real
  boolean; a `nil` written back would re-trigger the default on next load and silently reset the user's
  choice.
- **This plan and Plan 01 both edit `CDMTab.lua`.** That is why they are in different waves and this one
  depends on `35.1-01` — `CreateConfigPanel`, `panel.Content` and `ns:ShowTBTConfigPage` must already exist.
