# Phase 35.1 — Plan 01: Gear Square and the Config Page Swap

**Created:** 2026-09-21
**Requirements:** CFG-01, CFG-02, CFG-04

## Approach

**The `+` is not in a header.** It is `addSquare` in `ns:BuildAllSections` (`CDMTab.lua:908-955`) — a plain
38x38 `Frame` parented to the **Suggested section's `GridLayoutFrame` container**, pinned first by
`layoutIndex = 1`. "Next to the `+` button" therefore means *slot 2 of that same grid*, not a new header
row. This matters for the constraint about `AnchorTabBelowCDMTabs`: nothing in this plan touches
`TBTSettingsTab`, its anchors, or `GetCDMTabs`, so the v0.2.6 bottom-most-tab anchoring is untouched by
construction.

**Reserved slots become a constant.** `RefreshTBTSections` currently seeds `local suggestedSlot = 1` and
pre-increments, so catalog tiles land at 2,3,4… With the gear at 2 the catalog must start at 3. One
module-level `SUGGESTED_RESERVED_SLOTS = 2` is the single source for both the gear's `layoutIndex` and
that seed, so a future third square is a one-line change rather than two numbers that can disagree.

**Chrome is extracted, behaviour is not.** The gear and the `+` share exactly the visual chrome —
38x38, `EnableMouse`, BACKGROUND colour texture, 24x24 centred overlay icon, `ButtonHilight-Square`
HIGHLIGHT at `ADD`. That becomes `CreateActionSquare(parent, r, g, b, a)`, which the `+` is rebuilt on.
The `+`'s tooltip and `OnMouseUp` handler are moved verbatim, not rewritten — they stay a `Frame`
handler with the `(self, button, upInside)` signature. Do **not** convert either square to a `Button`:
that changes the `OnMouseUp` contract for code that has shipped since v0.2.0.

**Gear icon is a file texture, not an atlas.** `Interface\ICONS\Trade_Engineering` is a cog and ships in
every client back to vanilla. A modern gear *atlas* would be a Midnight-only asset that silently renders
as nothing on Forever, which is the same class of cross-flavour trap `GetScaledCursorPositionForFrame`
was. The file-texture idiom already exists at the top of this file (`ICON_PATH`).

**The page swap is two sibling frames, one visible at a time.** `ns.tbtConfigPanel` is created with the
*same* parent, the *same* two `SetPoint` calls and the *same* frame level as `ns.tbtPanel`
(`CDMTab.lua:1064-1067`), so it occupies the identical rect. No new kind of parenting relationship is
introduced and no Blizzard CDM frame is written to, parented into, or asked for a mixin method.

**Return path: state is preserved by not destroying it.**
- *Expanded/collapsed sections* — `section.collapsed` lives on the section tables built once by
  `ns:BuildAllSections`. `ns:RefreshTBTSections` reads it and never resets it. So the return path must
  call neither `BuildAllSections` nor `BuildTBTSection`; hiding and re-showing the panel preserves
  collapse state for free.
- *Scroll position* — captured into a file-local `savedListScroll` before hiding, restored one frame
  after showing. The deferred restore is required: `ns.tbtPanel`'s existing `OnShow` hook refreshes, then
  refreshes again on `C_Timer.After(0, ...)`, and the scroll range is not settled until that has run. A
  restore registered *after* `Show()` returns is queued behind the hook's timer in the same frame, so it
  lands last.
- *Redraw* — comes from that same `OnShow` hook. `ns:ShowTBTTrackerList` must not call
  `ns:RefreshTBTSections` itself; the call-site count in this file stays at 12 (11 call sites plus the
  definition).

The gear only ever opens the page — it is inside the tracker list, so it is not on screen to close it.
`Back` is the sole return control, which is exactly what `CFG-04` asks for.

## Risks

- **Hiding `ns.tbtPanel` mid-drag.** `ns.tbtPanel` already has an `OnHide` hook calling `EndDrag(false)`
  (`CDMTab.lua:1114-1118`), so a drag in flight is cancelled cleanly by the swap. No new handling needed —
  verified by reading that hook, not assumed.
- **Scroll restore racing the deferred refresh.** Mitigated by registering the restore *after* `Show()`, so
  it queues behind the `OnShow` hook's own `C_Timer.After(0, ...)`. If the list still lands at the top, the
  fix is a second `C_Timer.After(0, ...)` nesting, not a per-frame `OnUpdate` — do not add an `OnUpdate` to
  a panel that has one reserved for drag tracking.
- **Rebuilding the add square could regress the Add dialog.** Its three script handlers are moved verbatim
  and the `Frame`/`OnMouseUp(self, button, upInside)` contract is preserved deliberately. If the `+` stops
  opening the dialog, the cause is a converted frame type, not the helper.
- **The gear sitting inside the Suggested grid is intended.** It is not a drag source (it is not in
  `section.itemPool`, which `SectionHitTest` and the reorder marker enumerate) and Suggested is already a
  rejected drop target per D-04, so drag-and-drop is unaffected.
