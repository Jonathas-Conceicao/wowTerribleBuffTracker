# Phase 36 — Plan 01: Dynamic Registry, Key Generation and Rehydration

**Created:** 2026-09-21
**Requirements:** CONT-04, CONT-05, CONT-06

## Approach

Phase 35 made `ns.CONTAINERS` the single ordered registry that every consumer loops. This plan makes
that list **dynamic**: base entries stay hardcoded in the literal, user entries are rehydrated from
SavedVariables and appended at `ADDON_LOADED`. Nothing downstream learns a new key string — the
invariant "adding a container is append-an-entry-and-refresh" is what the other three plans build on.

**Storage.** Two new `ns.db` keys, both seeded idempotently at the read site (no `schemaVersion` bump —
the same rule Phase 35.1 used for `stealMode`, because seeding a missing key with a default is
idempotent and must converge for fresh and upgraded databases alike):

| key | shape | purpose |
|---|---|---|
| `ns.db.userContainers` | **array**, creation order | one record per user container: `{ key, title, kind, defaultX, defaultY }` |
| `ns.db.nextContainerId` | integer, starts at `1` | monotonic key counter, **never decremented** |

An array, not a map, because registry order is user-visible: it is the CDM tab's section order and the
Edit Mode label order. Array order is creation order, and user containers always sit after the four base
ones and before `hidden`/`suggested`.

**Key generation** (`ns:GenerateContainerKey`): the key is `"user" .. id` where `id` is
`ns.db.nextContainerId`. Collision with a base key or a CDM-tab section key is impossible three times
over, and all three guards are deliberate:

1. **Prefix.** No base key (`buffs`, `bars`, `essential`, `utility`) and neither CDM-tab section key
   (`hidden`, `suggested`) begins with `user`. `utility` shares only the letter `u`.
2. **Monotonic counter.** `nextContainerId` is incremented on every issue and never decremented, so a
   deleted container's key is never reissued. A stale `entry.section = "user3"` left anywhere can
   therefore never be adopted by a later container — it simply names nothing and falls through the
   existing render filters.
3. **Live re-check.** Before returning, the generator loops while
   `ns.CONTAINER_BY_KEY[key] or key == "hidden" or key == "suggested"`, incrementing `id`. This costs
   nothing and survives a hand-edited SavedVariables file that duplicates an id.

**Rehydration order — this is the part that must be exact.** `ns:RehydrateUserContainers()` is called
from the `ADDON_LOADED` branch of `Core.lua`'s event handler, **after** the `ns.db.containerSettings`
table guard and **before** the `for _, def in ipairs(ns.CONTAINERS)` settings pass. That position is
load-bearing:

- It is inside `ADDON_LOADED`, so it runs before `PLAYER_ENTERING_WORLD` fires
  `ns:InitEditModeFrames` and `ns:InitDisplay`, and long before `EventUtil.ContinueAfterAllEvents`
  fires `ns:InitCDMTab`. All three of those already loop the whole registry, so they pick user
  containers up with no extra code.
- It is before the settings pass, so the *existing* loop seeds each user container's
  `containerSettings` table for free.
- The only registry loops that run **earlier** are the file-scope loops in `Display.lua` (pools,
  timer lists) and `CDMTab.lua` (`SECTION_DEFS`, `VALID_DROP_SECTIONS`), which run at Lua load time
  before any event. Those are the two that must be re-callable after rehydration — Plans 02 and 04
  convert them into functions this plan's hook dispatch calls.

**Hook dispatch.** `ns:AttachContainerRuntime(def)` / `ns:DetachContainerRuntime(key)` are the only
place Core talks to the other three files. Every call is `if ns.X then ns.X(...) end`, so this plan
lands and works on its own in Wave 1 (the hooks simply do not exist yet), and each hook is itself
required to no-op when its own subsystem has not initialised. Rehydration and runtime creation use the
**same** attach path, so there is one code path to get wrong, not two.

**Deletion order is fixed** and is the difference between a clean delete and a Lua error mid-frame:

1. move every `trackedBuffs` entry whose `section` is the key to `"hidden"`;
2. `ns:UnregisterContainerDef(key)` — the container stops being iterated *immediately*, so the next
   `ns:UpdateDisplay()` tick cannot reach a half-torn-down container;
3. `ns:DetachContainerRuntime(key)` — sections, then frames, then per-key runtime tables;
4. drop `ns.db.userContainers` record, `ns.db.containerSettings[key]`, `ns.db.editModePositions[key]`;
5. refresh.

Unregistering **before** releasing per-key tables is the ordering that matters: the reverse would leave
`ns.CONTAINERS` naming a key whose `pools` entry is already gone, and `Display.lua`'s dispatch loop
would index a nil pool.

## Tasks

1. **`Core.lua` — persistence, settings extraction, key generation and the def register/unregister pair.**
   *Read first:* `Core.lua` (whole file — the registry literal, `ns.CONTAINER_BY_KEY`, and the
   `ADDON_LOADED` branch with its `containerSettings` loop), `.planning/phases/36-user-containers/36-CONTEXT.md`.

   a. Extract the body of the existing `containerSettings` loop into a module-level
      `function ns.EnsureContainerSettings(def)` placed immediately after `ns.CONTAINER_BY_KEY` is
      built. It keeps both existing halves verbatim — construct the kind-appropriate defaults table
      when `ns.db.containerSettings[def.key]` is nil, otherwise run the per-field backfill
      (`hideWhenInactive`, `showTimer`, `showTooltips`, `opacity`, and bar-kind `displayMode`).
      The `ADDON_LOADED` loop becomes `for _, def in ipairs(ns.CONTAINERS) do ns.EnsureContainerSettings(def) end`.
      The defaults table constructor must appear **exactly once in the file** after this change — that
      is what guarantees a user container created at runtime gets a fresh table and never aliases
      another container's settings.

   b. In `ADDON_LOADED`, immediately after the `if not ns.db.containerSettings then ... end` guard, add
      the two new defaults: `if not ns.db.userContainers then ns.db.userContainers = {} end` and
      `if ns.db.nextContainerId == nil then ns.db.nextContainerId = 1 end`. No `schemaVersion` bump,
      and do not touch `BuffEngine.lua`.

   c. Add `function ns:GenerateContainerKey()` implementing the three guards described in Approach.
      It returns `key, id`, and writes `ns.db.nextContainerId = id + 1` before returning.

   d. Add `function ns:RegisterContainerDef(record)`: builds and appends the def
      `{ key = record.key, title = record.title, frameName = "TBTContainer_" .. record.key,
      kind = record.kind, cdmViewerGlobal = nil, defaultX = record.defaultX,
      defaultY = record.defaultY, isUser = true }` to `ns.CONTAINERS`, sets
      `ns.CONTAINER_BY_KEY[record.key]`, and returns the def. `isUser = true` is set **here and
      nowhere else**, so the four literal base entries can never carry it.
      Add `function ns:UnregisterContainerDef(key)`: finds the index in `ns.CONTAINERS`,
      `table.remove`s it, nils `ns.CONTAINER_BY_KEY[key]`, returns true/false.

   e. Add `function ns:RehydrateUserContainers()` iterating `ns.db.userContainers` in array order,
      calling `ns:RegisterContainerDef(record)` then `ns:AttachContainerRuntime(def)` for each. Call it
      from `ADDON_LOADED` between (b)'s new defaults and (a)'s settings pass. Add a comment stating
      why that position is fixed (see Approach).

   *Acceptance:*
   - `grep -n 'ns.db.userContainers' Core.lua` matches at least twice.
   - `grep -n 'ns.db.nextContainerId' Core.lua` matches at least three times.
   - `grep -c 'orientation = def.kind == "bar"' Core.lua` returns `1` (one defaults constructor).
   - `grep -n 'function ns.EnsureContainerSettings' Core.lua` matches, and
     `grep -n 'ns.EnsureContainerSettings(def)' Core.lua` matches inside the `ADDON_LOADED` loop.
   - `grep -c 'isUser = true' Core.lua` returns `1`.
   - `grep -n 'ns:RehydrateUserContainers()' Core.lua` matches, and the line number is **greater** than
     the line number of `grep -n 'if not ns.db.containerSettings then' Core.lua` and **less** than the
     line number of `grep -n 'ipairs(ns.CONTAINERS)' Core.lua`'s hit inside `ADDON_LOADED`.
   - `grep -n '"user" ..' Core.lua` matches inside `ns:GenerateContainerKey`.
   - `grep -n '"hidden"' Core.lua` matches inside `ns:GenerateContainerKey`'s collision loop.

2. **`Core.lua` — the create/delete API and the subsystem hook dispatch.**
   *Read first:* the result of Task 1, plus `BuffEngine.lua` `ns:SetBuffSection` (it already rewrites
   `entry.section`, mirrors the section onto a live `ns.activeTimers` proc, clears the proc when the
   target is `"hidden"`, and calls `ns:UpdateDisplay()`), and `CDMTab.lua`'s
   `if ns.configOpen then ns:StartAllPreviewTimers() end` idiom at the end of `EndDrag`.

   a. `function ns:AttachContainerRuntime(def)` — calls, in this order, each guarded by `if ns.X then`:
      `ns.AllocateContainerRuntime(def)`, `ns.CreateContainerFrames(def)`,
      `ns.RebuildContainerSectionDefs()`, `ns.AddContainerSection(def)`.
      `function ns:DetachContainerRuntime(key)` — calls, in this order, each guarded:
      `ns.RemoveContainerSection(key)`, `ns.DestroyContainerFrames(key)`,
      `ns.ReleaseContainerRuntime(key)`, `ns.RebuildContainerSectionDefs()`.
      Add a comment stating that every hook is nil-guarded because Core loads first and because each
      hook is additionally required to no-op before its own subsystem has initialised (rehydration runs
      at `ADDON_LOADED`, when `ns.containers` and `ns.tbtSections` do not exist yet).

   b. `function ns:CountContainerTrackers(key)` — returns the number of `ns.db.trackedBuffs` entries
      whose `.section == key`. No allocation; a plain counter over `pairs`.

   c. `function ns:CreateUserContainer(title, kind)`:
      - reject and return nil unless `kind == "bar" or kind == "icon"`;
      - `local key, id = ns:GenerateContainerKey()`;
      - `title` falls back to `"Container " .. id` when nil or the empty string. **Titles are not
        required to be unique** — the key is the identity, and no uniqueness check is to be added;
      - `defaultX = 300`, `defaultY = -320 - 80 * #ns.db.userContainers` (evaluated *before* the
        insert), so successive containers stack downward instead of landing on top of each other;
      - `table.insert(ns.db.userContainers, record)`;
      - `local def = ns:RegisterContainerDef(record)`;
      - `ns.EnsureContainerSettings(def)`;
      - `ns:AttachContainerRuntime(def)`;
      - `print("|cff00ccffTerribleBuffTracker|r: Created container |cff00ff00" .. def.title .. "|r.")`
        matching the existing print idiom;
      - `if ns.UpdateDisplay then ns:UpdateDisplay() end`; return `def`.

   d. `function ns:DeleteUserContainer(key)`:
      - `local def = ns.CONTAINER_BY_KEY[key]`; if `not def or not def.isUser` then print
        `"|cff00ccffTerribleBuffTracker|r: That container cannot be deleted."` and return `false`.
        **This is the primary base-container guard** — `isUser` exists only on defs built by
        `ns:RegisterContainerDef`, so none of the four literal entries can pass it.
      - move contents: iterate `pairs(ns.db.trackedBuffs)`, collect the keys whose `.section == key`
        into a local list first, then call `ns:SetBuffSection(dbKey, "hidden")` for each. Collect
        before mutating — `SetBuffSection` calls `ns:UpdateDisplay()`, and mutating entries while
        iterating the same table it reads is the kind of thing that only breaks in-game.
      - `ns:UnregisterContainerDef(key)`, then `ns:DetachContainerRuntime(key)`, in that order and for
        the reason given in Approach.
      - `ns.db.containerSettings[key] = nil`; `if ns.db.editModePositions then ns.db.editModePositions[key] = nil end`;
        `table.remove(ns.db.userContainers, i)` at the record's index.
      - `print("|cff00ccffTerribleBuffTracker|r: Deleted container |cffff6600" .. def.title .. "|r.")`
      - `if ns.configOpen then ns:StartAllPreviewTimers() end` — preview procs carry a `section` field
        snapshotted at `StartAllPreviewTimers` time, so a stale one naming the deleted key would
        otherwise fall through `Display.lua`'s `timersByContainer[timer.section] or timersByContainer.bars`
        and render in Tracked Bars for a tick.
      - `if ns.tbtSections then ns:RefreshTBTSections() end`; `if ns.UpdateDisplay then ns:UpdateDisplay() end`;
        return `true`.

   *Acceptance:*
   - `grep -n 'function ns:CreateUserContainer' Core.lua` and
     `grep -n 'function ns:DeleteUserContainer' Core.lua` both match.
   - `grep -n 'not def.isUser' Core.lua` matches inside `ns:DeleteUserContainer`.
   - `grep -n 'ns:SetBuffSection(.*"hidden")' Core.lua` matches inside `ns:DeleteUserContainer`.
   - `grep -c 'if ns.AllocateContainerRuntime then' Core.lua` returns `1`; the same for
     `ns.CreateContainerFrames`, `ns.AddContainerSection`, `ns.RemoveContainerSection`,
     `ns.DestroyContainerFrames`, `ns.ReleaseContainerRuntime`.
   - `grep -c 'ns.RebuildContainerSectionDefs' Core.lua` returns `2` (attach and detach).
   - `grep -n 'function ns:CountContainerTrackers' Core.lua` matches.
   - `grep -n 'ns.db.stealMode' Core.lua` shows **only** the pre-existing default-seeding block — this
     plan adds no reader of that flag.
   - Reading `ns:DeleteUserContainer`, `ns:UnregisterContainerDef(key)` appears on an earlier line than
     `ns:DetachContainerRuntime(key)`.

## Risks

- **A hook called before its subsystem exists.** Rehydration runs at `ADDON_LOADED`, when
  `ns.containers` and `ns.tbtSections` are both nil. Core guards on the function existing; each hook
  must additionally guard on its own state. Plans 02–04 carry that requirement explicitly, and until
  they land, the `if ns.X then` guards make this plan inert rather than broken.
- **Preview procs outliving their container.** Covered by the `ns.configOpen` re-seed in
  `ns:DeleteUserContainer`; real procs are covered because `ns:SetBuffSection(k, "hidden")` clears
  `ns.activeTimers[k]` outright.
- **`defaultX`/`defaultY` persisted rather than recomputed.** Deliberate: a rehydrated def must be
  byte-identical to the def that was created, or a user who never opened Edit Mode would see their
  container move after a delete shifted the array indices.
