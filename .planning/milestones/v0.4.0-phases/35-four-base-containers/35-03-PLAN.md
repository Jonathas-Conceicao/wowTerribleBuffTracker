# Phase 35 — Plan 03: One CDM Tab Section Per Container

**Created:** 2026-09-21
**Requirements:** CONT-01, CONT-03

## Approach

`entry.section` already *is* the container key, and `SECTION_DEFS` already pairs a key with a title. The
drag-and-drop machinery — `SectionHitTest`, the reorder marker, `GetDropLayoutOrder`, `EndDrag`,
`UpdateScrollChildHeight`, `BuildAllSections`, `RefreshTBTSections` — is already written against those
two lists. So the list grows and the mechanism does not change. The only hand-written per-section code is
the right-click context menu, which is an if/elseif chain over three hardcoded section names; that becomes
a loop.

Because `bars` and `buffs` keep their keys, **`CONT-03`'s tracker-placement half is a no-op**: every
`entry.section` written by v0.3.0 already matches a section in the new list. No entry is rewritten in this
plan. If a task tempts you to iterate `ns.db.trackedBuffs` and reassign `section`, that is a bug, not the
plan.

**Section order** follows `ns.CONTAINERS` (Tracked Buffs, Tracked Bars, Essential Cooldowns, Utility
Cooldowns), then `hidden` → *Not Displayed*, then `suggested` → *Suggested*. This swaps today's
Bars-before-Buffs order; that is intentional and comes from `35-CONTEXT.md`.

**Section headers use the bare `def.title`** — *Tracked Buffs*, not *TBT Tracked Buffs*. The tab is
already TBT's own tab, so there is nothing to disambiguate from. (Edit Mode overlays do carry the prefix,
because Blizzard's Edit Mode shows systems with the identical four names — see Plan 02.)

**Nothing here creates or deletes a container.** The delete zone in *Not Displayed* deletes a *tracker*.
Container create/delete is Phase 35.1's config panel; per-container settings are Phase 36. Do not add a
`+` or an `x` to any container section header.

## Tasks

1. **Derive `SECTION_DEFS` and `VALID_DROP_SECTIONS` from the registry.**
   *Read first:* `CDMTab.lua` lines 35-55 (`SECTION_DEFS`, `VALID_DROP_SECTIONS`), lines 274-345
   (`SectionHitTest` and the reorder marker, both of which iterate `VALID_DROP_SECTIONS`), lines 663-785
   (`UpdateScrollChildHeight`, `RefreshTBTSections`), lines 896-912 (`BuildAllSections`); `Core.lua`
   (`ns.CONTAINERS` from Plan 01).
   Build both lists at file load by iterating `ns.CONTAINERS`:
   - `SECTION_DEFS` — one `{ key = def.key, title = def.title }` per registry entry, in registry order,
     then `{ key = "hidden", title = "Not Displayed" }`, then `{ key = "suggested", title = "Suggested" }`.
   - `VALID_DROP_SECTIONS` — one `def.key` per registry entry, then `"hidden"`. Keep it a module-level
     constant built once; `SectionHitTest` and the marker update run per frame during a drag and must not
     allocate. Keep the existing comment saying so.
   Change nothing else in the drag/drop, layout or refresh code — those already loop these two lists.
   Leave the `if def.key == "hidden"` delete-zone block and the `if def.key == "suggested"` catalog block
   untouched; the four container sections fall through to the existing `else` branch that reads
   `entry.section == def.key`.
   *Acceptance:* `grep -n '{ key = "bars", title = "Tracked Bars" }' CDMTab.lua` returns nothing.
   `grep -c 'ipairs(ns.CONTAINERS)' CDMTab.lua` ≥ 2.
   `grep -n 'VALID_DROP_SECTIONS = {' CDMTab.lua` shows it is no longer a literal list of three strings.
   `grep -n '"Not Displayed"\|"Suggested"' CDMTab.lua` — both still present, appended after the registry
   entries.
   `grep -c 'def.key == "hidden"' CDMTab.lua` ≥ 1 (delete zone still scoped to Not Displayed).

2. **Generalise the right-click context menus.**
   *Read first:* `CDMTab.lua` lines 123-208 (the `OnMouseUp` context-menu handler, both the `suggested`
   branch and the tracked-item if/elseif chain).
   - **Tracked items** (`sectionName` is any registry key or `"hidden"`): replace the
     `if sectionName == "bars" … elseif … "buffs" … elseif … "hidden"` chain with a loop over
     `ns.CONTAINERS` that creates a `"Move to " .. def.title` button for every `def.key ~= sectionName`,
     each calling `ns:SetBuffSection(self.spellID, def.key)` then `ns:RefreshTBTSections()`. After the
     loop, when `sectionName ~= "hidden"`, add the existing `"Hide"` button targeting `"hidden"`. Keep the
     trailing `rootDescription:CreateDivider()` and `"Remove"` button exactly as they are.
     Menu labels become *Move to Tracked Bars*, *Move to Essential Cooldowns* and so on — the old short
     *Move to Bars* / *Move to Buffs* labels are replaced by the pinned container names.
   - **Suggested items:** replace the two hardcoded `"Add to Bars"` / `"Add to Buffs"` buttons with one
     `"Add to " .. def.title` button per registry def, each passing `def.key` into the existing
     `addSuggestedToSection` local. `addSuggestedToSection` itself is already section-agnostic — do not
     change its body. Keep the D-08 rule that Suggested has no *Remove* entry.
   *Acceptance:* `grep -n '"Move to Buffs"\|"Move to Bars"\|"Add to Bars"\|"Add to Buffs"' CDMTab.lua`
   returns nothing.
   `grep -n '"Move to " .. def.title' CDMTab.lua` matches.
   `grep -n '"Add to " .. def.title' CDMTab.lua` matches.
   `grep -c '"Hide"' CDMTab.lua` ≥ 1 and `grep -c '"Remove"' CDMTab.lua` ≥ 1.
   `grep -n 'sectionName == "bars"\|sectionName == "buffs"' CDMTab.lua` returns nothing.

3. **Format, syntax-check and deploy.**
   Run `stylua` from the repo root with no flags. Confirm the file parses (`luac -p CDMTab.lua`, or
   `stylua --check CDMTab.lua` if `luac` is unavailable). Run `./scripts/install.bat`.
   *Acceptance:* `stylua --check .` exits 0; `git diff --stat` lists only `CDMTab.lua`; `install.bat`
   exits 0.

## Verification

- `grep -c 'ns.db.trackedBuffs\[.*\].section =' CDMTab.lua` returns `0` — no bulk re-sectioning was added.
- `grep -n 'tbtDeleteZone' CDMTab.lua` — every creation/show site is inside the `def.key == "hidden"`
  block.
- `stylua --check .` exits 0.
- **In-game, Forever (human) — folded into Plan 04's pass, not a separate login:** open `/tbt`. Six
  sections in the order Tracked Buffs, Tracked Bars, Essential Cooldowns, Utility Cooldowns, Not
  Displayed, Suggested. Every previously tracked buff is in the section it was left in. Dragging a
  tracker into Essential Cooldowns lands it there and it survives a `/reload`. Right-clicking a tracker
  lists *Move to* entries for the other three containers plus *Hide* and *Remove*. No section header
  offers a rename or delete.

## Risks

- **The tab gets taller.** Six sections at ~80px each plus 18px gaps already exceed the previous four.
  `UpdateScrollChildHeight` sums `SECTION_DEFS` and the tab is already in a scroll frame, so this is
  handled; accepted cost, recorded in `35-CONTEXT.md`.
- **Reordering Bars and Buffs is user-visible.** Intended — the order is the user's own from
  `35-CONTEXT.md`. No data changes, only render order.
- **A tracker dropped into Essential or Utility has no renderer until Plan 04.** Plan 04 is in the same
  phase and generalises `UpdateDisplay` to all four. Until it lands, such a tracker falls through
  `Display.lua`'s `else` branch and renders as a bar — wrong, but not an error, and fixed within the phase.
