<objective>
Close STEAL-15: a TBT container hidden by its visibility setting also hides the merged frames placed
in it, and showing it brings them back.

What is already done, verified at planning time against the code:
- Phase 68 review WR-03 rebuilt the cooldownID -> cell map whole on every render. Every TBT hide
  path returns before `ns:AttachMergedItem`:
  - `RenderIconContainer` and `RenderBarContainer`: `if not visible then container:Hide() return`,
    after `ShouldShow` (Visibility Hidden, Visibility In Combat while out of combat, Hide When
    Inactive with nothing active);
  - `RenderContainers`: no container or no settings snapshot;
  - container deletion, which unregisters the def.
- So the ids in a hidden container are not attached that render, `ns:FlushMergedPlacement` sees
  `mappedCount ~= attachedCount`, prunes them, and its pool walk `ReleaseItem`s their frames back to
  the parked viewer. That is the CONTEXT rule: back to the viewer, not SetAlpha(0).
- Showing the container re-attaches the ids on the same render, and the flush places them.
- The combat edge already renders at once: Display.lua's PLAYER_REGEN_DISABLED/ENABLED handler calls
  `ns:UpdateDisplay()`.
- No other path hides a TBT container without a render deciding it:
  - `EditModeFrames.lua` `ApplyEditModePositions` / `HideEditModeHandles` hide on `tbtVisible == false`,
    which the next render overrides;
  - line 960 is container deletion.
- What is left for this plan:
  1. State the rule in the code, and retire the OPEN ITEM that still lists it as "Phase 69, STEAL-15".
  2. The other direction (68-REVIEW IN-03). The moved frames are still children of their Blizzard
     viewer. When the CDM's OWN Visibility (In Combat / Hidden) hides that viewer
     (`CooldownViewerMixin:ShouldBeShown`, CooldownViewer.lua:1888-1920), the merged frames vanish
     from a visible TBT container, so "showing the container brings them back" fails.
     - TBT cannot fix this inside the boundary. Showing a viewer is a Show/Hide write MergeMode.lua
       rules out ("no Show, no Hide"). It runs the CDM's OnShow on TBT's stack and taints it, and
       Blizzard's UpdateShownState would hide it again on the next combat edge anyway.
     - The viewer is parked off-screen, so the player cannot see the cause.
     - Decision (planner, as the orchestrator asked): this belongs to STEAL-15. Handle it by telling
       the player, once per viewer per session, only when that viewer has merged entries, with the
       exact fix.
     - Add a Visibility line per viewer to `/tbt merge` for Phase 72.

Output: MergeReanchor.lua, Display.lua, MergeMode.lua edited.
</objective>
