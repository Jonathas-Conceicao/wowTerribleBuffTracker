<objective>
Fix STEAL-13: reordering an entry in the CDM settings window, or moving it to another category,
updates TBT's preview right away with no entry in the wrong container and no bar mis-sized or
misaligned.

Diagnosis (from code, recorded so the executor does not re-derive it):
- Phase 68's review fixes already rebuild the cooldownID -> cell map whole every render (WR-03) and
  place from a flush that walks Blizzard's pools, so placement now reaches preview frames (CR-01).
  The POC's "wrong until the window closes" was mostly CR-01: placement went through
  `ns.mergeItemFrames`, which is empty while previewing. That part is done; this plan closes what is
  left.
- What is left is a stale-map window with no ownership check. `CooldownViewerSettingsMixin:EndOrderChange`
  fires `CooldownViewerSettings.OnDataChanged` once, on the drop. Each viewer then runs
  `OnCooldownDataChanged` synchronously. If its item count changed, as on a category move, it calls
  `RefreshLayout`: `ReleaseAll`, then Acquire with `OnAcquireItemFrame` (which resets
  SetScale/SetBarWidth), then `Layout`. TBT's Layout post-hook then force-places every frame through
  `cellByID`, which the PREVIOUS render built. So the bar viewer's new frame for the moved id lands
  on that id's old Tracked Buffs icon cell, with the old `kindByID` "icon": anchored CENTER, scaled
  to the icon's height, and with no SetWidth. That is the "moved buff shows in another container"
  and the "bar size/alignment off" in the report.
  - `PlaceItem` matches on cooldownID alone and never checks that the frame's viewer is the one the
    cell's container mirrors.
  - The shown-slot pass that follows the mirror rebuild also places, through the same old map,
    because Display has not rendered the new lists yet.
- Mid-drag `layoutIndex` reads are NOT a cause. The settings window drags its own
  `CooldownViewerDraggedItem`, not a viewer item frame. `OnDataChanged` fires only on the drop.
  `RefreshLayout` stamps `layoutIndex` before `Layout`. The same-count path (`RefreshData(cooldownIDs,
  forceSet)`) keeps `layoutIndex` and re-assigns ids in place, with no Layout. The deferred mirror
  therefore always reads a consistent order. No delay is added (CONTEXT: "fix the cause, don't add
  delays").

Fix (CONTEXT STEAL-13 decision: rebuild whole, fix the cause):
1. Viewer ownership. Each attach records the CDM viewer of the attaching container. `PlaceItem`
   treats a frame whose parent is not that viewer as having no cell, and releases it to its parked
   viewer.
2. Render before placing after a mirror rebuild, so placement never reads an old map.
3. A same-render duplicate-attach guard, so one id can never flip between two cells.

Output: MergeReanchor.lua, Display.lua and MergeMode.lua edited. No new file, no TOC change.
