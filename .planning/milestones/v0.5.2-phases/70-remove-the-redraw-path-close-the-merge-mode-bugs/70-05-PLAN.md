- One frame on many cells: impossible; a frame has one anchor, and PlaceItem sets it from one
  cellByID lookup.
- One id fanned out to many cells: cellByID maps an id to one cell; AttachMergedItem's same-render
  guard keeps the first cell; the mirror publishes each cooldownID in one list (frameOwnerByID /
  claimedIDs, added by the previous phase's review fix IN-01).
- One cell holding many ids: idByCell evicts the previous id when a cell is reused.
- A frame from another viewer on a cell: PlaceItem's `parent ~= viewerByID[id]` check releases it.
- Two active frames for one cooldownID in one viewer: Blizzard lays out one frame per configured id;
  even if that broke, the damage is two copies of the same id on that id's own cell, not a fan-out.
  Record it as a residual note, not a route.
- Stale map after a configuration change: the Merge-on mirror rebuild places nothing
  (ReanchorMergeViewers(skipPlace)); the next render rebuilds the map whole (renderGen /
  attachGen / the mappedCount prune) before its flush places; the Layout post-hook's forced pass is
  limited to its own viewer by the viewer check.
- Mind control / charm: nothing in Merge Mode now depends on unit reaction, assistability, faction
  or "is from player"; there is no aura filter left to bypass. Whatever a merged cell shows is
  exactly what Blizzard's own CDM frame for that id shows. If Blizzard's CDM itself showed a foreign
  aura on every item, that would be visible in the unmerged CDM too; TBT neither reads nor copies it.
- Merge Mode off: ns:SetMergeMode wipes the shown lists inline; Display's fail-closed
  `elseif entry.isMerged then` arms hide; the flush and PlaceAllMergedItems release every placed
  frame.
- 999.21: the merged charge count is drawn only by Blizzard's frame now; PLAYER_SPECIALIZATION_CHANGED
  and TRAIT_CONFIG_UPDATED are in REFRESH_MIRROR and REASSERT_VISIBILITY, the rebuild sets
  mirrorChangedForPlacement, the shown pass renders then places, PlaceItem re-places a frame whose
  cooldownID changed (placedID stamp), and the viewer's own Layout post-hook re-places it too.
  Observation, outside STEAL-20's scope: a CUSTOM cooldown tracker still uses the sticky
  chargeCapable cache; note it for the backlog, do not change it here.
- 999.25: SlotDraws returns entry.cdmShown for a merged entry; the parked viewer stays shown so
  Blizzard keeps acquiring one frame per configured id, which keeps `seen > 0` outside preview; the
  render runs every UPDATE_INTERVAL from the OnUpdate driver, so a cdmShown flip re-centres within
  one interval; Tracked Buffs publishes its whole configured set, so each entry keeps the same pooled
  cell and the container stays shown when it holds only merged buffs. The previous phase's accepted
  latency (a cell with no points until the next render after a buff lands) still applies.
