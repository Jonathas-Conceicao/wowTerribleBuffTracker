## Overview

TBT stopped being a buff tracker that sits beside Blizzard's Cooldown Manager and became something
that can replace it. Three things define the milestone.

**Cooldown tracking.** A spell's cooldown is now a tracker type of its own, icon-only, with charge
counts where the client will report them — and the same spell can be tracked as a buff *and* as a
cooldown simultaneously, which required re-keying the database into a `cd:<spellID>` namespace
because until then the two were literally the same record.

**Merge Mode.** All-or-nothing across all four categories: Blizzard's CDM containers move off
screen and their entries are drawn inside TBT's own containers alongside the player's trackers. TBT
never injects into, parents into, or writes to a Blizzard CDM frame. The hardest problem in the
milestone lived here — giving a merged buff icon a cooldown sweep — and it was solved by inverting
the approach: stop trying to *read* the aura and draw it, hand Blizzard widgets to an
`AuraContainer` and let the engine draw. Every read-based route was structurally dead, not merely
difficult, because the getters return secrets and the numeric setters are `AllowedWhenUntainted`.

**One download, two clients.** The two flavour-suffixed TOCs v0.3.0 shipped collapsed back into one
`TerribleBuffTracker.toc` declaring `## Interface: 120100, 16001`, with one `.pkgmeta`, one CI job
and one zip — following the pattern shipping Forever addons already use, and deleting the
two-flavour drift bug class rather than guarding against it.

Around those: four base containers plus user-created ones, per-container settings, Centered growth,
a settings panel under Options > AddOns, rank grouping on Forever, and racial trackers for gnome,
troll and orc.

The milestone also carries a deliberate reversal worth reading before trusting any timer: a custom
cooldown tracker runs on the duration the **user typed**, timed from the cast TBT observed — not on
the game's own cooldown handle. That was reported as a bug ("the TBT CD is being overwritten by the
actual CD"), investigated, and found to be the opposite of a bug: the typed value had never been
used for any spell the client knows. The cost is accepted and real — haste, cooldown reduction and
resets make the displayed time wrong. Merged CDM slots are unaffected, because they carry no typed
duration and keep the engine's own handle.

For current project status, see `.planning/ROADMAP.md`.

## Milestone Summary

**Renumbered / swapped phases:**

- **Phase 39 → Phase 35.1 (Config Panel).** The user's decision to put container create/delete in
  the config panel meant it had to land *before* Phase 36 built user containers. Renumbered so
  numeric order matches execution order. There is no Phase 39.
- **Phases 42 and 43 swapped (2026-09-22).** Cleanup first, then the Forever end-to-end pass against
  the cleaned code. Verifying code that is about to be rewritten gets the order backwards. Seven
  phase status lines written on 2026-09-21 still say "deferred to Phase 42"; they mean Phase 43.

**Key Decisions:**

- **One TOC, all flavours.** `## Interface: 120100, 16001` in a single TOC, following shipping
  Forever addons (Platynator declares six interface versions and no `## AllowLoadGameType:`).
  Supersedes v0.3.0's two-TOC split. No flavour-forked Lua or XML file may exist.
- **Merge Mode is all-or-nothing.** No per-category toggle. One switch, four categories.
- **Engine-driven sweeps for merged auras.** Hand Blizzard widgets to an `AuraContainer` and let the
  engine draw, rather than reading the aura. The supported shape, and the only one that survives
  combat.
- **Cooldown trackers run on the typed duration** (CD-02, reversed 2026-09-22), timed from the
  observed cast. Accepted cost: haste, CDR and resets are not reflected.
- **The add dialog lost two controls** (ADD-01, ADD-02, superseded 2026-09-22): type comes from the
  active tab, and every new tracker lands in Not Displayed.
- **Centered growth is the default** for buff icon containers, and schema v5 migrates existing ones
  from Right to Centered — defensible only because v0.4.0 has not shipped.
- **No refactors during cleanup phases**, except duplication the milestone itself introduced. Phase
  42 recorded one exception by name: the two render functions.
- **README is the store copy.** No separate CurseForge/Wago description file exists; the user pastes
  README.md into both by hand.

**Issues Resolved:**

- The `.pkgmeta` was not ignoring `.planning`, so every release zip carried 334 tracked planning
  files into players' AddOns folders. Fixed in `295c601` — the one Phase 42 change that affects what
  ships rather than source tidiness.
- Merged auras drifted out of position: the container was sized from slots it held while merged
  entries were withheld from that list, so a narrower container re-centred and every offset followed.
  Merged entries are now published-but-not-drawn, and all grid arithmetic lives in one function,
  `ns:GridSlotPlacement`.
- `STEAL-05` closed in `322806d` by building the mirror from the viewers' own item frames — Blizzard's
  resolution of the player's overrides — so hidden and recategorised spells follow. No mixin call
  needed.
- Fourteen defects across two characters during the Merge Mode rework, each re-tested on the same
  client before moving on.

**Issues Deferred:**

- **Cooldown icon can stay grey through the GCD.** Never reproduced consistently, so it stays in the
  backlog for the next milestone rather than being closed on a guess. User decision, 2026-09-23.
- **Racial catalogue is incomplete.** `RACE-06` / `RACE-07` fill in the remaining races. v0.4.0 ships
  gnome, troll and orc; every other race resolves to a "not yet supported" tile.

  closure at 20 Hz — while `Display.lua` hoisted `ByLayoutOrder` specifically to avoid exactly that.

  grew a v6 block and the constant went 5 → 6, agreeing only because both were remembered.

  not in the TOC and not in the zip, but it is in the repo.
- **No test suite exists.** There is no build manifest, no `luacheck`, and no automated regression
