## Overview

Requirements at [`v0.5.3-REQUIREMENTS.md`](v0.5.3-REQUIREMENTS.md); the audit at
[`../v0.5.3-MILESTONE-AUDIT.md`](../v0.5.3-MILESTONE-AUDIT.md).


The duration question was settled by
[`research/BUFF-DURATION-PROBE.md`](../research/BUFF-DURATION-PROBE.md) (no API gives a buff's
duration, so it is typed).

**Install first.** Pointing `install.ps1` at `_forever_` is independent of everything else and tiny,
and every later phase deploys through it.

**Spells, then the icon, then items.** The buff's config, saved keys and engine timer land on spell
cooldowns first, because spell trackers are already editable and the Aura ID has a natural default
there. The icon look comes next: it needs only a running buff timer on a cooldown tracker, and with
it in place the spell path can be seen end to end before items are touched. Items come last because
they need something no tracker has today, an Edit entry on a `metaItem` tile and greyed read-only
fields in the shared dialog, and they then reuse the buff fields, engine timer and icon look as
built.

### Phase 74: Buff Duration on Spell Cooldowns
**Goal**: A player can give any user spell cooldown tracker its buff, and casting the spell runs a
buff timer of the typed duration alongside the cooldown
**Depends on**: Phase 73
**Requirements**: BUFFCD-01, BUFFCD-02, BUFFCD-03, BUFFCD-04, BUFFCD-08
**Success Criteria** (what must be TRUE):
  1. The add and edit dialogs of a user cooldown tracker show, on the Advanced tab, a "Track buff
     duration" checkbox (off on new and on every existing tracker), an Aura ID pre-filled with the
     spell ID until the user types their own, and an empty Duration
  2. With the checkbox on, the dialog refuses to save until the Aura ID and a positive Duration are
     both filled; with it off, the dialog saves and the two fields keep what they hold, with no effect
  3. With the buff on, casting the spell starts a buff timer of the typed duration at the same moment
     as the cooldown, and the cooldown runs exactly as it does without the buff
  4. The buff timer ends early when its aura is read as gone under the user-buff readable-only rule,
     and never on a read that comes back secret
  5. The buff settings survive logout and login; existing saved trackers load with the buff off and
     nothing else changed, and if the schema changes `node scripts/migrate-dryrun.js` proves it
     against a real SavedVariables file with `--selftest` passing
**Plans**: 2 plans
**UI hint**: yes

Plans:
- [x] 74-01-PLAN.md — reusable greyed field state + "Track buff duration" checkbox, Aura ID, Duration on the Advanced tab (wave 1)
- [x] 74-02-PLAN.md — cast starts the buff timer under the cooldown key; aura-loss end, reset, preview, edit-off (wave 2)

### Phase 75: Buff Look on Cooldown Icons
**Goal**: A cooldown tracker's icon shows its buff the way the CDM shows a cooldown entry's aura,
and shows the cooldown again once the buff is gone
**Depends on**: Phase 74
**Requirements**: BUFFDISP-01, BUFFDISP-02, BUFFDISP-03, BUFFDISP-04, BUFFDISP-05
**Success Criteria** (what must be TRUE):
  1. While a cooldown tracker's buff runs, its icon shows the buff's countdown with the yellow swipe
     (1, 0.95, 0.57, 0.7) clearing back to full colour, no edge, the icon not grey, and no cooldown
     shown

     TBT's current white-to-grey sweep with a grey icon
  3. An icon is grey only while a cooldown shows and no buff does; with neither running it is in full
     colour with no sweep
  4. A cooldown tracker's charge or item count stays visible while its buff runs
  5. Buffs-tab and Reminders-tab icons and the Trinket/Pot meta-trackers look exactly as they do
     today, dark swipe included
