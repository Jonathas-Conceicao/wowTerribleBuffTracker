<objective>
Give a cooldown tracker's icon the CDM's aura look while its buff (Phase 74) runs, return it to TBT's
current cooldown look the moment the buff is gone, and keep the charge or item count visible
throughout. Buff-only, reminder and Trinket/Pot icons stay unchanged.

Purpose: BUFFDISP-01..05. Phase 74 already files the buff proc under the cooldown's own key, and
RenderIconContainer's live-timer branch already draws it on the cooldown's icon. The look is still
the dark buff swipe, though, and the timer branch's ClearCooldownStamps hides the count. Phase 76
reuses this for bag items: everything is keyed on ns:IsCooldownSlotEntry(entry) plus
ns:CooldownBuffDuration(entry), and bag items already answer true to the first.

Output: Display.lua only. Two new file-local helpers (ApplySwipeLook, ApplySlotCount), the
timer-branch handling for a cooldown-slot entry, the look assertion in ApplyCooldownSlot, and
the new stamps reset in ClearCooldownStamps.

Design choices (from 75-PATTERNS.md and the Blizzard CDM source, read-only at
C:\Users\jonat\Repositories\wow-ui-source):
- Per-state look (D: "The three states", "Ground truth"). The aura state uses the Essential item
  template's Cooldown, which has no `reverse` (CooldownViewer.xml:48), plus the aura arm's
  ITEM_AURA_COLOR (1, 0.95, 0.57, 0.7) with no edge (CooldownViewer.lua:892-893). With reverse
  false, the swipe covers the remaining fraction: it starts as a full yellow fill and clears.
  The cooldown state keeps TBT's constructor look: SetReverse(true), SetSwipeColor(0, 0, 0, 0.7),
  SetDrawEdge(true).
- BUFFDISP-04 count approach: **option (a)** from the pattern map. The count half of
  ApplyCooldownSlot's generation block moves into its own helper, ApplySlotCount, with its own
  stamp pair (_cntGen/_cntKey). The timer branch keeps `_cdGen` nil while the buff draws, so
  ApplyCooldownSlot's generation block (and with it ApplyCooldownHandle's re-issue) always runs
  on the handover back to the cooldown. This is why (a) was chosen over (b): the handle re-issue
  rests on a stamp the timer branch never sets, not on clearing logic that has to be kept in sync.
- SetUseAuraDisplayTime (optional in the pattern map) is **not adopted** (Claude's discretion).
  CONTEXT names reverse, colour, edge and desaturation as the look. The API cannot be confirmed
  on the Forever client from the Midnight-only source tree, and TBT drives every sweep from
  SetCooldown(GetTime start, typed duration) anyway.
</objective>

Core.lua
- ns:IsCooldownSlotEntry(entry) -> boolean. True for trackerType USER_CD, or META_ITEM with a
  numeric itemID (a bag item). False for Trinket/Pot meta trackers, userBuff, userReminder and
  metaReminder. Nil-safe.
- ns:IsBagItemEntry(entry) -> boolean. True for META_ITEM with a numeric itemID.
- ns:CooldownBuffDuration(entry) -> positive number or nil. Non-nil only when
  entry.buffEnabled == true and entry.buffDuration is a positive number. Allocation-free and
  never secret.
- ns.cooldownGeneration -> number, bumped by ns:MarkCooldownsDirty().
