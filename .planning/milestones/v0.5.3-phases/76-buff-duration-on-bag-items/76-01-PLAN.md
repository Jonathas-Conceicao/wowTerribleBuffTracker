<objective>
The engine and runtime half of Phase 76: a bag item tracker (kind `metaItem` with a numeric
`entry.itemID`) can be edited for its buff only, and using the item starts its buff timer exactly as a
spell cooldown's cast does in Phase 74 (BUFFCD-05 engine half, BUFFCD-07).

Purpose: per 76-CONTEXT, a bag item carries its buff "exactly like a spell cooldown". Phase 74's
`ns:StartCooldownBuffFromCast`, `ns:CooldownBuffDuration`, `ns:CooldownBuffAliveBuffs` and the cancellation
scan already accept any `ns:IsCooldownSlotEntry` entry; this plan opens the two gates that exclude items
(the edit predicate and the item cast path), adds a buff-only save path that can never re-key or touch the
game-owned `entry.duration`, and fixes the timer-branch icon, which assumes a spellID.
Output: BuffEngine.lua (edit predicate, buff-only commit, shared running-buff refresh, preview itemID),
Providers.lua (item cast starts the buff, proc.itemID, stale comments), Display.lua (item icon while the buff runs).

Saved keys (the Phase 74 contract, reused unchanged on the item entry; missing means off, no schema bump):
- `buffEnabled` — true, or nil
- `buffAuraID` — a number, or nil (for an item the dialog in plan 76-02 always requires a typed one)
- `buffDuration` — seconds, or nil
`entry.duration` on a bag item stays the game's item cooldown, written only by `ns:SeedItemTracker` /
`ns:RefreshTrackedItemCooldowns`; nothing in this plan writes it.
</objective>
