Findings established while planning (Task 1 re-verifies each before anything is touched):

1. **Dead: `ns:CooldownBuffAuraID` (Core.lua).** Added in Phase 74. Its only caller was the first
   `ns:StartCooldownBuffFromCast`, and the Phase 74 review fix CR-01 (commit 4aea96f) replaced that
   call with `ns:CooldownBuffAliveBuffs`. The non-comment tree-wide count is now 1, the definition
   itself. One stale comment still names it as a runtime reader: CDMTab.lua, in the field-contract
   paragraph ("Their runtime readers are Core.lua's `ns:CooldownBuffDuration` and
   `ns:CooldownBuffAuraID`"). Verdict: remove the function and fix the comment.
2. **Stale: Core.lua `ns:IsBagItemEntry` comment** (about line 592, carried in from the Phase 75
   verifier). It says IsBagItemEntry is "narrower than ns:IsCooldownSlotEntry, which also answers
   true for trinket/pot". Both actually answer false for Trinket/Pot, because neither has a numeric
   itemID. IsCooldownSlotEntry is wider only because it also answers true for a user cooldown.
   Verdict: reword (comment only).
3. **Stale: Providers.lua cooldown-buff header** (the block above `ns:StartCooldownBuffFromCast`).
   It lists "an edit that turns the buff off (ns:UpdateTrackedBuff)". Since Phase 74 IN-04 and
   Phase 76, the edit-time end is `ns:ApplyCooldownBuffEdit`. It is called from both edit commits
   (`ns:UpdateTrackedBuff` and `ns:UpdateTrackedItemBuff`), and it also ends a running buff whose
   Duration changed. Verdict: reword.
4. **Overlong comment lines this milestone added.** There are three comment lines over 105 columns,
   at tab width 4:
   - Providers.lua, UserSpellProviderMixin:OnTrigger's cooldown side: "can end on a readable aura
     loss. The cast is still not a timer, ..." (131 columns).
   - Providers.lua, the cooldown-buff header: "now, keeping the cast grace. Pooled and
     allocation-free. On ns, ..." (108 columns).
   - CDMTab.lua, the ApplyFieldEnabled header: "per-field code. The 0.5 grey and the white restore
     are the house convention, copied from the New Container" (110 columns).

   stylua never wraps comments. Verdict: re-wrap to about 100 columns, with the words unchanged.
5. **Hot path: `ns:StartCooldownBuffFromCast` walks `ns.CONTAINERS` with ipairs on every
   qualifying cast** to find `entry.section`'s def. `ns.CONTAINER_BY_KEY` (Core.lua, about line 168)
   is the same registry keyed by container key. `ns:RegisterContainerDef` and
   `ns:UnregisterContainerDef` keep the two in step. "hidden" and "suggested" are in neither, so
   a nil def refuses exactly as the loop does today. Verdict: fix, using one table read.

Kept, not touched (the reasons go into the audit, and Task 1 confirms each):
- `ApplySlotCount`'s second `type(spellID) ~= "number"` guard (Display.lua). Phase 75 review IN-02
  was skipped with a reason: the guard sits inside the `_cntGen`/`_cntKey` stamp gate, and hoisting
  it would add ungated per-tick work.
- The three stamp-clearing sets in Display.lua: `ClearCooldownStamps`, the live-timer branch's
  own-buff handover, and `ApplySwipeLook`'s nils. They are deliberately different subsets. Each
  decides which stamps survive one particular handover (75-REVIEW traces every one), so merging
  them would change behaviour. Swipe-look switching itself already lives in one function,
  `ApplySwipeLook`.
- The `ns:IsCooldownSlotEntry(entry) and ns:CooldownBuffDuration(entry)` pairs in
  `ns:StartAllPreviewTimers`, `ns:ApplyCooldownBuffEdit`, `ns:StartCooldownBuffFromCast` and
  `RenderIconContainer`. Each pair is one expression, and RenderIconContainer reuses its `slotEntry`
  local. A helper would add a call and remove no logic.
- `ns:IsCooldownSlotEntry`'s META_ITEM arm repeats `ns:IsBagItemEntry`. Both predate the milestone
  (`git grep -c "IsCooldownSlotEntry\|IsBagItemEntry" 3377a8e -- Core.lua` is 5), so they are
  protected.
- Buff timer start and end are already unified. Every start goes through
  `ns:StartCooldownBuffFromCast`, which both callers use. Every edit-time end goes through
  `ns:ApplyCooldownBuffEdit`, which both commits use.
