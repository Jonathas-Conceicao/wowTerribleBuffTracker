Create `scripts/reminders-doc-check.js`: plain Node, `fs` and `path` only, in the house style of `scripts/aura-read-gate.js` (header comment block explaining purpose, the two CLI forms, and known limits; small named functions; `FAIL ...` lines; a final PASS line; `process.exitCode` rather than `process.exit`). CLI: `node scripts/reminders-doc-check.js` checks the repo; `--selftest` runs embedded fixtures; `--code <path>` and `--doc <path>` override the defaults (repo-root `Providers.lua` and `docs/REMINDERS.md`, resolved from `path.join(__dirname, '..')`). The overrides exist so a gate can point at a missing doc without touching the tree.

Code side, function parseCode(text):
1. Lex Lua: replace every comment (`--` to end of line; `--[[ ... ]]` and `--[=[ ... ]=]` long comments, keeping their newlines so line numbers survive) with spaces. Leave string literals intact (the `client = "..."` value must stay readable and no ID lives in a string), but the lexer must still recognise strings so a `--` inside one is not taken for a comment. Keep a parallel array of RAW lines for reading trailing comments.
2. Find every call `MetaReminderRow(` and `MetaReminderGroup(` in the lexed code whose name is not preceded by `function ` (so the two `local function` definitions are skipped). From the opening paren, scan to the balanced closing paren (count `(`/`)` and `{`/`}`) to get the argument text; this handles stylua's multi-line calls.
3. Row: spellID = first integer argument; minutes = second integer argument; client = `client\s*=\s*"(\w+)"` or "forever" (any other value is a problem); auraID = `auraID\s*=\s*(\d+)` or none; useItems = the balanced `{...}` after `useItems\s*=`: if it contains inner braces, take the FIRST integer inside each inner `{...}`; otherwise take every integer. From the RAW line holding the call's closing paren, read the trailing comment: class = `--\s*([A-Z][A-Za-z ]*?):` (first word group before the colon, e.g. "Mage", "Warlock"); verified = "unverified" if the comment contains `unverified` (case-insensitive), else "yes". A row with no class comment is a problem.
4. Group: ids = every integer in the argument text; inForever = the call's offset lies inside an `if ns.CLIENT_IS_FOREVER then` block. Find that block's span by walking lexed tokens from the `if`: depth +1 on `function`, `if`, `do`, `repeat`; -1 on `end` and `until`; `for`/`while` do not count (their `do` does); the block ends where depth returns to 0. Support any number of such blocks.
5. codeSets(parsed) returns { forever, retail }, each a Map from key `spell:<id>` / `item:<id>` to a short origin string ("row 10220", "auraID of 474750", "useItems of 1302303", "group of 7301"). Rows: client forever adds to forever, retail to retail, both to both (spellID, auraID, useItems as item keys). Groups: inForever adds every id to forever only; a group outside a Forever block adds its ids to each client on which at least one of its ids is a registered row. A group with no registered row on any client it could apply to is a problem ("group <first id> names no row").
6. Also print, always and first, one line `CODE ROWS <total> (forever <a>, retail <b>, both <c>), GROUPS <n>` so a gate can compare the parser's row count with `grep -c '^MetaReminderRow(' Providers.lua`.

Doc side, function parseDoc(text):
1. Split into sections by `## ` headings (level 2 exactly). Required headings, exact text: `## Forever`, `## Retail`, `## Not included`. A missing one is a problem. Track the current `### <Class>` heading inside Forever and Retail.
2. Collect every link matching `https://www.wowhead.com/<path>` with the full path captured. Accept only `forever/spell=<id>`, `forever/item=<id>`, `spell=<id>`, `item=<id>` (an optional trailing `/slug` or `#anchor` is fine). Any other path (classic, tbc, wotlk, cata, ptr, beta, npc=, quest=, ...) is a problem wherever it sits. In Forever every accepted link must be a `forever/` link; in Retail none may be. Links before the first `## ` heading are a problem. Links under `## Not included` are not collected, but one whose id is a row spellID on any client is a problem ("row <id> listed as not included").
3. Table rows: a line starting `|` that is neither the header line (the line directly above a `|---` separator) nor the separator. cells = split on `|`, drop the empty first and last, trim. In Forever/Retail, cells[1] must be an integer (the Row ID) or the line is a problem. Record per section: rowID -> { class: current `###` text, spellCell: cells[0], duration: cells[2], verified: last cell, line number }. A row ID twice in one section is a problem.

compare(code, doc) returns an array of problem strings; it never prints or exits:
- Per section: forever code keys vs Forever doc keys, retail code keys vs Retail doc keys. Each key missing from the doc: "missing from docs (Forever): spell:10220 (row 10220)". Each doc key missing from the code: "missing from Providers.lua (Retail): spell:12345 (docs line N)".
- Overall: the union of code keys vs the union of doc keys (the CONTEXT's literal rule; usually redundant with the per-section check, kept so the stated contract is checked directly).
- Per row, in each section of its client(s): a table line exists; its `###` heading equals the row's class; its Spell cell contains a link to the row's own spellID; Duration cell is exactly `<minutes> min`, or `permanent` when minutes is 0; Verified cell is exactly `yes` or `unverified` and equals the row's comment-derived value. A table line whose Row ID is not a row of that section's client is a problem.

runGate(): read both files (a missing file is a problem line `FAIL cannot read <path>`, exit 1, still after printing the CODE ROWS line if the code file was readable); print `FAIL <problem>` for each problem; on none, print `REMINDERS-DOC CHECK PASS (<f> Forever IDs, <r> retail IDs, <n> rows)` and exitCode 0, else exitCode 1.

The clean doc fixture must itself satisfy every rule above. Print `SELFTEST PASS <name>` / `SELFTEST FAIL <name>: <msgs>`, then `REMINDERS-DOC SELFTEST PASS (<n> cases)` or `REMINDERS-DOC SELFTEST FAIL (<k>/<n> cases failed)` as the LAST line, with the matching exitCode.
