### Phase 68: Merge Mode by Re-anchoring
**Goal**: With Merge Mode on, every merged CDM entry is drawn by Blizzard's own item frame, placed
in TBT's layout at TBT's size, with no taint
**Depends on**: Phase 67
**Requirements**: STEAL-10, STEAL-11, STEAL-12, STEAL-16, STEAL-17, STEAL-18
**Success Criteria** (what must be TRUE):
  1. Turning Merge Mode on is enough, with no experiment toggle: each merged entry shows Blizzard's
     own frame on its TBT slot at TBT's icon size (bars at the row's height and width), TBT draws
     nothing of its own there, and cooldowns, charges, aura timers, glows, pandemic and dispel
     borders look exactly as on the CDM
  2. Merged entries follow each container's order, direction, Centered and padding, interleave with
     the player's own trackers in the same container, and nothing overlaps
  3. Resizing the CDM or changing its settings leaves merged frames' size in TBT unchanged; changing
     a TBT container's scale or bar width resizes them
  4. A code read shows TBT touches Blizzard's frames only through plain C widget setters on the item
     frames and their child regions (no `SetParent`, field writes or mixin calls) and one `Layout`
     post-hook per viewer, and re-places a frame only when
     its slot or size changes or its viewer re-lays out — never per display refresh; no taint error
     through combat, Edit Mode, combat while Edit Mode is open, and a spec change (M+ in Phase 72)
  5. Turning Merge Mode off returns every moved frame to its Blizzard viewer and restores the
     viewers' positions, without `/reload`
**Plans**: 2 plans
- [x] 68-01-PLAN.md — MergeReanchor.lua becomes the real placement engine: Merge Mode gate, full container styling via plain setters, stamped placement, exact restore on Merge Mode off
- [x] 68-02-PLAN.md — Display/MergeMode wired to the engine; old redraw path unreachable while Merge Mode is on; gates and deploy
**UI hint**: yes
**Notes**: If `MergeReanchor.lua` is folded into another file or renamed, the TOC load list changes
and a **full client restart** is needed before testing, not `/reload`.
