Design choices recorded here (Claude's discretion per 57-CONTEXT):
- Saved key (written by Plan 04): `entry.visibility` = `"present"` or `"absent"`; nil means "always".
- Cache shape: `ns.auraState[key]` = `true` (present), `false` (absent), nil (unknown). It is RUNTIME state that survives rebuilds (a SPELLS_CHANGED rebuild in combat must not thaw a frozen state); a rebuild only invalidates a key whose watched ID changed or which left the watched set.
- **Frozen in combat:** `ns:RefreshAuraStates` returns at once while `InCombatLockdown()` or `C_Secrets.ShouldAurasBeSecret()`; the Plainsrunning precedent says the read cannot succeed there and must not be attempted per event. Per-ID unreadable results inside a refresh also leave that key's state untouched.
- **Cast evidence:** the tracker's own cast is evidence its aura went up, so OnTrigger sets `ns.auraState[ownerKey] = true` for a visibility-gated key; a cross-spell rule ("aura A clears when B is cast") sets `ns.auraState[k] = false` for EVERY visibility-gated buff key the rule lists (not only one whose timer was running: an aura cast by someone else, or one whose timer already expired, is still gone). That is what lets "present" follow its timer and "absent" show or hide its reminder at once in combat, while an aura that merely drops in combat still waits for the next readable moment.
- **Aura-driven start is hybrid (checker decision, 57-CONTEXT "Aura-driven start for present"):** out of combat only, when the aura is present, the tracker is "present" mode USER_BUFF, not hidden, and no timer runs, start it when EITHER (1) the aura's real timing is readable (`ns:ReadableAuraTiming` returns a duration) -- the start then copies the aura's own expiration, so it is correct on every refresh and cannot loop: once that expiration passes, `expirationTime > now` fails and path (1) closes -- OR (2) the state just changed to present (from absent or unknown), the edge-only typed-duration fallback. Plainsrunning starts whenever "seen and no proc", which is safe for an indefinite racial but with a typed duration would restart a finite timer that expired while its aura is still up; the edge restriction on (2) prevents exactly that. The expired-but-aura-up case with unreadable timing draws the idle icon under "present" (57-CONTEXT: "timer/icon").
- **Aura-driven timing:** `ns:ReadableAuraTiming(aura, now)` returns the aura's own `duration, expirationTime` when both are non-secret numbers, `duration > 0` and `expirationTime > now` (then `startedAt = expirationTime - duration`, so the sweep is right), else nil and the typed duration from now is used. `aura` is always the table `ns:ReadPlayerAura` returned in the same refresh (that function already returns it), so there is no second read and aura-read-gate.js stays green.
- **Predicate:** `ns:VisibilityGate(key, entry)` returns nil (no gating: not detailed, no mode, a non-user kind, or unknown state), true (the condition holds: draw even under hideWhenInactive; for "absent" this is the reminder) or false (the condition fails: do not draw). Callers still draw everything while `ns.configOpen` or Edit Mode is active (Plan 03).
