## Migration reconciliation (review item e)

`BuffEngine.lua`'s `ns:MigrateDropDetailedFlag` (lines 538-566) and `scripts/migrate-dryrun.js`'s `migrateV9` (lines 395-419) agree step for step:

| Step | Lua (`ns:MigrateDropDetailedFlag`) | JS (`migrateV9`) |
|------|-------------------------------------|-------------------|
| Gate | `ver >= CURRENT_SCHEMA_VERSION` (9) returns; `ver < 8` returns | `schemaVersion < 8 \|\| schemaVersion >= 9` returns -- same two-sided window, expressed as one OR in JS and two ifs in Lua |
| Fresh read | `local ver = ns.db.schemaVersion or 0` read on every call, not a captured value | `const schemaVersion = db.get('schemaVersion') \|\| 0` read on every call |
| Walk | `for _, entry in pairs(ns.db.trackedBuffs)` + `type(entry) == "table"` guard | `for (const [key, entry] of tb)` + `entry instanceof Map` guard -- same "skip anything that isn't a record" shape |
| Clear condition | `if entry.detailed ~= true then` clear the four Advanced keys | `if (entry.get('detailed') !== true)` clear the four Advanced keys -- identical predicate |
| Clear mechanism | `entry.auraID = nil` etc., unconditional assignment (a no-op if the key was already absent) | `entry.has(field)` guard before `entry.delete(field)`, only to count `cleared` for the log line -- the end state (key absent) is identical; the guard exists in JS only because Map has no no-op "set nil" |
| Drop `detailed` | `entry.detailed = nil` unconditional, every entry, after the clear block | `entry.delete('detailed')` unconditional (Map.delete on an absent key is a safe no-op), after the clear block -- same ordering |
| Stamp | `ns.db.schemaVersion = CURRENT_SCHEMA_VERSION` (9) | `db.set('schemaVersion', 9)` |
| Extra | `ns:RebuildCastIndex()` (Lua-only: rebuilds runtime indexes from the now-migrated saved data; the JS mirror has no runtime to rebuild) | `log.push(...)` per changed key (JS-only: the mirror's diagnostic trail; the Lua migration prints nothing per-key, matching v7/v8's own silence, as already noted in 57.1-01-SUMMARY.md) |

The two extra steps (Lua's index rebuild, JS's log line) are each mirror-appropriate and were already called out as intentional in 57.1-01-SUMMARY.md's "Decisions Made" section; nothing new was found here. No defect exists in either implementation.
