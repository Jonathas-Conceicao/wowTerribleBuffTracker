# Phase 57.1: Tracker Dialog Redesign - Context

**Gathered:** 2026-09-28
**Status:** Ready for planning
**Mode:** Decisions taken with the user in conversation. The ROADMAP.md "### Phase 57.1" section is

<domain>
## Phase Boundary

Redesign the add/edit dialog into two Blizzard text tabs, **General** and **Advanced**, remove the
"Detailed tracking" checkbox and the saved `detailed` mode flag, prefill Advanced with defaults, and
replace the three visibility checkboxes with a radio dropdown. No new tracking behaviour.

Requirement: ADD-07.

</domain>

<decisions>
## Implementation Decisions

### Tabs
- `TabSystemTemplate` tabs hanging ABOVE the dialog (`tabTemplate = "TabSystemTopButtonTemplate"`),
  labelled **"General"** and **"Advanced"**. `tabTemplate` is read in OnLoad, so use a one-line XML
  virtual in CDMTab.xml (e.g. `TBTTopTabSystemTemplate` inheriting TabSystemTemplate with the
  KeyValue), or re-run OnLoad after setting it. Use `AddTab(text)`, `SetTabSelectedCallback(fn)`
  (it must return a falsy value) and `SetTab(id)`.
- **General** = choosing the spell: the portrait, Spell ID, "secret?" badge, Duration (with its
  suggestion) and Cover all ranks (Forever). **Advanced** = the portrait plus the extra settings:
  aura ID (with its small preview and badge), "End when the aura is lost" (buffs only), visibility,
  and the cast rule ("Ends when you cast" / "Resets when you cast").
- The portrait shows on both tabs. The dialog height follows the current tab via the existing
  Layout(). Advanced is offered on both tabs of the CDM (buff and cooldown trackers), with the same
  per-kind child rules as Phase 57.
- Opening the dialog (Add or Edit) selects General.

### Prefilled defaults, no mode flag
- The Advanced tab opens PREFILLED: the aura ID box shows the spell's ID and follows the Spell ID box
  until the user edits it; "End when the aura is lost" is checked; visibility is Always; the cast
  rule is empty.
- Saving: a value equal to its default is stored as nil (aura ID equal to the spell ID → nil,
  cancellation on → nil, Always → nil, empty rule → nil). A non-default value is stored and ALWAYS in
  effect.
- **No `detailed` flag anywhere.** Runtime gates (ns:DetailedAuraID, ns:CancelsOnAuraLoss, the
  visibility index, the end-rule index) key on the values themselves, not on `entry.detailed`.
  General never becomes invalid or disabled because of Advanced.
- **Migration:** drop the `detailed` key. For records whose `detailed` was not true, clear
  `auraID`, `keepOnAuraLoss`, `visibility` and `endOnCast`: they were switched off, and clearing them
  keeps current behaviour. Records with `detailed = true` keep their values. Follow the existing
  schemaVersion chain rules (a new v9 block, older blocks pinned to literals; see Phase 53) and
  mirror it in scripts/migrate-dryrun.js with a selftest case. Verify with a real logout/login.

### Visibility dropdown
- `WowStyle1DropdownTemplate` + `SetupMenu` with three `rootDescription:CreateRadio` entries:
  "Always", "Only while the aura is up", "Only while the aura is missing". Blizzard's own pattern
  (Auction House duration, CDM alerts, Edit Mode). The dropdown shows the selected entry's text. It
  replaces the three checkboxes and `ns:SyncVisibilityChecks`. The Cooldowns-tab rule that
  present/absent needs an aura ID stays, but "aura ID" now defaults to the spell's ID, so decide in
  planning whether that validation still applies or is satisfied by the default.

### No reset button
- By user decision there is no "Reset to defaults". A user who wants plain behaviour starts the
  tracker over.

### CreateAddDialog
- It WILL change this phase (the tab system is dialog-level), which ends the Phase 54-57 hash
  invariant. Keep the change minimal and generic. Prefer a per-field `tab = "general"|"advanced"`
  property that the walker's visibility respects, over special-casing fields. The TRACKER_FIELDS
  contract comment is updated to match.

### Claude's Discretion
- The exact tab widths and offsets (the dialog is 240px), the XML virtual name, and the dropdown width.

</decisions>

<code_context>
## Existing Code Insights

- The TRACKER_FIELDS walker (CDMTab.lua): build/reset/prefill/update/read/validate/available/
  visible; Layout(); RefreshState; "not read means not written" (hidden fields keep saved values).
  The tab split fits naturally as a visibility rule, but saving must read BOTH tabs' fields (a
  field hidden because its tab is not selected is still part of the tracker), unlike the old
  detailed-hidden rule. Plan this carefully: with no mode flag, the "hidden means kept" rule is
  replaced by "every field is read, and defaults are stored as nil".
- `ns:DetailedModeOffered`, `ns:DetailedChildShown`, the `detailed` field, and
  `ns:SyncVisibilityChecks` are removed or replaced. Runtime users of `entry.detailed`:
  BuffEngine.lua (DetailedAuraID, CancelsOnAuraLoss), Core.lua (RebuildDetailedRuleIndex, the
  visibility index, detailedRankFamilies), and Providers/Display where they read it.
- Blizzard_Menu's MenuUtil already works on both clients in this addon (the tile context menu).
- CDMTab.xml exists and holds the TBT tab button XML; add the tab-system virtual there, and keep
  the TOC unchanged.

</code_context>
