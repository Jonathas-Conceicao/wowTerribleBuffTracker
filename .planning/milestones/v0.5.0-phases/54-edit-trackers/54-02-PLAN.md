THE FIELD DEFINITION CONTRACT (EDIT-03 — state it verbatim-in-substance in the comment block above TRACKER_FIELDS; later phases rely on it):

`TRACKER_FIELDS` is one ordered array literal. Each element is a table with:
- `id` (string, unique) — how siblings find it: `dialog.GetFieldState(id)`. GetFieldState is defined BEFORE the build loop, so a field's `build` may call it to anchor to a sibling built EARLIER in TRACKER_FIELDS (a later sibling is not built yet and returns nil)
- `entryKey` (string or nil) — the saved-entry field this field owns. nil = display-only (never read or stored). `spellID` and `duration` are passed to the engine positionally; every other entryKey travels in `fields`/`fieldKeys` and is persisted by ns:AddTrackedBuff / ns:UpdateTrackedBuff with no engine edit
- `available()` (optional) — the BUILD-TIME capability gate, evaluated ONCE at build; false = never built, no row, no space (Cover all ranks: `ns.CLIENT_HAS_SPELL_RANKS`, the one sanctioned flavour flag — its only reader stays this field). Never re-evaluated; use `visible` for anything that changes while the dialog is open
- `visible(state, ctx)` (optional) — the RUNTIME show/hide hook, evaluated on every open and after every state change; absent = always visible. A hidden field's row is hidden and takes no space (the walker re-lays out every row and resizes the dialog), is not validated, is skipped by Tab, and is not read — so its entryKey is stored as nil (ns:UpdateTrackedBuff clears it)
- `build(row, y, onChange, dialog)` -> `state, nextY` — `row` is a per-field Frame the walker creates and positions; the field creates its widgets on `row` (FontStrings via `row:CreateFontString`, frames parented to `row`), anchored TOPLEFT to `row` at (16, y) with `y` starting at 0, wires every value change to `onChange`, and returns a per-field state table (may set `state.editBox` to join the Tab/Enter ring) plus **the cursor for the NEXT row, gap included**. The walker takes the row's height as `-nextY`; a field never adds a leading gap for itself
- `reset(state, ctx)` — add-mode defaults
- `prefill(state, entry, ctx)` — edit-mode values from the saved entry (54-03 calls it, after `reset`). **prefill copies**: a table value from `entry` is copied into the field's state, never aliased, so editing the dialog cannot mutate the saved entry before Save
- `update(state, ctx, dialog)` (optional) — runs on every change, before visibility and validation (for live previews and suggested values). **update must compare before writing** to a sibling widget: `SetText`/`SetChecked` on a sibling re-fires its `onChange` and re-enters RefreshState, so write only when the new value differs from the widget's current one, or the dialog recurses without end
- `read(state, ctx)` -> value to store; nil = store nothing. **read returns a fresh table** for a table-valued field (never the state's own table), because the engine stores what it is given by reference
- `validate(state, ctx)` -> `ok, message` — ok=false disables confirm; message (optional) is shown in the red error label; the first failing visible field with a message wins

`ctx` is one reusable table on the dialog: `{ mode = "add" | "edit", kind = ns.KIND.USER_BUFF | ns.KIND.USER_CD, editingKey = key | nil, entry = saved entry | nil }`.

Layout (the walker owns vertical placement): `Layout()` starts its cursor at -38 (today's first-row offset); for each built field in order it either hides the row, or anchors it TOPLEFT to the dialog at (0, cursor) and steps the cursor down by the row's height; then it anchors the error label TOP at (0, cursor), steps 32 and calls `dialog:SetSize(240, math.abs(cursor) + 46)`. The error label therefore always sits after the last visible row. Resulting offsets: Spell ID row -38, Duration row -88, Cover all ranks row (Forever) -138, error label -164 on Forever (dialog 240x242, identical to today) and -138 on retail (dialog 240x216; today retail's label sits at -106, on top of the Duration box — this fixes it).

A helper declared lower in the file (e.g. AddExclusiveCheck at :1386) is nil to these functions — do not call it from a field def.
