## Performance and cleanup review

Covers the phase diff against 6bd11d0 for Core.lua, BuffEngine.lua, Providers.lua, Display.lua and CDMTab.lua.

- **Hot paths.** These paths call none of `ns:TrackerLoad`, `ns:SpellKnownState`, `ns:ResolveSpellKnown` or any C_SpellBook API, and allocate nothing new:
  - the Display render loops (bar slots, icon slots, `RefreshCooldownSlotCounts`);
  - `ns:GetActiveTimers`;
  - `UserSpellProviderMixin:OnTrigger`, which reads only the cast and rank indexes;
  - the racial provider: `OnTrigger`, `ConsumeRacialStack` and `RacialAuraTrigger`, which now walk `ns.racialDefsActive` (usually 0 to 2 entries instead of the race's list);
  - `ns:OnUnitAura` and `ns:RefreshAuraStates`, which walk `ns.visibilityKeys`, already filtered.

  The only new per-frame read is `ns:IsTrackerLoaded(key)`, a single table lookup (gated). `ns:ConditionalCooldown`, on the per-cast path after a cooldown match, now does one map read through `ns:RacialDefForSpellID` instead of an ipairs walk. No resolution needed.
- **Rebuild cost.** `ns:ResolveSpellKnown` is called from exactly two places, `ns:RebuildTrackerLoad` and `ns:RebuildRacialLoadLists` (gated). Per When known tracker with a numeric spell ID, `ns:SpellKnownState` makes:
  - 2 guarded lookups (base and override);
  - then up to 4 known-spell pcalls per distinct ID, stopping at the first "true". A known spell typically costs 3 pcalls in total. An unknown spell costs at most 2 + 4 x 3 = 14.

  On Forever the rank scan runs only when the spell, its base and its override all read not known, and the family is cached per spell ID in `ns.loadRankFamilies` (wiped only with `ns.endRuleFamilies`). The racial lists pass `noRanks`, so they never scan ranks. The five talent/spec/learn events coalesce into one `C_Timer.After(0)` rebuild through the single file-scope `RunLoadRefresh`.
  - **Finding, fixed (0bf217b):** `ns:RebuildRacialLoadLists` ran the known check for all ~20 racials on every rebuild, retail included. On retail `ns.knownRacialDefs` is never read, because `ns:RacialSuggestions` is Forever-only, and retail fires SPELLS_CHANGED often, so that was ~120 wasted pcalls per rebuild. It now builds the known list only when `ns.CLIENT_IS_FOREVER`. That is an existing named consumer, not a new flavour check.
- **Dirty checks.** `ns:RebuildTrackerLoad` bumps `ns.trackerGeneration` and redraws only when the loaded set actually changed (`changed` flag). It swaps two tables instead of allocating (`loadScratch`).
  - **Noted, accepted:** that redraw runs from inside `ns:RebuildCastIndex`, before the cast and rank indexes are rebuilt. Nothing the redraw draws reads those indexes, and Display's 0.05s OnUpdate tick redraws within one tick, so any transient is invisible. Moving it would have added a second deferral path for no user-visible gain.
- **Dead code.** These now appear nowhere, code or comment (gated): `ns:IsRacialKeyVisible`, `racialGateKeyIDs`, `ns:RacialDefsForPlayer` and its two module tables. `ns:RacialDefsRaw` and `racialRaceIDMemo` remain, called only by schema v7's migration (BuffEngine.lua), and their comment says so. `racialSpellOwners` remains for `ns:IsRacialSpellID` (schema v8). `EMPTY_RACIAL_DEFS` and `ns:RacialDefInList` are still used (RacialDefsRaw, RacialSuggestions, RacialCooldownSeed). The UnitRace call in Core.lua's `ns:LogPlayerRace` is a debug print, not gating.
- **Duplication introduced by this phase.** None:
  - the known check lives in `ns:SpellKnownState` alone (the four API names appear nowhere else, gated);
  - the load resolver lives in `ns:TrackerLoad` alone;
  - `ns:ClearTrackerRuntimeState` now reuses `ns:EndTrackerRuntime` instead of repeating it;
  - the refresh pattern in `ns:RebuildTrackerLoad` mirrors the existing one in Core.lua, with no new third copy elsewhere.

  Pre-existing code was not refactored.
- **Upvalue order.** Every file-local the phase added is declared above its first reader: FIXED_LOAD, the two LOAD_REASON strings, AskKnown, loadScratch, RunLoadRefresh, racialRaceIDsSorted, racialDefsAll/racialDefsBySpellID/racialDefsAllResolved, and LOAD_CHOICES. Everything read across files is on `ns`: LOAD, TrackerLoad, trackerLoaded, IsTrackerLoaded, TrackerLoadReason, SpellKnownState, ResolveSpellKnown, RebuildTrackerLoad, RequestLoadRefresh, EndTrackerRuntime, RacialDefsAll, RebuildRacialLoadLists, knownRacialDefs and racialDefsActive.
- **Scope.** Since 6bd11d0, only Core.lua, BuffEngine.lua, Providers.lua, Display.lua and CDMTab.lua changed. MergeMode.lua, EditModeFrames.lua, Config.lua, CDMTab.xml, the TOC and scripts/ are byte-identical. The schema is still 10, and no OnUpdate was added (all gated). CHANGELOG.md was not touched.
