<objective>
The engine half of Phase 57.3 (LOAD-02, LOAD-03, LOAD-04; LOAD-01's saved-value semantics are
defined here and its dialog lands in 57.3-02). One generic load rule decides whether a tracker runs
at all. This plan adds the resolver, the "known" check, the cached loaded state and its rebuild
triggers, leaves unloaded trackers out of every runtime index and provider path, clears their
runtime state when they unload, and replaces the race-based racial list with "the racials this
character knows".

The race gate's render-time predicate (`ns:IsRacialKeyVisible`) is NOT deleted here: Display.lua
and CDMTab.lua still call it, and 57.3-02 swaps those callers and deletes it in the same commit, so
every commit on the branch leaves a working addon.

Purpose: the user's framing, "rework this racial meta-tracking thing into something more generic a
user can have too", and "our meta-trackers abide a very similar rule-set than user created ones".
Output: Core.lua, BuffEngine.lua and Providers.lua changes, two commits.

Decisions this plan takes (Claude's discretion, recorded for the SUMMARY):
- Saved values: `entry.load` is nil (When known), `ns.LOAD.ALWAYS` ("always") or `ns.LOAD.NEVER`
  ("never"). `ns.LOAD.KNOWN` ("known") is the resolver's answer and is never saved. Any other saved
  value (a hand edit) reads as When known. A built-in kind ignores any saved `load`.
- Built-ins: metaSkill and metaSkillCd When known; metaItem (trinket, pot, bag items) and the
  reserved userItem kind Always; `ns.META_KEY.LUST` Always (it is a metaSkill key with no spell ID).
- The load state is rebuilt at the top of `ns:RebuildCastIndex`, so every existing rebuild site
  (add, edit, remove, migrations, InitBuffEngine, world entry, SPELLS_CHANGED, CDM drop) refreshes it
  with no new call site. Before the first PLAYER_ENTERING_WORLD (`ns.knownReady` unset) every When
  known tracker is loaded: the spellbook is not ready, and nothing runs before world entry anyway.
- Unreadable answers hold the last readable answer per spell ID (`ns.spellKnownHeld`), and with none
  fail open for trackers (loaded) and closed for Suggested racials (not offered).
- On Forever the rank-family fallback runs only when the spell, its base and its override all read
  not known, and the family is cached per spell ID (`ns.loadRankFamilies`, wiped where
  `ns.endRuleFamilies` is). The racial lists skip the rank fallback (`noRanks`): every
  RACIAL_SPELLS row is a single-rank ID, and skipping it keeps ~20 spellbook scans off every
  SPELLS_CHANGED.
- The five talent/spec/learn events are coalesced through one `C_Timer.After(0)` callback declared
  once at file scope, so a burst of TRAIT_CONFIG_UPDATED costs one rebuild.
- Unloading clears runtime state through a new `ns:EndTrackerRuntime(key)` that keeps the proc pool,
  so a tracker that loads again allocates nothing on its first cast. `ns:ClearTrackerRuntimeState`
  becomes EndTrackerRuntime plus ReleaseProc, unchanged in effect.
</objective>
