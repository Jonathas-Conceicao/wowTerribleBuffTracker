## Performance and cleanup review

**(a) Cast path.** UserSpellProviderMixin:OnTrigger, ns:FillUserBuffProc and ns:ApplyEndOnCast only
lost lines (the `auraState` evidence writes); FillUserBuffProc changed only in its header comment.
ns:RebuildCastIndex admits only USER_BUFF into ns.buffKeyBySpell and USER_CD/META_SKILL_CD into
ns.cooldownKeyBySpell; ns:RebuildRankIndex stores a reminder's family (for the aura watch) but skips
both cast-resolving index writes; the end-on-cast trigger index is USER_BUFF/USER_CD only. A cast
can never resolve to a reminder key.

**(b) UNIT_AURA and PLAYER_REGEN.** ns:OnUnitAura's secret branch calls ns:ClearReminderStates,
the normal path ns:RefreshAuraStates. Both are numeric loops over ns.visibilityKeys with no table
constructor, no pairs, no closure; each sets `changed` only on an actual state change and calls
ns:UpdateDisplay once. PLAYER_REGEN_DISABLED is one flag write plus ClearReminderStates;
PLAYER_REGEN_ENABLED clears the flag before RefreshAuraStates. In combat with readable auras a
UNIT_AURA costs one early loop that writes nothing (all states already nil).

**(c) Render path.** SlotDraws, RenderIconContainer, RenderBarContainer: the reminder selection is
VisibilityGate (one predicate call, one table lookup), the centred test changed `== "buffs"` to
`~= "spells"` (same cost). VisibilityShowsIn is the unchanged Phase 57 numeric loop. No new table,
closure, string or pairs walk per frame. The Phase 57 runtime was reused as-is: beyond the reminder
selection, the present-path deletion and the two REM-03 additions (combat flag, clear-to-unknown),
no rename or restructure. Not changed: RenderBarContainer's reminder loop is unreachable today
(reminders are icon-only), kept by the "reuse as-is" direction and so commented.

**(d) Dialogs and menus.** The category dropdown's IsSelected/SetSelected are built once per
dialog build; the SetupMenu generator runs on menu open; the three new `visible` hooks
(duration, auraID, endOnCast) run in the dialog's layout pass on open/change only; the Move to /
Add to category filters run inside the right-click menu generator. ADD_TITLE_BY_CATEGORY is read on
hover and open only.

**(e) Dead code and stale comments.** No reference remains to auraStartPending,
StartUserBuffFromAura, ReadableAuraTiming or VISIBILITY_CHOICES (gate). Found and fixed:
- Display.lua RenderIconContainer: "a tracker gated off by its visibility mode" -> now describes
  the reminder gate (3c1e9e9).
- BuffEngine.lua ns:OnUnitAura: "a secret or full-update event ... the state holds" was Phase 57
  semantics; a secret event now clears every reminder state (ede4b99).
- Core.lua (2), Display.lua (1), EditModeFrames.lua (1): comment lines left at 121-159 columns by
  partial rewraps in plans 01-03, rewrapped (3c1e9e9). Pre-existing overlong lines were not touched.

Recorded, not changed:
- WireExclusivePair (CDMTab.lua, CONT-04) now has one caller (Icons/Bars) after plan 03 replaced
  the category pair with a dropdown. It predates the milestone, and inlining it would be a refactor
  of pre-existing code; same reasoning as the named ns:FillUserBuffProc exemption.
- ns:VisibilityGate tests `not entry` before ns:IsReminderEntry, which is already nil-safe. Harmless.

**(f) Migration reconciliation.** Neither side changed after plan 01 (`git log 443f7af..HEAD --
scripts/migrate-dryrun.js` is empty; ns:MigrateBuffReminders has no diff since 443f7af):

## Known behaviour

- A reminder's state is held while its aura cannot be read (combat, M+, secret): an unreadable
  read never counts as missing. A reminder whose timer ends mid-combat shows mid-combat.
  (Corrected 2026-09-29: the 57.2-04 build hid reminders in combat; 57.2-05 changed that.)
- A reminder whose aura cannot be read at all never shows (unknown hides; unreadable is never
  "missing").
- A Buff Reminders container whose Edit Mode Visibility is set to "In Combat" shows a reminder
  whose timer runs out mid-combat, so the option is valid and kept. (Corrected 2026-09-29: the
  57.2-04 build hid reminders in combat, so this container never showed; 57.2-05 changed that.)
- The Buff Reminders seed position is TBT's own (BOTTOM 0, 430), one row above Blizzard's BuffIcon
  viewer; it mirrors no CDM viewer.
