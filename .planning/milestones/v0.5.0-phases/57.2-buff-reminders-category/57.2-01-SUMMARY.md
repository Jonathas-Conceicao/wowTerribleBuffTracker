# Phase 57.2 Plan 01: Reminder kind, container and schema v10 Summary

**Buff reminders become a canonical kind (`userReminder:<id>`) behind one extensible predicate (ns.REMINDER_KINDS / ns:IsReminderEntry), with a fifth undeletable "Buff Reminders" base container in a third category "reminders", engine add/update/conflict rules for a kind that has no duration, and schema v10 migrating Phase 57's "absent"-visibility buffs into reminders. The migration was specified first in scripts/migrate-dryrun.js (case I) and the Lua matches it line for line.**

## Performance and cleanup review

- No per-frame or per-cast work added. ns:IsReminderEntry and the REMINDER_KINDS checks are one
  table lookup; RebuildRankIndex's reminder branch runs only on its existing event triggers.
- The migration runs once per database (schemaVersion gate), collects into one local array.
- Observation, not changed: ns:AddTrackedBuff and the ns:InitBuffEngine preallocation loop still
  call ns:PreallocateProc for a reminder key, so each reminder carries an unused proc buffer. It is
  a one-off allocation per tracker, not a hot path; plan 02 (runtime) may skip it when it wires
  the reminder display.
- Every code path that reads `cdmViewerGlobal` / `cdmCategoryName` (EditModeFrames.lua, Display.lua,
  MergeMode.lua) is already nil-guarded, so the reminders container is skipped there like a user
  container.
- No dead code introduced.

## Known Stubs

None that block this plan's goal. Consumers of the new kind and category (the runtime watch and
display in plan 02, the Reminders tab and dialog in plan 03) are later plans by design;
ns:DefaultGrowthDirection still centres only "buffs" containers until plan 02.
