# Phase 57.2 Plan 03: Reminders tab, reminder dialog and radio-dropdown container category Summary

**Reminders are now reachable by the player: a third "TBT Reminders" CDM side tab, tile menus that never cross categories, an "Add Reminder" / "Edit Reminder" dialog driven by per-kind visible() hooks (no Duration, aura ID only on Advanced), the visibility field gone from every tracker (and the aura ID from cooldowns), and a Buffs / Cooldowns / Reminders radio dropdown in the new-container dialog that doubles as the recorded multi-choice pattern.**

## What changed

- **Tab (REM-01):** TBTRemindersTab (LargeSideTabButtonTemplate, no parentArray) is set up by
  SetUpTBTTab, anchored under TBTSettingsTab in AnchorTabBelowCDMTabs, shown in ns:InitCDMTab, and
  its checked state is kept in ns:SelectTBTCategory (which now accepts "reminders"),
  ns:ShowTBTPanel and ns:HideTBTPanel. The Reminders tab's Suggested section keeps only the + and
  settings squares.
- **Menus (REM-01):** "Move to" lists only containers of `ns:GetTrackerCategory(entry)`; the
  Suggested "Add to" lists only containers of the active tab's category. The + square's tooltip
  names what the tab adds.
- **Dialog (REM-02/REM-04):** duration and endOnCast get `visible = not ns.REMINDER_KINDS[ctx.kind]`;
  auraID gets `visible = ctx.kind ~= ns.KIND.USER_CD`; keepOnAuraLoss unchanged (its comment
  updated). The visibility field, VISIBILITY_CHOICES and the WR-01 cooldown tip are deleted.
  OpenForAdd picks USER_REMINDER on "reminders"; titles come from ADD_TITLE_BY_CATEGORY /
  EDIT_TITLE_BY_KIND, both declared above CreateAddDialog.
- **Container dialog (REM-01):** the Buffs/Cooldowns checkbox pair is replaced by a
  WowStyle1DropdownTemplate DropdownButton over CONTAINER_CATEGORY_CHOICES; any category other
  than Buffs forces Icons and disables Bars; SelectCategory (unknown values fall back to Buffs)
  and ResetChoices call GenerateMenu. WireExclusivePair lost its unused onSelect parameter.
- **Config.lua:** paragraph updated, three 170px buttons at PAD_X, +180, +360 (fits PANEL_W 620),
  "Reminders" row label, ns:OpenContainerDialog forwards any category.

## Deviations from Plan

1. **Local variable renamed to satisfy the gate.** The plan said Create reads a local `category`,
   but Task 3's gate requires the literal `dialog.SelectCategory = function(category)`. The dialog's
   upvalue is `selectedCategory`, so SelectCategory's parameter does not shadow it. Same behaviour.
2. **keepOnAuraLoss comment updated (code unchanged).** It said it was "the one Advanced field with
   its own visibility rule left", which stopped being true once auraID and endOnCast got their own
   hooks.

No gate was changed.

## Performance and cleanup review

- Everything added runs on click, hover or dialog open: the menu generators, the + tooltip lookup
  (one string index), the title lookups and the visible() hooks (they read only ctx and allocate
  nothing). None of it runs per frame.
- CONTAINER_CATEGORY_CHOICES, ADD_TITLE_BY_CATEGORY and EDIT_TITLE_BY_KIND are built once at file
  load. The dropdown's IsSelected/SetSelected are built once per dialog build.
- Dead code removed: VISIBILITY_CHOICES, the visibility field, WireExclusivePair's onSelect
  branches, buffsCheck/spellsCheck. No reference to `visibility` is left in CDMTab.lua code, only in
  comments that describe its removal.
