# Phase 57.2 Plan 02: Reminder Runtime on the Phase 57 Aura Watch Summary

The Phase 57 "absent" aura watch now drives reminders. It is selected through `ns:IsReminderEntry`, a reminder hides the moment combat starts or a read becomes unreadable, the whole "present" path is gone, and reminder containers now grow Centered by default.

## What changed

- **Core.lua:** `ns:RebuildDetailedRuleIndex` watches `ns:IsReminderEntry(entry) and type(entry.spellID) == "number"`. The `pending` table and `ns.auraStartPending` are deleted. `ns.playerInCombat = false` is new, set at PLAYER_ENTERING_WORLD from `InCombatLockdown()`. PLAYER_REGEN_DISABLED sets it and calls `ns:ClearReminderStates()`. PLAYER_REGEN_ENABLED clears the flag before `ns:RefreshAuraStates()`. `ns:RebuildRankIndex` now builds the aura-ID family for USER_BUFF and reminders; USER_CD is dropped. `ns:DefaultGrowthDirection` returns Centered for any non-bar container whose category is not "spells".
- **BuffEngine.lua:**
  - New `ns:ClearReminderStates()`: a numeric loop that makes one write per key only where needed and redraws once.
  - `ns:RefreshAuraStates`: calls the clear and returns when in combat, restricted or secret. It now writes `nil` on an unreadable read (`present ~= previous`).
  - `ns:OnUnitAura` calls the clear in its secret branch.
  - `ns:VisibilityGate` now answers only for reminders.
  - Deleted: `ns:ReadableAuraTiming`, `ns:StartUserBuffFromAura`, the auraState writes in the expiry sweep, the cancellation scan and `ns:ApplyEndOnCast`, the auraStartPending lines in `ns:ClearTrackerRuntimeState`, and `entry.visibility = nil` in the IN-01 block.
- **Providers.lua:** OnTrigger returns `ns:FillUserBuffProc(...)` directly, and the cast-evidence write is gone. The FillUserBuffProc comment now names its one caller.
- **Display.lua:** the only code change is the centred test, now `~= "spells"`. The Phase 57 comments describe reminders, and no `"present"` remains.
- **EditModeFrames.lua:** DirectionOpts offers Centered on any category other than spells. The ApplyContainerPosition comment no longer claims Forever never reads saved variables.

## Deviations from Plan

1. **[Review extra, requested by orchestrator] Reminders are no longer preallocated a proc buffer.** This covers `ns:InitBuffEngine`'s preallocation loop, `ns:AddTrackedBuff`, and the re-key branch of the tracker update path, which already had `isReminder` in scope. A reminder never produces a proc. `ns:AcquireProc` still creates on demand, so this is safe. (be5c3af)
2. **Comment accuracy:** the PLAYER_REGEN_DISABLED comment said "Kept to this one call". It is reworded because the handler now does the reminder hide as well.

No gate needed fixing.

## Performance and cleanup review

- **UNIT_AURA while secret:** `ns:ClearReminderStates` walks the few reminder keys and writes only non-nil states. Once everything is nil, repeated secret UNIT_AURA events cost one short loop and no redraw. It allocates nothing.
- **UNIT_AURA in combat but not secret:** `ns:RefreshAuraStates` returns through the same clear before any aura read.
- **PLAYER_REGEN edges:** one flag write plus one clear (disable), or one flag write plus one refresh (enable). No OnUpdate or polling was added.
- **Dead code:** no references remain anywhere in the addon to `auraStartPending`, `ReadableAuraTiming` or `StartUserBuffFromAura`. `ns.visibilityAuraID` is still read by `ns:RefreshAuraStates` and the rebuild invalidation. `ns:RebuildVisibilityWatch` is unchanged and still used.
- The bar-container reminder append loop in `RenderBarContainer` can never match, because reminders are icon-only. It was kept on purpose under the minimal-churn direction and is commented as such.
