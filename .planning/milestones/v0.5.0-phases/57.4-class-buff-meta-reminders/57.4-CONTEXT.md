### Kind and behaviour (MREM-01)
- Add a new canonical built-in reminder kind, e.g. `ns.KIND.META_REMINDER = "metaReminder"`,
  keyed `metaReminder:<spellID>` following the Phase 53 scheme. Add it to `ns.REMINDER_KINDS`, and
  to the buff-like set where reminders are.
- It behaves **exactly like a user reminder**, through the shared buff code paths (the standing
  rule: reminders are buffs). That means the cast timer, aura-loss ending, the aura watch, the
  expiry sync, holding state while unreadable, drawing while missing, and the Reminders category.
- Its data (spellID, duration, rank coverage) comes from the table, not from user input. Decide
  in planning between storing a copy on the entry at creation and resolving from the table by key,
  following how metaSkill racial trackers do it, and keep one source of truth.
- **Not editable:** `ns:IsEditableTracker` excludes it, so no Edit entry. It can be moved and
  removed like other built-ins.
- **Load:** fixed at When known in the `ns:TrackerLoad` / FIXED_LOAD table (Phase 57.3).
- **Coexistence:** it never blocks a user tracker (buff, reminder or cooldown) for the same spell,
  and a user tracker never blocks it (the 2026-09-29 rule). Use a separate cast index, as 57.2-05 did
  for reminders and the meta-cooldown fix did for metaSkillCd. A second metaReminder for the same
  spell is refused as a duplicate, and dragging the tile again moves the existing one.

### Suggested offering (MREM-02)
- Forever only (`ns.CLIENT_HAS_SPELL_RANKS` or the flavour check the racial tiles use). Retail
  offers none.
- Show a tile on the **Reminders** tab's Suggested section for each table row this character
  **knows** (the 57.3 known check, rank-aware). Drag to a reminders container to create it. Follow
  exactly the racial Suggested tile flow (`ns:RacialCooldownKeys` / `AddSuggestedTracker`), and
  reuse it rather than duplicating it.
- Tile icon, name and tooltip come from the spell, like any spell key.

### Ranks (MREM-03)
- Every rank the character knows counts, resolved from the spellbook by name through the existing
  "Cover all ranks" family (`ns:ResolveRankFamily` / the rank index). The metaReminder is treated
  as rank-covering always. A rank the character doesn't know, cast on them by someone else, is
  not recognised; this limitation is accepted.
- **Blood Pact** is an imp (pet) spell: the warlock may not "know" it through the player
  spellbook. The planner verifies how the known check and rank family work for a pet spell on
  Forever (IsSpellKnown(id, true), the pet spellbook) and makes it load for a warlock who has the
  imp's spell. If that can't be verified statically, fail open: treat it as loaded for warlocks
  (e.g. by class) and flag it in the UAT. It has no duration, so no timer: it shows while the aura
  is readably missing and hides while present.

### Claude's Discretion
- The kind name, the data table's location (Providers.lua next to the racial data is the natural
  home), and the tile order.
