## Performance and cleanup review

Scope: `git diff 04fc8bb -- Core.lua BuffEngine.lua Providers.lua CDMTab.lua`.

- **Cast hot path.** `UserSpellProviderMixin:OnTrigger` gains the metaReminder side, which costs two table lookups on a miss (`ns.metaReminderKeyBySpell`, `ns.rankIndexMetaReminder`). It adds no constructor and no API call. `ns:StartReminderFromCast` is the old inline reminder block moved unchanged: pooled procs through `ns:FillUserBuffProc`, one `GetTime()` only when there is a positive duration, and one `UpdateDisplay`. The gate confirms that neither function nor `ns:GetActiveTimers` builds a table. Finding: none.
- **Aura and render hot paths.** `ns:RefreshAuraStates`, `ns:OnUnitAura`, `ns:GetActiveTimers` and `ns:VisibilityGate` are unchanged. They key on `ns:IsReminderEntry`, so a metaReminder joins with no new per-event work. Display.lua is byte-identical. Finding: none.
- **Rebuild cost.** `ns:ApplyMetaReminderDef` runs once per metaReminder entry per `ns:RebuildCastIndex`: one map read, and it writes only on a difference. The pet-spellbook pass in `ns:ResolveRankFamily` runs only when `includePetBook` is true, which only `ns:RebuildRankIndex` passes, and only for Blood Pact. Its walk is bounded by `C_SpellBook.HasPetSpells()` (at most about 10 slots) and does nothing with no pet out. Finding: none.
- **Render cost.** `ns:MetaReminderSuggestionKeys` is called only from the Reminders tab's Suggested draw (gated). It makes 14 `ns:ResolveSpellKnown` calls on CDM open or after a drag, never per frame. A row the character does not know at the base ID falls through to the rank family, which is cached per spell in `ns.loadRankFamilies` until the next SPELLS_CHANGED or world entry, so the spellbook scan runs at most once per row per spellbook change. The key array is module-level and wiped, not reallocated. Finding: none.
- **Drag cost.** AddSuggestedTracker now calls `ns:RebuildRankIndex()` instead of `ns:RebuildCastIndex()`. That costs one full rank rebuild per user drag or menu add, the same as `ns:AddTrackedBuff`. It never runs per frame. Finding: accepted by design (57.4-02 decision).
- **Dirty checks.** No new redraw was added. A spell tracked as both a user reminder and a metaReminder redraws twice on a cast. This is accepted, as in the 57.2-05 buff-and-reminder case. Finding: none.
- **Dead code and stale comments.** No "future metaReminder" or "future built-in reminder" wording is left (gated). The old inline reminder start is gone from OnTrigger, and `reminderKey` is still read by `ns:ApplyEndOnCast`'s skip rule, so nothing is unused. Stale comments were updated: the "Seven canonical kinds" header, the "ONE CAST, FOUR POSSIBLE TRACKERS" block (now five), the "four cast-index maps" header (now five), and the provider list. Finding: none.
- **Duplication introduced by this phase.** There is one reminder start (`ns:StartReminderFromCast`), one Suggested key-tile draw (`PlaceSuggestedKeyTile`, which also serves the racial cooldown loop), and one data source (the table, re-applied by `ns:ApplyMetaReminderDef`). The phase introduced no duplicate. Pre-milestone code was not refactored. Finding: none.
- **Upvalue order.** `META_REMINDER_DEFS`, `metaReminderDefsBySpellID`, `MetaReminderRow` and `metaReminderSuggestionKeys` are declared above their only readers in Providers.lua, and `PlaceSuggestedKeyTile` is declared above `ns:RefreshTBTSections`. Everything read across files or above its declaration is on `ns` (`ns:MetaReminderDef`, `ns:MetaReminderKnownID`, `ns:MetaReminderUsesPetBook`, `ns:ApplyMetaReminderDef`, `ns:MetaReminderSuggestionKeys`, `ns:StartReminderFromCast`). The Core.lua call sites are nil-guarded, because Providers.lua loads after Core.lua. Finding: none.
- **Scope.** Since 04fc8bb only Core.lua, BuffEngine.lua, Providers.lua and CDMTab.lua changed. Schema is still 10, and no OnUpdate or event registration was added (all gated). CHANGELOG.md was not touched.
