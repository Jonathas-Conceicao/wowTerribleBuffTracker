<objective>
The Suggested half of Phase 57.4 (MREM-02): the class-buff tiles on the Reminders tab, and creating a
metaReminder from one. Follows the racial Suggested tile flow exactly (CONTEXT "Suggested offering":
`AddSuggestedTracker`, drop-or-menu, a tile stays offered so dragging it again moves the tracker) and
reuses it instead of duplicating it.

Purpose: ROADMAP 57.4 criterion 1 ("the Reminders tab's Suggested section offers a tile for each class
buff this character knows. Dragging it creates a built-in reminder") and criterion 4 (retail offers
none).
Output: CDMTab.lua changes, one commit.

Decisions this plan takes (Claude's discretion, recorded for the SUMMARY):
- A tile stays in Suggested after its reminder exists, like the racial cooldown tiles, so "dragging
  the tile again moves the existing one" (CONTEXT) is reachable. AddSuggestedTracker already moves an
  existing key, and the key is the duplicate check.
- AddSuggestedTracker rebuilds with `ns:RebuildRankIndex()` (which runs `ns:RebuildCastIndex()`
  first) instead of `ns:RebuildCastIndex()` alone, the same call `ns:AddTrackedBuff` makes. Without it
  a new metaReminder would have no rank family or rank-aware aura watch until the next SPELLS_CHANGED,
  and a lower-rank cast would not start it. The extra cost is on a user drag, never per frame. It also
  preallocates the new key's proc buffers (`ns:PreallocateProc(key)`), so its first cast allocates
  nothing (the pool rule).
- The tile draw shared by the racial cooldown loop and the new loop is a file-local
  `PlaceSuggestedKeyTile(section, key, slot)` declared above `ns:RefreshTBTSections`, its only caller.
  It also hides a pooled frame's charge count, which the racial cooldown loop never did (a recycled item
  tile could show its count on a racial tile); that is a fix, not a behaviour change.
- The Forever gate stays inside `ns:MetaReminderSuggestionKeys` (Providers.lua, 57.4-01); the render
  path names no flavour flag.
</objective>
