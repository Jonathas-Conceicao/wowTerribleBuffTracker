<objective>
Lay the naming scheme's foundation and the saved-data migration: one kind table in Core.lua that
mints and parses every key, a spellID -> key cast index so the hot path stays a table lookup, and
schema v8 in BuffEngine.lua that re-keys a v0.4.1 database onto `<kind>:<id>` without losing
anything.

Purpose: NAME-01 (one canonical scheme driving identifiers and constants) and NAME-02 (saved data
uses it; v0.4.1 migrates on first load with every container, order and setting intact). Plans
53-03 (Providers.lua) and 53-04 (CDMTab/Display/MergeMode) consume the ns API this plan defines.

Output: Core.lua key/kind helpers and cast index; BuffEngine.lua schema v8.
Note: between this plan and plans 53-03/53-04 the addon is intentionally inconsistent (callers still
use the removed prefix constants). Nothing is deployed until plan 53-05.
