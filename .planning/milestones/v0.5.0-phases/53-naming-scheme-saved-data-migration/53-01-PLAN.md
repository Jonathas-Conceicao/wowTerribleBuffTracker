<interfaces>
Canonical kind strings (53-CONTEXT "Kind names", locked): userBuff, userCd, metaSkill, metaSkillCd,
metaItem, userItem (reserved, no producer). Key shape (53-CONTEXT "Keys", locked): `<kind>:<id>`.
Meta ids chosen for this phase (Claude's discretion, 53-CONTEXT): `metaSkill:lust`,
`metaItem:trinket`, `metaItem:pot`. These exact strings are also what plan 53-02 puts in Core.lua
(`ns.KIND`, `ns.META_KEY`) — keep them byte-identical.

v8 classification table (old key -> new key, kind):
- numeric N (trackerType "buff" or nil)        -> `userBuff:N`, userBuff
- numeric N with trackerType "cooldown" (defensive; v6 should have moved it) -> cooldown rule below
- `cd:N`, N in RACIAL_SPELLS (ANY race)         -> `metaSkillCd:N`, metaSkillCd
- `cd:N`, N not a racial spellID                -> `userCd:N`, userCd
- `item:N`                                      -> `metaItem:N`, metaItem
- `racial:N`                                    -> `metaSkill:N`, metaSkill
- `lust`                                        -> `metaSkill:lust`, metaSkill
- `trinket` / `pot`                             -> `metaItem:trinket` / `metaItem:pot`, metaItem
- key already `<knownKind>:<...>`               -> key unchanged, trackerType set to that kind
- anything else                                 -> left exactly as it is
Per moved record: entry.trackerType = kind; entry.key = newKey; entry.spellID backfilled from N ONLY
when nil and the kind is a spell kind (userBuff/userCd/metaSkill/metaSkillCd); entry.itemID
backfilled from N ONLY when nil and kind is metaItem with a numeric id. Nothing else on the record
is touched. If newKey is already occupied the old record is dropped rather than clobbering (the
v7 T-49-08 precedent) — never reached by a real v0.4.1 database because the mapping is injective.
Gating: v8 runs only when schemaVersion >= 7 (v7 complete) and < 8; stamps 8.

Live v7 (BuffEngine.lua ns:MigrateRacialKeys, current source): returns if schemaVersion >= 7;
returns WITHOUT any change when raceID is nil; for slot i of { "racial", "racial2" }: removes the
old key; if the race has a def in slot i, writes the SAME entry table to `racial:<def.spellID>`
(unless occupied) after setting entry.key, entry.spellID = def.spellID, entry.duration =
def.duration, entry.label = def.fallbackLabel or entry.label; stamps 7.
</interfaces>
