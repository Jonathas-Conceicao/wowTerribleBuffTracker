**Status:** Ready for planning

<domain>
## Phase Boundary

Reminders get "alternative buffs that also satisfy the main one" in place of the buff tracker's
"Ends when you cast" rule. The built-in paladin blessings use this so they satisfy each other.
Righteous Fury is added, and Sanctuary is dropped.

The user said, after testing 57.4 on a paladin: "the list should be alternative buffs that also
satisfy the main one ... all 3 pally buffs are mutually exclusive, so if I have all 3 reminders
on screen, two reminders will always be up, when in reality I expect any of these buffs to satisfy
all 3 triggers."

</domain>

<decisions>
## Implementation Decisions

### The rule (RALT-01)
- For **reminders only** (every kind in `ns.REMINDER_KINDS`: user and meta), the Advanced field
  becomes **"Also satisfied by (comma separated):"**. It uses the same spell-ID list input as
  today, with its icon row and validation. **Buff trackers keep "Ends when you cast (comma
  separated):" exactly as it is.** This is a deliberate, user-decided divergence from the
  "reminders are buffs" rule, and the only one. Record it in comments.
- **Semantics:** a reminder is satisfied (hidden) while its own buff OR any alternative is
  **present** (a readable aura read) or **running** (a timer started by casting it). It shows only
  when none of them is. Each alternative covers its rank family (Forever) and its base/override
  (retail), as the aura ID and rank families do today.
- **Suggested model:** the reminder's watched aura set becomes its own family plus each
  alternative's family, which the existing watch lists already hold as ID lists. Casting an
  alternative starts the reminder's timer exactly as casting the main spell does; a cast index maps
  alternative IDs to the reminder key. The duration is the reminder's own, and the readable-expiry
  sync takes the latest expiry among the present watched auras. "End when the aura is lost"
  applies to the whole set: the reminder ends only when none of the watched auras is present.
- **Keep the post-cast re-check** (57.4 CR-01) working with alternatives. Casting an alternative
  on another player must not keep your own reminder hidden once a readable read says none of the
  set is on you.
- **Saved key:** the planner picks either a new key (e.g. `alternatives`) or reusing `endOnCast`
  with the kind giving its meaning. Prefer a new key for clarity. The dialog stores nil when it's
  empty (the stored-as-nil rule).
- The self-reference validation ("can't list itself") and the "Advanced:" error prefix work as
  they do today.

### Migration (RALT-02)
- **Schema v11:** for every reminder entry (user reminders; built-in reminders carry no user
  `endOnCast`), move `endOnCast` into the alternatives list as-is, then drop `endOnCast`. That is
  the user's choice, "Convert to alternatives". Buff trackers keep `endOnCast`.
- Follow the chain rules: a new v11 block, with v10 pinned to the literal 10. Mirror it in
  scripts/migrate-dryrun.js, writing the selftest cases first. Verify with a real logout/login.

### Built-in data (RALT-03)
- Blessings of Kings (20217), Might (25291), Wisdom (25290), Salvation (1038) and Light (19979)
  list each other as alternatives in the metaReminder table (Providers.lua `META_REMINDER_DEFS`
  / `MetaReminderRow`). A built-in row's alternatives come from the table (single source of
  truth, applied like the other def fields in `ns:ApplyMetaReminderDef`), not from user input.
- **Remove Blessing of Sanctuary (20914)**: the user reports it no longer exists on Forever. A
  placed Sanctuary reminder then takes the 57.4 WR-02 path: greyed, "no longer offered", with no
  data deleted.
- **Add Righteous Fury (25780), 30 min, Paladin.** Its load gate is When known, like every row. Its
  aura ID is assumed to be the spell ID; the user verifies it.
- Update the table header comment about which rows are verified in game. The user tested Mage,
  Paladin and Warlock, and is now testing other classes.

### Claude's Discretion
- The key name, how the cast index maps alternatives, and whether the dialog's icon row reuses the
  existing cast-rule row code (it should).

## Existing Code Insights
- CDMTab.lua TRACKER_FIELDS: the `endOnCast` field. It is labelled per kind, with "Resets when you
  cast" for cooldowns and "Ends when you cast" otherwise, both with "(comma separated)". It has an
  icon row, `ns:ParseSpellIDList` and self-reference validation.
- Core.lua: `ns:RebuildDetailedRuleIndex` (endKeysBySpell and the reminder watch list),
  `ns:RebuildVisibilityWatch`, the rank families (`ns.detailedRankFamilies`, `ns.endRuleFamilies`),
  `ns:RebuildCastIndex` (reminderKeyBySpell, metaReminderKeyBySpell), and `ns:IsReminderEntry` /
  `ns.REMINDER_KINDS`.
- BuffEngine.lua: `ns:ApplyEndOnCast` (the cross-spell end), `RefreshAuraStates`,
  `ScanActiveTimersForCancellation`, the post-cast re-check, the migrations (v10 is the current
  block), and `ns:ApplyMetaReminderDef`.
- Providers.lua: `ns:StartReminderFromCast`, `META_REMINDER_DEFS`, and OnTrigger.
- scripts/migrate-dryrun.js (the migration mirror) and scripts/aura-read-gate.js (must pass
  unchanged).
