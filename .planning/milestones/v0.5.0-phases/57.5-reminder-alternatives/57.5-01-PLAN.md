<objective>
The saved-data and dialog half of Phase 57.5 (RALT-02, and RALT-01's dialog). A reminder's
"Ends when you cast" list becomes "Also satisfied by" (the user's words: "the list should be
alternative buffs that also satisfy the main one"). This plan adds the new saved key, the schema v11
step that converts every reminder's existing list into it, and the dialog field that edits it. The
runtime that reads `alternatives` lands in 57.5-02. Until then a reminder's list is saved but not
yet acted on, and every commit leaves a working addon: no reminder key reaches the cast rule after
v11, and buff trackers are untouched.

Purpose: ROADMAP 57.5 success criteria 1 (the dialog half) and 2.
Output: scripts/migrate-dryrun.js, BuffEngine.lua, Core.lua and CDMTab.lua changes, five commits.

Decisions this plan takes (Claude's discretion per CONTEXT, recorded for the SUMMARY):
- **New saved key `alternatives`** (CONTEXT "Saved key: prefer a new key for clarity"). It is an
  array of positive spell IDs, stored as nil when empty (the stored-as-nil rule). A reminder never
  carries `endOnCast` after v11. A buff or cooldown never reads `alternatives`.
- **This is the one deliberate divergence from "reminders are buffs"** (CONTEXT RALT-01, user
  decision 2026-09-29). Every comment that touches it says so and cites RALT-01.
- **v11 conversion rule** (CONTEXT "Migration": "Convert to alternatives"). For every entry whose
  trackerType is in ns.REMINDER_KINDS (userReminder and metaReminder) with a non-nil `endOnCast`:
  - A non-empty table becomes `alternatives`, as the SAME table object ("as-is").
  - If `alternatives` is already a table (only possible by hand-editing), each numeric positive ID
    not already in it is appended.
  - An empty table or a non-table value is dropped.
  Then `endOnCast = nil`. A metaReminder is converted like a user reminder (CONTEXT: "built-in
  reminders carry no user endOnCast"; ns:ApplyMetaReminderDef already clears it, and 57.5-02 makes
  the table overwrite `alternatives` too).
- **Selftest shape.** Cases I and J (v10) now call `migrateV10` directly instead of `migrate()`.
  This is case H's precedent: v11 would otherwise move the endOnCast that v10 keeps on the
  reminders it creates. The end-of-chain cases A, D, F and G assert `schemaVersion === 11`. The new
  case K covers v11 on its own; the new case L runs the real v9 -> v10 -> v11 path, where an
  "absent" buff becomes a reminder whose cast rule becomes its alternatives.
- **Dialog.** One shared spell-ID list row, per CONTEXT "the dialog's icon row reuses the existing
  cast-rule row code (it should)". Its build, text setter, icon update, read and validate become
  file-locals above TRACKER_FIELDS. Two field defs use them:
  - `endOnCast`: gains a `visible()` that hides it for reminders.
  - `alternatives`: new, directly after `endOnCast`; visible only for reminders.
  The dialog's "not read means not written" rule keeps a hidden field's saved value, so an edit
  never touches a buff's `alternatives` or a reminder's leftover `endOnCast`.
</objective>
