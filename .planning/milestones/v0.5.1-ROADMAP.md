## Phase Details

### Phase 61: Bug Fixes
**Goal**: Selecting a TBT container in Edit Mode no longer reaches into Blizzard's Edit Mode, and a
merged charge spell reads "buff time left, N charges" at once, as the CDM's own icon does
**Depends on**: Nothing (first phase of the milestone)
**Requirements**: EDM-08, STEAL-09
**Success Criteria** (what must be TRUE):
  1. In Edit Mode, clicking a TBT container still selects it, highlights it and opens its settings
     popup on mouse-down as before — and no TBT code path calls `EditModeManagerFrame.ClearSelectedSystem`
     or any other Edit Mode mixin method (the `pcall` in `ns:SelectContainer` is gone, not replaced
     by a different call or a direct `selectedSystem` write)
  2. Blizzard's yellow highlight may stay on a Blizzard system while a TBT container is also
     selected; that is the accepted cost and is not treated as a regression
  3. On retail in Merge Mode, casting the Mage's Prismatic Barrier shows the buff duration **and** the
     charge count on the TBT cell for the whole time the buff is up, matching the CDM's own icon
  4. When the buff ends, the cell returns to its cooldown display with the charge count still
     correct, and a charge spell whose buff is not active looks exactly as it did before the fix
**Plans**: 2 plans

Plans:
- [x] 61-01-PLAN.md — delete the Edit Mode clear-selection call from `ns:SelectContainer`, scan TBT's other Edit Mode references (EDM-08)
- [x] 61-02-PLAN.md — diagnose 999.17, then raise the merged charge count above the engine aura frame while the engine path is active (STEAL-09)

*Two small, independent fixes from backlog 999.9 and 999.17, grouped so the Edit Mode taint fix lands

### Phase 63: Clickable Reminders
**Goal**: Out of combat, a player can refresh a missing buff by clicking its reminder, without TBT's
display ever becoming protected or tainted
**Depends on**: Phase 61 (Edit Mode taint fixed before secure frames sit next to Edit Mode), Phase 62
**Requirements**: CLICK-01, CLICK-02, CLICK-03, CLICK-04, CLICK-05, CLICK-06
**Success Criteria** (what must be TRUE):
  1. Out of combat, left-clicking a shown reminder icon casts that reminder's cast spell, in every
     reminders container — the base Buff Reminders container and every user-added one — and hovering
     it still shows the reminder's tooltip
  2. A click area exists only where a reminder icon is drawn: an empty reminders container, or one
     whose reminders are all unloaded or satisfied, has nothing clickable. Each area sits exactly on
     its icon after login and after Edit Mode closes, and while Edit Mode is open no overlay catches
     the mouse, so containers drag normally
  3. In combat, clicking a reminder does nothing; entering and leaving combat with reminders shown
     raises no Lua error, no blocked-action message and no taint, and anything that changed during
     combat is applied on leaving it
  4. Each reminder's Advanced settings carry a cast spell that defaults to the reminder's own spell
     and can be changed; built-in reminders ship with it set, and a built-in with no castable spell —
     Forever's Blood Pact, an imp ability — has no click action at all
  5. Clickable reminders are on by default and can be turned off, and the option's tooltip says
     plainly that clicks work out of combat only
**Plans**: 3 plans

Plans:
- [x] 63-01-PLAN.md — each reminder gets a cast spell: an Advanced "Cast spell ID" field for user reminders, castID on the built-in rows (Blood Pact none), ns:ReminderCastID (CLICK-06)
- [x] 63-02-PLAN.md — ReminderClick.lua: pooled secure overlays on UIParent, placed by screen rect, state-driver combat hiding, stood down in Edit Mode, tooltip and highlight; added to the TOC (CLICK-01, CLICK-03, CLICK-04, CLICK-05)
- [x] 63-03-PLAN.md — Display marks which drawn icons are clickable, a default-on Click to Cast checkbox on every reminders container, all gates and a deploy (CLICK-01, CLICK-02, CLICK-04)
**UI hint**: yes

*Settled design, backlog 999.18: a separate `SecureActionButtonTemplate` overlay per icon, parented
to `UIParent` and **never anchored** to the icon or any TBT frame; placed in screen coordinates from
the icon's `GetRect()` (size, strata, frame level + 1), deferred one frame after login and redone
when Edit Mode closes, dirty-checked on the rect; action via `type1 = "spell"` and `spell = <cast
spellID>`, written only out of combat and only on change; `RegisterStateDriver(overlay,
"visibility", "[combat] hide; show")`; every function touching attributes, position, `EnableMouse`
or visibility returns early on `InCombatLockdown()`, with `PLAYER_REGEN_ENABLED` applying what was
deferred; mouse off (or hidden) while Edit Mode is open. Reminders are buffs — the cast-spell field
follows the same field rules as every other reminder field.*
