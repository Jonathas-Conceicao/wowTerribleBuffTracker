### Phase 53: Naming Scheme & Saved-Data Migration
**Goal**: Every tracker kind — user buff, user cooldown, meta skill (Lust, racials), meta item
(trinket, pot, bag consumables), with user item reserved — is named by one scheme in code and in
saved data, and a player upgrading from v0.4.1 loses nothing
**Depends on**: Nothing (first phase of v0.5.0; builds on shipped v0.4.1)
**Requirements**: NAME-01, NAME-02
**Success Criteria** (what must be TRUE):
  1. With a v0.4.1 `TerribleBuffTrackerDB` in place, logging in on the new build shows every existing
     tracker — user buffs, user cooldowns, Lust, trinket, pot, racials and bag items — in the same
     container, in the same order, with the same settings as before. Proven by a **real
     logout/login**, never `/reload`
  2. After a second logout/login the saved file carries only the canonical `trackerType` values and
     key prefixes and the bumped `schemaVersion`; the migration does not re-run and no tracker is
     duplicated
  3. Every tracker kind still behaves as it did in v0.4.1 — a cast starts a user buff timer and a
     user cooldown tile, Lust, trinket, pot, racial and bag-item trackers still fire — with no Lua
     errors
  4. A user buff and a user cooldown added after the migration are saved under the canonical names
     and survive a logout/login
  5. One canonical kind list drives the kind identifiers, provider names and constants in code; the
     old kind identifiers survive only inside the migration step

### Phase 57.1: Tracker Dialog Redesign (INSERTED)
**Goal**: The add/edit dialog presents Simple and Detailed as two tabs made from Blizzard's own
templates, with every Detailed field prefilled with its default, so nothing expands and every
choice reads clearly
**Depends on**: Phase 57
**Requirements**: ADD-07
**Inserted**: 2026-09-28 by user decision, after reviewing a mockup of the Phases 56-57 dialog. The
"Detailed tracking" checkbox that expanded options, and the three checkboxes for visibility, were
both rejected. Research that settled the templates (retail 12.1 source plus the BigWigsMods/WoWUI
`forever-beta` tree; everything below exists on both clients):
- **Tabs:** `TabSystemTemplate` with `tabTemplate = "TabSystemTopButtonTemplate"` (the modern
  Spellbook/Professions/Friends tabs), set through a one-line XML virtual because `tabTemplate` is
  read in OnLoad. API: `AddTab(text)`, `SetTabSelectedCallback(fn)` (it must return a falsy value),
  `SetTab(id)`. Blizzard has no vertical text side tab: `LargeSideTabButtonTemplate`, which the CDM
  settings use, is icon-only.
- **Visibility:** `WowStyle1DropdownTemplate` + `SetupMenu` + three `rootDescription:CreateRadio`
  entries: Blizzard's own pattern (Auction House duration, CDM alerts, Edit Mode).
**Success Criteria** (what must be TRUE):
  1. The dialog shows "Simple" and "Detailed" text tabs above it. Simple shows the portrait, Spell
     ID and Duration (plus "Cover all ranks" on Forever); Detailed shows the portrait and the
     detailed fields. There is no "Detailed tracking" checkbox.
  2. On the Detailed tab every field opens prefilled: aura ID = the spell's ID (and it follows the
     Spell ID box until the user edits it), "End when the aura is lost" checked, visibility Always,
     cast rule empty.
  3. Visibility is one dropdown whose menu shows the three choices as radio items.
  4. There is no saved mode flag: a tracker behaves as detailed only where a Detailed value differs
     from its default. Existing trackers saved with `detailed = true` keep their behaviour through a
     migration or an equivalent rule, verified by a real logout/login.
  5. Add and Edit both work on both tabs and on both clients; the dialog's height fits its current
     tab.
**Plans**: 3 plans
- [x] 57.1-01-PLAN.md — a new schema step drops the saved mode flag (switched-off values cleared; node mirror and selftest first); runtime gates key on the saved values
- [x] 57.1-02-PLAN.md — dialog: General and Advanced top tabs from TabSystemTemplate, Advanced prefilled (aura ID follows the Spell ID), visibility radio dropdown, both tabs read on save
- [x] 57.1-03-PLAN.md — whole-phase gates, performance and cleanup review, deploy, retail and Forever in-game checklist with the logout migration check
**UI hint**: yes
**Settled with the user, 2026-09-28 (supersedes the tab names above):**
- **The tabs are named "General" and "Advanced"** (not Simple/Detailed). General is choosing the
  spell (portrait, Spell ID, Duration, and Cover all ranks on Forever). Advanced holds extra
  configuration.
- **No "Reset to defaults" button.** The user prefers one feature and one UI element fewer; a user
  who wants plain behaviour starts the tracker over.
- **Advanced values are just more settings, always in effect.** Nothing on Advanced invalidates or
  disables anything on General, and there is no mode that turns Advanced off. The migration drops
  the old `detailed` key. For records whose `detailed` was not true, it clears the Advanced keys
  (`auraID`, `keepOnAuraLoss`, `visibility`, `endOnCast`), because those values were switched off.
  Such records can only exist from unreleased 56-57 test builds; clearing them keeps their current
  behaviour.

## Milestone Summary

### What shipped

The three backlog items the milestone was opened for, then five inserted phases that grew out of
in-game review of the first ones:

1. **One naming scheme** (NAME-01/02, backlog 999.13) — every tracker kind (`userBuff`, `userCd`,
   `metaSkill`, `metaSkillCd`, `metaItem`, with `userItem` reserved) named once in code and in saved
   data. Schema v8 re-keys a v0.4.1 database; v9, v10 and v11 followed later in the milestone.
2. **Editing trackers** (EDIT-01..04, backlog 999.12) — every user tracker is editable after
   creation, spell ID included, from one shared field definition (`TRACKER_FIELDS`) that drives both
   the add and the edit dialog.
3. **ID preview, suggested cooldown and secrecy** (ADD-04/05, SECR-01..03) — a live portrait of the
   ID being typed, the game's cooldown suggested, and the aura secrecy level on every TBT tooltip
   and the TOOL-01 line, with a "secret?" badge in the dialog.
4. **Advanced tracking** (DTRK-02/04/05/06, ADD-06/07, backlog 999.14) — a separate aura ID, an
   opt-out of aura-loss cancellation, cross-spell "ends/resets when you cast" rules working in
   combat, and an unreadable aura never treated as absent. Shipped as General/Advanced tabs with no
   saved mode flag.
5. **Buff Reminders** (REM-01..04, Phase 57.2, inserted) — a third category with its own tab and
   container. A reminder is a buff tracker that shows while its buff is missing. It replaced the
   Phase 57 visibility option.
6. **One load rule** (LOAD-01..04, Phase 57.3, inserted) — When known / Always / Never on every
   tracker. It replaced the racial race gate; unloaded trackers are never processed and show greyed.
7. **Class-buff meta reminders** (MREM-01..03, Phase 57.4, inserted, Forever) and **reminder
   alternatives** (RALT-01..03, Phase 57.5, inserted) — ready-made reminders for class buffs, and an
   "Also satisfied by" list so mutually exclusive buffs (the paladin blessings) satisfy each other.

### Key decisions

- **Advanced values are just more settings, always in effect** (57.1). There is no simple/detailed
  mode and no saved `detailed` flag. A tracker behaves differently only where an Advanced value
  differs from its default, and defaults are stored as nil. No "Reset to defaults" button.
- **A reminder is a buff tracker in its own category** (57.2-05). Same fields, same timer, same aura
  rules; only its category, container and display differ. Any future change to buff tracking is
  expected to apply to reminders too.
- **Typed input always makes a user tracker** (2026-09-29). Only a Suggested tile creates a built-in
  tracker. A user cooldown and a built-in racial cooldown for the same spell coexist, and one cast
  starts both; built-ins never block or shadow a user tracker.
- **"Racial" names a group of built-in spells, nothing more.** The race gate is gone: racials load
  When known, like any other spell, and a user tracker on a racial spell is just a spell.
- **The dialog ended on Blizzard's own panel frame with CDM-style icon side tabs** (57.3), after the
  `TabSystemTemplate` top tabs of 57.1 were compared side by side against it in game.
- **Merge Mode is on for a fresh database** (58, user request). Every existing database keeps its
  saved value.

### Findings worth carrying forward

- **An unreadable read is not an absent read.** DTRK-06's rule — hold the last known state while an
  aura cannot be read — ended up carrying reminders, alternatives and the load rule's in-combat
  hold. `scripts/aura-read-gate.js` is its standing selftest.
- **A readable expiry is worth taking when it is offered.** Reminders sync their timer to a readable
  aura expiry, which is what lets a reminder show mid-combat when its buff runs out, even though the
  aura itself is unreadable by then.
- **Retail M+ confirms the expected limit, not a bug.** Inside a key, an aura the player cancels by
  hand is not picked up, because auras are secret there. No Lua errors, and reminders and the load
  rule behave the same inside the key.
- **Schema steps are proven in node before they run in game.** Every migration (v8-v11) was written
  first as a spec in `scripts/migrate-dryrun.js`, then mirrored in Lua, then checked by a real
  logout/login. All four ran without loss on real saved data on both clients.
