## Phase Details

### Phase 12: Schema Migration + Data Tables
**Goal**: The addon ships complete spell and item lookup tables for all tracked trinkets and potions, registered in the CDM Suggested section. Schema v3 is terminal for v0.2.3 (no migration needed — first release with these features).
**Depends on**: Phase 11
**Requirements**: DATA-01, DATA-02, DATA-03 (N/A — documented)
**Success Criteria** (what must be TRUE):
  1. TRINKET_SPELLS contains exactly 9 entries, each with spellID, itemID, and duration matching trinket_info.csv
  2. POT_SPELLS contains exactly 4 entries, each with spellID, itemID, and duration matching pots_info.csv
  3. ns.SUGGESTED_BUFFS contains trinket and pot entries; CDM Suggested section renders all three (lust + trinket + pot) without Lua errors
  4. DATA-03 reconciled as N/A in REQUIREMENTS.md with rationale documented in InitBuffEngine; schemaVersion remains 3
**Plans**: 2 plans
- [ ] 01-PLAN.md — TRINKET_SPELLS and POT_SPELLS data tables + derived item ID sets (Wave 1)
- [ ] 02-PLAN.md — SUGGESTED_BUFFS entries, CDMTab getCDMIcon nil guard, DATA-03 reconciliation (Wave 2)

### Phase 13: Timer Functions + Cast Detection
**Goal**: Casting any tracked trinket or pot spell creates a correctly keyed timer in the correct meta-slot, and both entries appear in the CDM Suggested section
**Depends on**: Phase 12
**Requirements**: TMR-01, TMR-02, TMR-03, TMR-04, CDM-01, CDM-02
**Success Criteria** (what must be TRUE):
  1. After casting a tracked trinket spell, a running timer appears for that trinket's known duration with no Lua errors
  2. After casting a tracked pot spell, a running timer appears for that pot's known duration with no Lua errors
  3. Casting a second tracked trinket spell while a trinket timer is already active removes the old timer and starts a fresh one — only one trinket timer is ever active at a time
  4. The trinket and pot entries appear in the CDM tab Suggested section alongside the Lust entry, and can be dragged to Bars or Buffs
  5. The timer key is the actual spellID so the existing aura scan cancellation path removes the timer when the buff drops
**Plans**: 2 plans
- [x] 13-01-PLAN.md — OnSpellCastSucceeded fan-out with trinket/pot meta-slot timers and shared-slot overwrite (Wave 1)
- [x] 13-02-PLAN.md — In-game verification of CDM Suggested entries and spell ID accuracy, debug log cleanup (Wave 2)

### Phase 14: Icon Resolution + Caching
**Goal**: At-rest CDM and Display icons for trinket and pot meta-slots reflect the player's actual equipped gear and bag contents, refreshed on CDM settings open (combat-gated). ICON-06 (PLAYER_EQUIPMENT_CHANGED / BAG_UPDATE_DELAYED hooks) is reconciled as N/A — refresh piggy-backs on StartPreview per CONTEXT D-03/D-04.
**Depends on**: Phase 13
**Requirements**: ICON-01, ICON-02, ICON-05, ICON-06 (N/A — documented), ICON-07
**Success Criteria** (what must be TRUE):
  1. The trinket Suggested entry shows the icon of the first matching equipped trinket (slot 13 or 14); if neither slot matches the tracked list, it falls back to the first CSV-order entry whose icon resolves
  2. The pot Suggested entry shows the icon of the first matching damage pot found in bags; if none are found, it falls back to the first CSV-order entry whose icon resolves
  3. Opening the CDM settings window while out of combat triggers a fresh icon scan and the displayed icons (Suggested + Bars + Buffs) update to reflect current equipment and bags
  4. Bars/Buffs at-rest rendering for trinket/pot slots routes through ns:GetAtRestMetaIcon (D-12) — no longer falls back to the GetSpellIcon Bloodlust/?-icon
  5. Lust at-rest rendering remains class-aware (D-13 — getCDMIcon=nil branch preserved)
  6. During combat or when InCombatLockdown() returns true, inventory scanning is skipped entirely and the last cached icon is shown without error or cache mutation
  7. ICON-06 documented as N/A in REQUIREMENTS.md with D-04 rationale
**Plans**: 2 plans
- [x] 14-01-PLAN.md — ns.metaIcons cache, RefreshMetaIcons (combat-gated, CSV-ordered fallback), GetAtRestMetaIcon helper, SUGGESTED_BUFFS getCDMIcon wiring, ICON-06 reconciliation (Wave 1)
- [x] 14-02-PLAN.md — CDMTab StartPreview hook, Display.lua bar+icon placeholder fix, in-game verification checkpoint (Wave 2)

### Phase 15: Display Integration + Active Icon Switching
**Goal**: While a trinket or pot timer is active, the icon shows the specific cast spell; when the timer expires, the icon reverts to the resolved at-rest icon
**Depends on**: Phase 14
**Requirements**: ICON-03, ICON-04
**Success Criteria** (what must be TRUE):
  1. Immediately after casting a tracked trinket spell, both the CDM Suggested entry icon and any display bar/buff icon switch to the icon for that specific cast spell
  2. Immediately after casting a tracked pot spell, both the CDM Suggested entry icon and any display bar/buff icon switch to the icon for that specific cast spell
  3. When the timer expires naturally (countdown reaches zero), the CDM and display icon reverts to the resolved at-rest icon (equipped trinket or bag pot)
  4. nil spellID and nil icon values do not cause Lua errors in CDMTab.lua or Display.lua at any point in the active/expired transition
**Plans**: 1 plan
- [x] 01-PLAN.md — Verification-only; Phase 15 requirements already satisfied by Phase 13 (timer.icon = cast spell icon) and Phase 14 (placeholder branch reverts to at-rest icon). User-approved in-game smoke test.
