# Milestone v0.3.0: WoW Forever compatibility

**Status:** ✅ SHIPPED 2026-09-19

**Total Plans:** 12
**Interface:** 120100 (Midnight retail) + 16001 (Forever beta) — first multi-flavour release
**Timeline:** 2 days (2026-09-18 → 2026-09-19), 57 commits

## Overview

TBT became a two-flavour addon. One shared Lua/XML source set now loads on both WoW Midnight retail
and the WoW Forever beta, selected by two flavour-suffixed TOCs, with no forked source file and no
runtime flavour branch anywhere in the codebase. The milestone was scoped as metadata and tooling only
and was deliberately widened once, mid-flight, to admit two user-facing capabilities without which it
could not be tested at all.

For current project status, see `.planning/ROADMAP.md`.

## Milestone Summary

**Decimal Phases:**

- **Phase 27.1: Forever Testing Enablers (INSERTED)** — inserted after Phase 27, mid-milestone, on
  explicit user approval 2026-09-18. v0.3 was scoped parity-only; this phase deliberately widened it,
  because the milestone was otherwise untestable. There was no way to discover a working Forever spell
  ID on that client without a diagnostic tooltip, so `VER-04` — the milestone-deciding requirement —
  could not be exercised at all. TOOL-01 unblocked it; META-01 removed three tiles that could never
  carry a value on Forever.

**Key Decisions:**

- **Split flavour TOCs (`_Mainline` + `_Camelot`) over one multi-interface TOC.** The client picks its
  own TOC with no reliance on comma-form interface parsing, and CurseForge/Wago receive correctly
  tagged per-flavour uploads. Verified on both clients.
- **The two TOCs may differ on `## Interface:` and `## Notes:` only.** Enforced by
  `scripts/check-toc.ps1` as a pre-tag guard, not by convention. Proven to actually fail via four
  independent negative tests before it was trusted.
- **No rollback TOC.** The user rejected keeping a third unsuffixed `TerribleBuffTracker.toc` as a
  safety net, which is what made `VER-01` a hard blocking gate rather than a deferred cleanup item.
- **Two flavour-pure zips, not one multi-flavour zip.** The packager's own recommended path for split
  TOCs is a single zip tagged for both game versions, and it needs no CI changes at all. The user chose
  two zips so each download carries only its own TOC. Cost accepted knowingly.
- **No `WOW_PROJECT_ID` flavour branching anywhere.** Every Forever difference found this milestone
  turned out to be a data-absence condition already detectable with a nil check. The constraint held
  end to end: zero flavour-detection tokens exist in any Lua file.
- **META-01 hides meta tiles by catalog resolution, not by flavour.** The user suggested a flavour
  guard; the locked constraints forbid one. The data-driven test has a property the guard would not: a
  future Forever build that ships lust spells makes the tiles reappear with no code change.
- **Cleanup-phase scope settled.** `CLAUDE.md`'s "unify repeated behaviour" mandate scopes to
  duplication the milestone itself introduced; `PROJECT.md`'s "No refactors during cleanup phases"
  protects everything pre-existing. Phase 30 is where the two rules first collided. Settled by user
  decision 2026-09-18; both documents now name each other.

**Issues Resolved:**

- `GetScaledCursorPositionForFrame` is absent from Forever's engine. `CDMTab.lua`'s ghost-frame
  `OnUpdate` called it every frame of every drag — 53 errors in one session. Fixed in `9e32f92` by
  reusing the `GetCursorPosition()`/`GetScale()` idiom the file's three other cursor sites already
  used, removing the dependency rather than shimming it. **Pre-existing since v0.2.0, not a v0.3
  regression.** The lesson generalises: an engine-side global present on Midnight is not guaranteed on
  Forever.
- The Lust Suggested tile rendered an empty tooltip on Forever, because `GetDisplayInfo` always
  returned a numeric spellID and `SetSpellByID` was called on a spell that does not exist there. Fixed
  by probing `C_Spell.GetSpellInfo` once before taking that branch (`9fde1eb`).
- Trinket and Pot at-rest tiles presented an unresolved hardcoded retail item as if it were real. Four
  unconditional `FALLBACK_ORDER[1]` sites removed in favour of a shared neutral placeholder. The
  placeholder carries `duration = 0`, **not `nil`** — `BuffEngine.lua:283` computes
  `now + info.duration`, so nil would throw. This corrected a real retail bug too, and is the one
  place v0.3 deliberately changed retail behaviour.
- An aura tooltip hovered in combat threw on a secret value. `RelatedID` compared a possibly-secret
  return with no `issecretvalue()` guard; the `pcall` did not cover it, because the call succeeded and
  the comparison after it raised. Note `type()` reports `"number"` for a secret number, so a type check
  alone passes and gives false confidence. Fixed in `19c4ddc`.
- A line-ending-only change produced a literally empty `git diff`. With `core.autocrlf=true` and no
  `.gitattributes`, every text file hashed as LF in the index while sitting as CRLF in the worktree, so
  a tool that reflowed only line endings left no trace — twice, before anyone noticed. Root-caused with
  `stylua.toml` pinning `line_endings = "Windows"`, and the blind spot itself closed by
  `.gitattributes`.

**Issues Deferred:**

- **`DIST-03`…`DIST-07` — the only requirement-level gap at close.** Two distinctly-named zips, each
  flavour-pure, published to one release without clobbering, with correct game-version tags and correct
  `RELEASE_NOTES.md`. All five are designed against and statically verified, and none can be observed
  without a real tag push. Deferred by explicit user decision 2026-09-18. `29-01-SUMMARY.md`'s Deferred
  Verification table is the checklist.
- **Settings do not persist between sessions on the Forever beta.** A client-side bug, not TBT's: the
  file is written correctly on logout and is byte-identical to its `.bak`, but is never read back on
  login, so each session starts from defaults and then overwrites the saved file. Other addons are
  affected identically. No Forever API change exists to adapt to — `Blizzard_ClientSavedVariables` is
  present on both flavours and no new TOC directive governs it. Documented as a known issue in
  `CHANGELOG.md` and `README.md`.
- Four tooling todos under `.planning/todos/pending/`, all captured rather than fixed because each
  would be new behaviour outside the milestone's requirements.

**Technical Debt Incurred:**

- `install.bat` copies but never prunes, so every file ever deleted from the repo lingers in a deployed
  folder (`ConfigUI.lua`, removed in v0.2.0, is still sitting in `_retail_`). Pruning is new behaviour
  outside `INST-01`…`04`.
- The runtime file set is enumerated in three independent places — `install.bat`'s `FILES` list and both
  TOCs — with no guard tying them together.
- The nine-line shared ignore block in `.pkgmeta-mainline`/`.pkgmeta-camelot` has no drift guard.
  Confirmed structurally irreducible against the pinned packager source: no include/inherit/extends
  directive exists.
- `release.bat` tags whatever `HEAD` it runs from but always pushes `origin main`, with no branch
  guard. Run from the wrong branch it tags the wrong commit.
