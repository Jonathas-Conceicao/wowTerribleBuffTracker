<objective>
A Forever player carrying Headmaster's Charge is reminded when the party Intellect buff (18264) is
missing, and a click uses the staff (ROADMAP Phase 90; HCHG-01, HCHG-02, HCHG-03, HCHG-04, DOC-09;
decisions D-01..D-10 in 90-CONTEXT.md).

Purpose: Well-Rested (Phase 86) is the template: an item-offered row, loaded everywhere, item click.
This row differs in two places only: the offer asks the equipped main-hand slot instead of the bags
(new load-time opt `offerSlot = 16`), and the click uses the slot ("16") instead of "item:<id>", and
only while the staff is in that slot.

**D-04 decision (planner, from the code):** BAG_UPDATE -> ns:MarkItemCatalogueDirty does NOT fully
cover equipment changes. It fires for the bag the staff leaves or enters, but (a) nothing orders it
after the inventory slot updates, and (b) a change that touches no bag (destroying the equipped
staff from the slot) fires only PLAYER_EQUIPMENT_CHANGED. So this plan adds the cheapest trigger:
Core's existing PLAYER_EQUIPMENT_CHANGED branch calls the existing ns:MarkItemCatalogueDirty() (a
flag plus CDMTab.lua's coalesced, CDM-open-only rebuild) only when the event's slot is one an offer
row asks (a load-time set lookup; empty on retail, so retail is unchanged). No new event, no
per-frame work, no allocation.

Scope rule (ROADMAP): nothing else works differently. Every new branch is reached only by a def with
`offerSlot`, which is this row alone, and the Core re-marks are gated on that slot.

**Gate hygiene:** every verify gate below was run by the planner against the current source and
fails for the right reason (the new identifiers, counts or doc-check totals do not exist yet).

Output: Providers.lua, ReminderClick.lua, Core.lua, scripts/reminders-doc-check.js,
docs/REMINDERS.md, and this plan's SUMMARY. In-game verification is Phase 92 (VER-17), not here.
</objective>
