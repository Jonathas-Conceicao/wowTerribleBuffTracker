  <name>Task 1: Write scripts/check-toc.ps1 implementing D-14's three assertions</name>
  <files>scripts/check-toc.ps1</files>
  <action>
Create a standalone PowerShell guard (D-13 — PowerShell, not batch: batch cannot diff two file bodies while excluding allowlisted lines without real pain, and keeping it standalone lets a future CI step call it unchanged).

Shape:
- `param([string]$Root = (Split-Path -Parent $PSScriptRoot))` — default target is the repo root (the script lives in `scripts/`), and `-Root` lets the verification step below point the guard at throwaway copies to prove it actually fails. Set `$ErrorActionPreference = 'Stop'`.
- Accumulate failure strings in a list rather than throwing on the first one, so a run reports every problem at once. Print each as `FAIL: <message>`, print `check-toc: OK (<Root>)` when the list is empty. `exit 1` if any failure, `exit 0` otherwise. No network calls, no `git` calls, no writes to disk.
- Resolve `TerribleBuffTracker_Mainline.toc` and `TerribleBuffTracker_Camelot.toc` under `$Root`. If either is missing, that is a failure naming the missing path — not a silent pass.
- Read each with `Get-Content -Raw` and split on the regex `\r?\n`. That split is the line-ending-insensitivity mechanism required by D-05/D-14.2: the working-tree files are CRLF while git stores LF, so the guard must compare content, never bytes.

Assertion 1 (D-14.1) — interface ranges. From each file take the first line matching `^##\s*Interface:\s*(\d+)\s*$`. A missing or unparseable directive is a failure. The Mainline value must match `^12\d{4}$`; the Camelot value must match `^16\d{3}$`. Failure message must name the file, the value found, and the expected pattern — PITFALLS.md pitfall 2's whole point is that the packager's own stderr line is generic, so this one should not be.

Assertion 2 (D-14.2) — body parity. From both line arrays drop every line matching `^##\s*(Interface|Notes):` (the two lines D-01 allows to diverge, and only those). Trim trailing whitespace on each remaining line, then compare the two arrays element by element using ordinal, case-sensitive comparison. On mismatch, report the 1-based index of the first differing line and both sides' content; if the lengths differ, report both counts. This assertion is what enforces TOC-03's "identical file list" as a machine check rather than a convention. Do not special-case `CDMTab.lua` — it is correctly absent from both TOCs (it loads from `CDMTab.xml`), and since both files are compared against each other, any attempt to add it to one and not the other fails here.

Assertion 3 (D-14.3) — `.pkgmeta-<flavor>` cross-ignore, forward-looking. For the pair (`.pkgmeta-mainline` → must ignore `TerribleBuffTracker_Camelot.toc`) and (`.pkgmeta-camelot` → must ignore `TerribleBuffTracker_Mainline.toc`): if the file does not exist under `$Root`, print an informational `skip: .pkgmeta-<flavor> not present (Phase 29)` and continue — **absence is not a failure**, because those files are not created until Phase 29 and this phase only creates the guard. If the file does exist, it must contain a YAML ignore entry for the other flavor's TOC (a line matching `^\s*-\s*["']?TerribleBuffTracker_<Other>\.toc["']?\s*$`) and must not contain any entry naming its own flavor's TOC — "ignores exactly the other flavor's TOC" is both halves.

Do not add assertions beyond these three. In particular do not check git state, do not check `.pkgmeta`, and do not attempt to validate `## Category` or `## IconTexture` against Forever — those are open research questions, not guard material.
  </action>

# neg4: a missing TOC is a failure, not a pass
rm "$S/neg4/TerribleBuffTracker_Camelot.toc"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-toc.ps1 -Root "$(cygpath -w "$S/neg4")"; test $? -ne 0
# pos1: correct .pkgmeta pair passes, and LF-only copies still pass (CRLF insensitivity)
printf 'ignore:\n  - TerribleBuffTracker_Camelot.toc\n' > "$S/pos1/.pkgmeta-mainline"
printf 'ignore:\n  - TerribleBuffTracker_Mainline.toc\n' > "$S/pos1/.pkgmeta-camelot"
tr -d '\r' < "$S/pos1/TerribleBuffTracker_Camelot.toc" > "$S/pos1/tmp" && mv "$S/pos1/tmp" "$S/pos1/TerribleBuffTracker_Camelot.toc"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-toc.ps1 -Root "$(cygpath -w "$S/pos1")"; test $? -eq 0
rm -rf "$S"

Per D-12, insert the guard invocation into `scripts/release.bat` **after** the `=== Releasing TerribleBuffTracker %VERSION% ===` banner and **before** the `git -C "%SOURCE%" tag -a "%TAG%"` line. It is a pre-tag guard (TOC-05): it must run while there is still nothing to clean up. Nothing else in the file changes — the tag, the push, and their existing error handling stay exactly as they are.

Match the file's established failure shape (`if errorlevel 1 ( echo ERROR: ... exit /b 1 )`): echo a short banner, invoke `powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0check-toc.ps1"`, then an `if errorlevel 1` block that echoes an explicit abort message naming the guard and `exit /b 1`. Use `%~dp0` so the invocation works regardless of the caller's working directory, and rely on the script's own `-Root` default (the parent of `scripts/`) rather than passing a path — `release.bat` already computes `SOURCE` as `%~dp0..\\` with a trailing double backslash, which is fine for `copy` but not worth threading through a `-File` argument.

Do not add the guard to `scripts/install.bat` (D-12 offers it as optional; this plan declines — see `<hard_constraints>`).

**Do not run `scripts/release.bat` to test this.** It creates and pushes a tag. Verification is by reading the file and asserting ordering.

Commit: `feat(25): run TOC drift guard before tagging in release.bat (TOC-05, D-12)`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer intent → release tag | The guard is the last automated check between a drifted TOC pair and an irreversible pushed tag |
| guard script → filesystem | The guard reads arbitrary paths via `-Root`; it must never write, delete, or execute anything |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-05 | Denial of Service | `release.bat` release flow | mitigate | Guard runs before `git tag`, so a failure aborts with nothing to clean up; failure messages name the file, the value and the expectation rather than relying on the packager's generic stderr |
| T-25-06 | Spoofing | guard false-pass | mitigate | Four negative tests prove the guard actually fails (bad interface, drifted body, wrong `.pkgmeta` ignore, missing TOC); a guard that only ever passes is worse than none |
| T-25-07 | Tampering | `scripts/check-toc.ps1` execution context | mitigate | Invoked with `-NoProfile -ExecutionPolicy Bypass -File` and an absolute `%~dp0` path, so no profile script or working-directory ambiguity can alter behavior; the script itself performs no writes and no network I/O |
| T-25-08 | Elevation of Privilege | `-Root` parameter | accept | Local developer tool reading two text files from a caller-supplied directory; no privilege boundary is crossed |
| T-25-SC | Tampering | package-manager installs | accept | No npm/pip/cargo install exists in this plan; PowerShell and git are pre-existing system tooling, so the supply-chain legitimacy gate has no surface |
</threat_model>
