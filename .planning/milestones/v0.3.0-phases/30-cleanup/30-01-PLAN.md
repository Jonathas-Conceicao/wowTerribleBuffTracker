<planner_findings>
Established by direct reading of this repo during planning on 2026-09-18. Confirm each in the task that depends on it; carry all four into the SUMMARY.

1. **`TRINKET_FALLBACK_ORDER` has exactly one reference in the whole repo — its own declaration at `Providers.lua:176`.** Verified: `grep -rn "TRINKET_FALLBACK_ORDER" --include=*.lua .` returns that single line. The `ns.TRINKET_FALLBACK_ORDER` namespace export was already deleted in v0.2.4 Phase 24, so nothing outside the file can reach it either. `POT_FALLBACK_ORDER` by contrast has two references — its declaration at `:178` and `for _, itemID in ipairs(POT_FALLBACK_ORDER) do` at `:437`, inside `PotProviderMixin:RefreshAtRest`. That asymmetry is the whole of D-04 and it is the one thing this task must not get wrong.

2. **Five consecutive lines come out, not one.** `Providers.lua:172` is a shared header comment reading "Ordered fallback iteration in CSV order (consumed by TrinketProvider:RefreshAtRest / PotProvider:RefreshAtRest below)" — it names the trinket provider as a consumer, which has been false since Phase 27, so it cannot survive the array it describes. `:173-175` are Phase 27's three-line marker ("Flagged for Phase 30's dead-code sweep; do not delete without re-checking D-10") — textbook migration-history comment, which `30-CONTEXT.md`'s comment-scrub policy says to remove. `:176` is the declaration. `:177` is a separate, accurate, POT-specific comment ("Still the pot scan's real iteration order") and **stays**, as does `:178`. So the edit is: delete `:172`–`:176`, keep `:177`–`:178`. Net −5 lines, zero insertions.

3. **The `EditModeFrames.lua` commit will look empty, and that is correct.** `core.autocrlf=true` with no `.gitattributes`, so `git ls-files --eol` reports `i/lf` for all six Lua files: git normalises the working tree to LF before hashing. Converting a file's endings therefore produces a literally empty `git diff` — empirically confirmed during Phase 27.1 planning on `CDMTab.lua`. Expect `git show --name-only HEAD` after Task 2 to list **only** `stylua.toml`. Do not interpret the absent `EditModeFrames.lua` diff as a failed conversion, and do not try to force it into the commit. `git ls-files --eol` is the only witness this class of change has (D-11).

4. **`EditModeFrames.lua` carries no formatting risk.** Verified 2026-09-18 (and recorded in the pending todo): `stylua --check --line-endings Windows EditModeFrames.lua` reports a diff that marks *every line from line 1*, the signature of a whole-file line-ending difference rather than formatting problems. The file's formatting is already correct. Related: a `stylua.toml` that sets only `line_endings` leaves every other option at stylua's own defaults — which is exactly what the repo's prior `--line-endings Windows` runs used, since they passed no other flags. That is why Task 2 can assert zero `--check` diffs across all six files as a correctness gate on the config rather than treating it as a hope.
</planner_findings>
