## Planner Findings — Confirmed

All five planner findings were confirmed by direct code reading before implementation, with no contradictions found:

1. **Exactly one Suggested-tile render site (`CDMTab.lua`'s `def.key == "suggested"` branch).** Confirmed the two other `ns.SUGGESTED_KEYS` readers (context-menu add path, drag-drop add path) are only reachable from a rendered tile, so only the render site was gated — both add paths are byte-unchanged, confirmed by `git diff HEAD~1 HEAD -- CDMTab.lua` showing no `SetBuffSection`/`RemoveTrackedBuff` line touched.
2. **`ns:StartAllPreviewTimers` iterates `ns.db.trackedBuffs`, not `ns.SUGGESTED_KEYS`.** Confirmed in `BuffEngine.lua` — hiding a tile has no effect on preview timers, so no `BuffEngine.lua` change was needed.
3. **The one-shot memo cannot mis-fire early.** Confirmed `ns:RefreshTBTSections` is only reached from a user-triggered CDM open or drag/menu action, both long past `PLAYER_ENTERING_WORLD`. No invalidation hook was added (see Decisions).
4. **`SHARED_LUST_BUFFS_LOCAL` covers the full lust buff family.** Confirmed its five entries (`32182`, `2825`, `264667`, `80353`, `390386`, each with their variant arrays including `1243972` and `466904`) are a strict superset of what `LustProviderMixin:GetDisplayInfo` can name. Used directly; no fourth data table invented.
5. **`CDMTab.lua` referenced no spell API or catalog table before this plan.** Confirmed `grep -cE 'C_Spell|TRINKET_SPELLS|POT_SPELLS' CDMTab.lua` was 0 before editing and remains 0 after — the new accessor lives in `Providers.lua`, and `CDMTab.lua` only asks one memoised boolean question. `item.suggestedIndex = i` (a Phase 23 D-13 artifact, read nowhere) was left exactly as-is, still indexing `ns.SUGGESTED_KEYS`, not repointed at `suggestedSlot`.

## Decisions Made

- **No invalidation hook on the sticky memo** (finding 3): a future reader might mistake the missing hook for an oversight. It is deliberate — the memo can only be populated after `PLAYER_ENTERING_WORLD`, by which point the client's spell database is stable for the session, so re-checking would be wasted work with no observable benefit.
- **Lust's `HasResolvableCatalog` could not reuse `AnyCatalogSpellResolves`** because `SHARED_LUST_BUFFS_LOCAL`'s values are variant-ID arrays (e.g. `{32182, 1243972}`), not itemID-keyed definition tables like `TRINKET_SPELLS`. Wrote a direct primary-then-variants walk instead of distorting the shared helper's contract to fit two incompatible table shapes.
