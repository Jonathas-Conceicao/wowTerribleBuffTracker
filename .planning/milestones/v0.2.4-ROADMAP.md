## Phase Details

### Phase 17: Provider Skeleton + UserSpellProvider
**Goal**: The SpellProvider interface contract exists and UserSpellProvider routes cast detection through it — proving the dispatch loop works before any existing behavior is removed
**Depends on**: Phase 16
**Requirements**: PROV-03
**Success Criteria** (what must be TRUE):
  1. Providers.lua loads without error and ns.providers contains at least UserSpellProvider
  2. Casting a tracked user spell triggers UserSpellProvider.OnTrigger and produces a normalized ActiveProc with all required fields (key, icon, duration, label, expiresAt, source)
  3. All four provider interface methods (GetEventInterests, OnTrigger, GetPreviewInfo, GetAtRestInfo) are defined on the base mixin and callable on UserSpellProvider without error
  4. Existing timer bars appear and behave identically to v0.2.3 — no visual regression
**Plans**: 2 plans
- [x] 17-01-PLAN.md — Create Providers.lua with SpellProviderBaseMixin + UserSpellProviderMixin + ns.providers registry + ns:DispatchEventToProviders; update .toc load order
- [x] 17-02-PLAN.md — Replace BuffEngine.OnSpellCastSucceeded user-spell branch with dispatcher call; in-game verification checkpoint for Phase 17 success criteria

### Phase 18: TrinketProvider + PotProvider + BuffEngine Dispatch
**Goal**: All cast-triggered providers (user spell, trinket, pot) are active and BuffEngine routes events by declared interest rather than hardcoded if/elseif chains
**Depends on**: Phase 17
**Requirements**: PROV-02, LIFE-01
**Success Criteria** (what must be TRUE):
  1. Casting a trinket spell creates an activeProc keyed by stable slot key ("trinket1" or "trinket2") via provider dispatch — no metaSlot bridge code in BuffEngine
  2. Casting a pot spell creates an activeProc keyed by "pot" via provider dispatch — same overwrite semantic as before
  3. Re-casting the same trinket or pot slot overwrites the previous activeProc entry (replace-on-reproc) — timer restarts correctly
  4. ns.activeProcs is the single authoritative table; expiry sweep removes finished entries; no parallel timer tables remain
  5. BuffEngine.OnSpellCastSucceeded contains no event-specific if/elseif chains — only a provider dispatch loop
**Plans**: 3 plans
- [x] 18-01-PLAN.md — Extend Providers.lua: add TrinketProviderMixin + PotProviderMixin, relocate static data tables, update ns.providers order, add castSpellID to UserSpellProvider proc (D-17)
- [x] 18-02-PLAN.md — Remove static data locals and OnSpellCastSucceeded branches 1/2 from BuffEngine.lua; update ScanActiveTimersForCancellation to read timer.castSpellID with fallback (D-15/D-16); migrate Display.lua metaSlot dual-index to slot-key lookup (D-04)
- [x] 18-03-PLAN.md — Deploy via install.bat and human-verify in-game: trinket/pot reproc, cancellation, lust regression guard, preview guard (PITFALL-4)
