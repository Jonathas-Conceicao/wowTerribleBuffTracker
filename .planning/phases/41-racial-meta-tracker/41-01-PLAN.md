# Phase 41 — Plan 01: Racial Provider & Eureka! Stack Engine

**Created:** 2026-09-21
**Requirements:** RACE-02, RACE-03

## Approach

`LustProvider` is the template: a meta tile keyed by one stable string, a per-character resolution step,
and its catalogue colocated in `Providers.lua`. The racial tile is the same shape with one addition —
the proc itself carries mutable state (`proc.stacks`), because the aura APIs cannot be read under
restriction and casts are the only signal available.

**One tile, resolved by race, never by client.** `UnitRace("player")` returns
`localizedName, raceFile, raceID`. Resolution keys on the **numeric `raceID`**, not `raceFile` — a
numeric key cannot be defeated by a capitalisation assumption, which a string token silently could
(a miss there would mean Eureka! never fires and nothing would error). `RACIAL_SPELLS` ships exactly one
entry this milestone:

| raceID | race | spellID | duration | maxStacks | fallback label |
|---|---|---|---|---|---|
| `7` | Gnome | `1259817` | `15` | `3` | `Eureka!` |

**Absence from that map IS the unsupported state.** There is no `supported = false` flag and no list of
other races' spell IDs — the racial catalogue for the rest of the races is `RACE-06`/`RACE-07`, next
minor milestone. This is what makes `RACE-04`'s "starts no timer" true *by construction* rather than by
a guard someone could delete: for an unsupported race there is no spell ID to compare a cast against, so
`OnTrigger` cannot start anything.

**A second, client-shaped guard sits on top of the race match, and it is not a flavour check.** A
mapped racial counts as supported only when `C_Spell.GetSpellInfo(spellID)` resolves on this client. A
gnome on a client where `1259817` does not resolve therefore lands in the unsupported presentation
automatically. This is the codebase's existing capability / data-absence pattern (`AnyCatalogSpellResolves`,
`ns:IsSuggestedKeyResolvable`), and it adds **no** second reader of `ns.CLIENT_HAS_SPELL_RANKS` and no
second `GetBuildInfo` call.

**The backstop is not new code.** `expiresAt = startedAt + 15` is written once at start and never
touched again; `ns:GetActiveTimers` already expires and drops any proc whose `expiresAt` has passed.
Early expiry is the *only* new lifecycle path, and it is a removal, not a shortening. Both endings
therefore coexist without either knowing about the other: whichever comes first wins.

**Accepted over-consumption, recorded here so it is never re-opened.** `C_Spell.IsSpellHarmful` means
"can target an enemy", not "deals damage". Frost Nova spent a Eureka! stack the game did not; Polymorph
and similar will behave identically. Accepted by the user 2026-09-20 — over-consuming ends the tracker
early, under-consuming would leave a buff on screen the player no longer has, and the second failure is
worse. Unknown (nil / secret) answers count as qualifying for the same reason. This is **accepted
behaviour, not a risk to mitigate**, and no code may try to narrow it.

**Hot-path budget.** `OnTrigger` runs on every player cast. On the common path — no racial window open —
the cost is one memoised local read, one `nil` test and one table index. The two API calls
(`IsSpellHarmful`, `IsAutoAttackSpell`) happen **only** while a live racial proc with stacks exists and
the cast is not the granting cast. No `pcall` per cast, no table constructor per cast, and the resolution
table is built once per session and returned by reference.

## Tasks

1. **`Providers.lua` — catalogue and per-character resolution.**
   *Read first:* `Providers.lua` (whole file; `LustProviderMixin` at lines 503-676 and
   `UnresolvedDisplayInfo` at 251-258 are the two shapes being followed), `.planning/phases/41-racial-meta-tracker/41-CONTEXT.md`.
   After `LustProvider`'s `CreateFromMixins` line and before the `UserSpellProvider` build, add:
   - `local RACIAL_SPELLS = { [7] = { spellID = 1259817, duration = 15, maxStacks = 3, race = "Gnome", fallbackLabel = "Eureka!" } }`
     with a comment stating that the key is the numeric `raceID` (third return of `UnitRace("player")`),
     that absence from this table is the "not yet supported" state, and that `RACE-06`/`RACE-07` add the
     remaining races in the next minor milestone.
   - Two module-level constant line arrays for the CDM-preview tooltip, referenced by name and never
     rebuilt per hover:
     - `RACIAL_SUPPORTED_LINES = { "Tracks your racial ability.", "Ends early when its last stack is spent." }`
     - `RACIAL_UNSUPPORTED_LINES = { "Your racial is not supported yet.", "Only Eureka! (gnome) is implemented in this version.", "Use the + button to track it yourself." }`
   - `local function ResolveRacial()` — a **sticky, session-long** memoisation returning either a def
     table or `false`. Same rationale as `ns:IsSuggestedKeyResolvable`'s one-shot cache: a character's
     race cannot change, and the first call can only arrive from a cast or a CDM open, long after
     `PLAYER_ENTERING_WORLD`, so spell data is loaded. Body:
     read `local raceName, _, raceID = UnitRace("player")`; if `issecretvalue(raceID)` or
     `type(raceID) ~= "number"`, memoise `false`; look up `RACIAL_SPELLS[raceID]`; if found **and**
     `C_Spell.GetSpellInfo(def.spellID)` returns non-nil, memoise a def copy carrying
     `spellID`, `duration`, `maxStacks` and `label` (the resolved spell name, or `fallbackLabel`);
     otherwise memoise `false`. Store `raceName` (guarded by `issecretvalue` before any concatenation)
     for the unsupported label built in Task 2.
   *Acceptance:*
   - `grep -n '1259817' Providers.lua` — exactly one hit, inside `RACIAL_SPELLS`. It is one because the
     spell ID is a catalogue datum and nothing else may name it literally.
   - `grep -n 'RACIAL_SPELLS\[' Providers.lua` — exactly one hit (the single lookup in `ResolveRacial`).
   - `grep -n 'GetBuildInfo\|CLIENT_HAS_SPELL_RANKS' Providers.lua` — no hits. Phase 37's invariant is
     that these have one definition and one reader, both outside this file.
   - Reading the file shows `UnitRace("player")` called exactly once, inside `ResolveRacial`, and its
     result reached only after an `issecretvalue` guard.

     qualifying test treats as "unknown".

## Risks

- **`raceID` 7 must actually be Gnome.** Keyed numerically precisely because a wrong-cased `raceFile`
  would fail silently. If the live check in Phase 44 shows the tile unsupported on a gnome retail
  character, the first thing to print is `select(3, UnitRace("player"))` — a one-number fix in
  `RACIAL_SPELLS`, not a design problem.
- **`IsSpellHarmful` / `IsAutoAttackSpell` are called without `pcall`.** The research recorded both as
  `AllowedWhenTainted` with no secrecy flag, and an `issecretvalue` guard sits before every comparison,
  so a future secrecy flag degrades to "unknown → qualifies" rather than erroring. A `pcall` per cast was
  rejected as a hot-path cost. The probe used `pcall` because it was a probe.
- **Over-consumption on harmful-but-harmless spells is accepted behaviour, not a defect.** Frost Nova and
  Polymorph will spend a stack. Do not add a damage filter; no readable API distinguishes them.
- **A user who also adds `1259817` manually gets two independent trackers** — one keyed `"racial"`, one
  keyed numerically. Identical to a user manually adding a trinket buff ID today. Not a bug; the manual
  one is a plain buff tracker with no stack logic, which is `RACE-05` working as intended.
- **`proc.stacks` is mutated in place inside `ns.activeTimers`.** This is the only mutable proc field in
  the codebase. It is safe because `ns:GetActiveTimers` copies references, never values, and nothing
  else writes the field. Do not "fix" it by rebuilding the proc — rebuilding would reset `startedAt` and
  destroy the 15s backstop.
