# Phase 41 — Plan 02: Stack Count Display

**Created:** 2026-09-21
**Requirements:** RACE-02 (the "showing 3 stacks" half)

## Approach

No existing tracker shows a stack count, so this is a widget addition either way. The rule is to reuse
Phase 38's charge-count treatment rather than invent a second one — and Phase 38's own comment records
that its widget was copied field-for-field from Blizzard's `CooldownViewerBuffIconItemTemplate`
**`Applications`** frame. So the icon side is not a new widget at all: `icon.chargeCount.Current` already
exists, already sits where Blizzard puts an applications count, and is simply driven by a second source.

The bar side has no such widget yet. Blizzard's own `CooldownViewerBuffBarItemTemplate`
(`Interface/AddOns/Blizzard_CooldownViewer/CooldownViewer.xml`, the `Icon` sub-frame) carries an
`Applications` FontString: `NumberFontNormalSmall`, `justifyH="RIGHT"`, size `32 x 10`, anchored
`BOTTOMRIGHT (-5, 5)` inside the bar's icon frame. Copying that is the same act Phase 38 performed, not
a second treatment — TBT's `bar.iconFrame` is the exact analogue of Blizzard's bar `Icon` frame.

**The value is TBT's own integer, not a game value.** Phase 38's `ApplyChargeCount` is wrapped in
`ns:CanReadTable`, `issecretvalue` and a `pcall` because `C_Spell.GetSpellCharges` is
`SecretWhenCooldownsRestricted` and `MayReturnNothing`. `proc.stacks` is a number this addon computed
from its own cast counter and never read from an API. It therefore needs **none** of that machinery, and
a reviewer must not add it "for consistency" — a comment states this at both call sites.

**Hot-path shape.** Both render paths run every tick for every slot. Each gains one field comparison
(`_stacks ~= timer.stacks`) in the common case and touches the font string only when the number actually
changed — the same dirty-stamp pattern as the existing `icon._lastStart` and `bar._lastDuration`. Zero
table constructors are added; `ns:UpdateDisplay` keeps exactly the two pre-existing placeholder
constructors across its three render functions.

**Pool hygiene is the failure mode to design against.** Widgets are recycled across slot kinds. The
existing `if icon._cdKey then ... end` reset already handles cooldown→buff recycling; `icon._stacks`
must be cleared in that reset, in `ApplyCooldownSlot`'s generation block, and on the placeholder path,
or a recycled widget can show a stack count belonging to a different tracker.

  (timer / cooldown / placeholder) either sets or clears the stack text, so no path leaves it stale.
- `grep -n 'timer.stacks' Display.lua` — hits only inside the two timer branches; nothing reads
  `proc.stacks` outside a render path.

- **No in-game check in this plan.** Nothing produces a `stacks` field until Plan 01 lands, and nothing
  puts a racial tile on screen until Plan 03. Deferred to Phase 42 (Forever) and Phase 44 (retail):
  - *(Forever, Phase 42)* Every existing tracker — buff bars, buff icons, cooldown icons with a charge

  - *(Forever, Phase 42, **gnome**)* The stack number counts 3 → 2 → 1 on the icon and on the bar as
    qualifying casts go out. Eureka! works on Forever — measured there 2026-09-20 — so this belongs to
    Phase 42, not Phase 44. **Requires a gnome test character**; without one, record it unperformed.
  - *(Forever, Phase 42)* With the CDM tab open, a **supported** racial tile dragged into a container
    previews at its full stack count, because Plan 01 passes `info.stacks` into the preview proc.
  - *(Retail, Phase 44)* The same stack behaviour as a parity regression check.

## Risks

- **`NumberFontNormalSmall` may be absent on WoW Forever.** Engine-side globals present on Midnight are
  not guaranteed on Forever — `GetScaledCursorPositionForFrame` threw 53 errors for exactly this reason.
  `SetFontObject(nil)` leaves an unrendered font string rather than erroring, but if the Phase 42 pass
  shows a missing or mis-sized bar count on Forever, the fix is a nil-guarded fall back to
  `NumberFontNormal`, not a redesign.
- **The bar stack number shares the bar icon with the icon overlay texture.** Both are OVERLAY on
  `bar.iconFrame`; the font string is created after the overlay texture, so it draws on top. This mirrors
  Blizzard's own layer ordering in the same template.
- **A stacking tracker in a bar container shows both a countdown and a stack count.** Intended: the
  15s backstop is a real countdown and must stay visible, per `RACE-03`.
