<objective>
Point the Phase 57 "absent" runtime at reminder entries and remove the "present" path
(57.2-CONTEXT "Runtime (REM-03)", "Visibility option removed (REM-04)"). User direction,
2026-09-29: "the currently working system we have for reminders are great, we just need the UI
for setting it up to be updated". So this plan is deliberately small: the aura-state cache, the
watch tables (`ns.visibilityKeys`, `ns.visibilityAuraID`, `ns.visibilityWatch`,
`ns:RebuildVisibilityWatch`), `ns:RefreshAuraStates`, `ns:VisibilityGate`, `ns:VisibilityShowsIn`
and every Display.lua call site keep their names and structure. The names still describe what they
do (they gate a tracker's visibility on its aura), so they are NOT renamed.

What changes:
- the index build selects `ns:IsReminderEntry(entry)` (plan 01) instead of `entry.visibility`;
- `ns:VisibilityGate` answers for reminders (unknown hides);
- the "present" path and the visibility writes that only served timed buffs are deleted (REM-04);
- two small, separate additions for REM-03: the combat-start hide (the user's explicit choice) and
  "an unreadable read clears the state" instead of freezing it (REM-03: never a stale missing
  state; Phase 57 held its last state, and CONTEXT records this difference as deliberate);
- reminder containers default to Centered growth; stale SavedVariables comment in
  EditModeFrames.lua reworded (checker W1).

Output: Core.lua, BuffEngine.lua, Providers.lua (engine); Display.lua (comments and the centred
test), EditModeFrames.lua (DirectionOpts and a comment).
Do NOT run scripts/install.bat in this plan; plan 04 deploys.
</objective>
