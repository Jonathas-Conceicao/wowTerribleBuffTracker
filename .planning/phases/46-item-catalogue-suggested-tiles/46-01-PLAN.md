<interfaces>
Contracts this plan creates. Plans 02 and 03 consume these exact names and shapes — do not rename.

- `ns.ITEM_KEY_PREFIX` — string, `"item:"`.
- `ns:ItemKeyItemID(key)` — number itemID, or nil for anything that is not an `item:<digits>` key.
- `ns:RefreshItemCatalogue()` — rebuilds the cache unconditionally and clears the dirty flag. No
  return value.
- `ns:ItemCatalogue()` — returns the module-level itemID array **by reference**, ascending. Callers
  must iterate, never retain or mutate.
- `ns:ItemCatalogueIcon(itemID)` — number fileID, or nil when the icon was unreadable.
- `ns:ItemCatalogueCount(itemID)` — number, or nil when the count was unreadable.
- `ns:MarkItemCatalogueDirty()` — sets the dirty flag and returns. Does no scanning work itself.
- `ns:IsItemCatalogueDirty()` — boolean, read by Plan 02's coalescing consumer.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WoW client API -> TBT Lua | Every `C_Item.*` / `C_Container.*` return crosses here. Under Blizzard's Secret Value restriction a value may be present, truthy, and report `type(v) == "number"` while being unreadable. This is TBT's only real input boundary. |
| SavedVariables -> TBT Lua | `ns.db.trackedBuffs` membership is read (Plan 03). No write this phase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Tampering | `ns:RefreshItemCatalogue` numeric reads | mitigate | `issecretvalue(v)` evaluated before `type(v)` on `GetContainerItemID`'s id, `GetItemInfoInstant`'s `classID`/`subClassID`/`icon`, `GetItemSpell`'s spellID and `GetItemCount`'s count. A failed guard skips the value and degrades the row, never errors. |
| T-46-02 | Tampering | `GetItemSpell` truthiness test | mitigate | A secret non-nil spellID is truthy under a naive `if spellID then`. The guard runs before the truthiness test, so a secret value is treated as "no use-spell" and the item is excluded rather than admitted on false evidence. |
| T-46-03 | Denial of Service (self-inflicted, frame time) | catalogue scan placement | mitigate | Scan lives only in `ns:RefreshItemCatalogue`; the render path reads flat cached tables. Zero per-scan allocation, `table.sort` once per scan, no table constructor in any loop. |
| T-46-SC | Tampering | package installs | accept | Not applicable — this phase installs no npm/pip/cargo package. The addon calls first-party WoW client APIs only. No Package Legitimacy Gate needed. |
</threat_model>
