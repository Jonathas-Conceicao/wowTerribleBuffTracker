# Phase 57.3 Plan 01: Tracker Load Rule engine Summary

**One cached load rule per tracker. Built-ins get fixed rules, and user trackers use their saved `entry.load`, where nil means When known. The rule is resolved through a pcall-guarded spellbook check that also counts base spells, override spells and Forever rank families. Unloaded trackers are left out of every index and provider path, and racial tiles now come from "known" instead of from the character's race.**

## Deviations from Plan

None to the plan's intent. Two notes on execution:

- **Task 1:** The first draft had a file-local `AskKnownAny` helper that asked the four functions about one ID. With that helper, `ns:SpellKnownState` no longer contained `AskKnown(` itself, which the gate requires. Rather than change the gate, I rewrote `ns:SpellKnownState` to walk its candidate IDs in one loop (spell, then base, then override, then the cached rank family) and call `AskKnown` directly. This matches the plan text ("any AskKnown true means known"), allocates no table, and the helper is gone.
- **Task 2:** The `ns:IsRacialKeyVisible` header comment (kept until 57.3-02) named `ns:RacialDefsForPlayer`. I reworded it to "never a resolved list" so the name appears nowhere in the Lua, as the gate requires.
