## The three structures that must not be "simplified" (42-CONTEXT.md D5)

This plan touches both `MergeMode.lua` and `Display.lua`, so all three are restated here. Each
looks like redundancy, is not, and each was arrived at by fixing a bug the user reported:

1. **One aura container per merged entry per unit** (`MergeMode.lua`). An aura FRAME carries
   `DenyTaintedAccessWhenAurasAreSecret` and cannot be moved in combat; the CONTAINER carries no
   such restriction. TBT moves containers, never frames. Collapsing back to one container per unit
   breaks Centered growth outright. **Task 1 makes a comment agree with this shape — it must never
   change the shape to agree with the comment.**
2. **`ns:GridSlotPlacement` as the single source of grid arithmetic** (`Display.lua`), used by both
   Display and MergeMode. The two drifted three separate times when they each derived it.
3. **`entry.cdmShown`, stamped from Blizzard's own CDM item frames.** It looks like it duplicates
   an aura lookup. It does not — the aura APIs are secret in combat and the engine's own visible
   count is unreadable; the CDM's `IsShown()` is the one plain boolean available.
</constraints>

  <name>Task 2: Correct the two "a merged buff icon has no sweep" blocks in Display.lua</name>
  <files>Display.lua</files>
  <action>
Two comment blocks in `Display.lua` state at length that a merged buff icon cannot have a cooldown
sweep. It can, and does — in two different ways — and the play-testing pass on 2026-09-22 is what
made both available.

**Block A**, above `RelayMergedBar` (roughly lines 955-962): the paragraph beginning *"The same
trick does NOT extend to merged buff ICONS"* and ending *"A merged buff icon therefore still has no
sweep, and that is an API limit rather than an omission."*

**Block B**, above `RelayMergedIconTime` (roughly lines 1000-1014): the opening *"a deliberately
smaller promise: it relays the countdown TEXT only, never a sweep"* and the paragraph *"The sweep is
not possible and this is where that is recorded, so it does not get retried."*

What is actually true, and what each block must say instead:

- The **API argument in both blocks is still correct and must be kept**. Every Cooldown getter on
  the CDM's own widget is `SecretReturnsForAspect = { Cooldown }`; the numeric setters
  (`SetCooldown`, `SetCooldownDuration`, `SetCooldownFromExpirationTime`) are
  `SecretArguments = "AllowedWhenUntainted"`; `SetCooldownFromDurationObject` is the one
  tainted-safe setter and nothing hands out a duration object for an aura. Do not weaken, shorten
  or delete that reasoning — it is exactly the kind of hard-won constraint D4 exists to protect.
- What is false is the **conclusion drawn from it**. The impossibility is specific to *relaying* a
  sweep off the CDM's Cooldown widget. A merged buff icon gets a real sweep by two other routes
  that do not read a secret:
  1. **The engine draws it.** When `ns.mergeAuraGroupsActive` is true the aura-group path hands
     Blizzard a Cooldown through `SetDurationCooldown` and the engine binds the real duration
     object to it. TBT never sees a value.
  2. **TBT issues it** from plain numbers. `ResolveMergedAuraTiming` in `MergeMode.lua` writes
     `entry.auraExpiry` / `entry.auraDuration` when the aura was readable, and
     `RenderIconContainer` calls `icon.cooldown:SetCooldown(entry.auraExpiry -
     entry.auraDuration, entry.auraDuration)` on them, stamped on `icon._mergedExpiry`.
- `RelayMergedIconTime` is therefore **the fallback**, not the ceiling: it runs when
  `entry.auraExpiry` is absent, which is what restricted content gives — a number and no spiral,
  rather than nothing at all. The code in `RenderIconContainer` already says this correctly around
  the `SetCooldown` branch; make both header blocks agree with it.

Rewrite both blocks to scope the impossibility to the relay and to name the two routes that do
work, pointing at the `SetCooldown` branch in `RenderIconContainer` rather than restating its
detail a third time.

Change comment lines only. `RelayMergedBar`, `MatchMergedTimeFont` and `RelayMergedIconTime`
themselves — every executable line — are untouched.
