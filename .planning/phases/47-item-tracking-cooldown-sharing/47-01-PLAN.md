<objective>
Build the entire runtime state layer for tracked items in `Providers.lua`: the use-spell → itemID
map (D-01), the per-item cooldown read and stamp (D-02, D-04), the tracked-count store with its
decrement and reconcile (D-03), and the `ItemProviderMixin` that ties a landed
`UNIT_SPELLCAST_SUCCEEDED` to all of it.

Purpose: this is the only plan that adds game-API reads, so every `issecretvalue`-first guard and
every degrade rule lives here and nowhere else. Plans 02 and 03 consume the four `ns:` functions
this plan exports and make no `C_Item` call of their own.

Output: four exported functions plus one registered provider. **Nothing calls them yet.** Plan 02
wires creation and events, Plan 03 renders. The addon must load and behave identically after this
plan — a player who never drags an item tile sees no change at all.

<interfaces>
Contracts this plan creates. Plans 02 and 03 consume these exact names and shapes — do not rename,
and do not change a return type.

- `ns:TrackedItemCount(key)` — the tracked count for an `item:<itemID>` tracker key, as a number,
  or `nil` when no count has ever been readable for it. **Read by `Display.lua` only.** It is NOT
  `ns:ItemCatalogueCount`, which is the Suggested list's live bag-walk cache and has no entry for a
  zero-stock item.
- `ns:SeedItemTracker(key, itemID, entry)` — called once, at tracker creation, by
  `AddSuggestedTracker`. Seeds the tracked count from a guarded `C_Item.GetItemCount` and seeds
  `entry.duration` / `ns.cooldownStarts[key]` from a guarded `C_Item.GetItemCooldown` (D-05). No
  return value.
- `ns:RefreshTrackedItemCooldowns()` — re-reads `C_Item.GetItemCooldown` for **every** tracked item
  entry and re-stamps it (D-02, D-04). Not combat-gated. No return value.
- `ns:ReconcileTrackedItemCounts()` — reconciles every tracked item's count against
  `C_Item.GetItemCount` and prunes orphaned keys (D-03). **Combat-gated internally**, so callers may
  call it unconditionally. No return value.

Module-local, never exported, never read from another file:

- `itemUseSpellToID` — `useSpellID -> itemID`. Wiped with the four existing catalogue tables.
- `itemTrackedCounts` — `"item:<itemID>" -> number`. Runtime-only, never persisted, never wiped by
  the catalogue rebuild.
