<objective>
Add the **render half**: TBT-owned instances of Blizzard's two virtual pandemic FX templates,
attached to TBT's mirrored icon and bar widgets, toggled purely with `Show()`/`Hide()` from Plan
01's resolver.

Purpose: this plan touches no CDM object at all. Every frame it creates is TBT-owned from
`CreateFrame` up, which is exactly what makes `Show`, `Hide`, `SetPoint`, `SetScale` and
`SetFrameLevel` on them taint-free — the locked rule is about frames TBT does **not** own.

Output: two lazy creators, two dirty-checked toggles, and one call site each in
`RenderIconContainer` and `RenderBarContainer`. After this plan the feature is code-complete and
Plan 03 gates it in game.

**Genuinely new surface.** Instantiating a Blizzard virtual FX template by name has no prior
instance anywhere in TBT — every existing `CreateFrame` in `Display.lua` builds a plain
`Frame`/`StatusBar`/`Cooldown` or uses `CooldownFrameTemplate`. There is no way to probe a virtual
template's existence ahead of use, so **both** creation calls are `pcall`-guarded and degrade to
"no highlight" (PAND-05, S10).

Locked decision IDs D-01..D-06 are listed in `48-01-PLAN.md`'s objective and apply unchanged.
</objective>
