# Phase 05.1 Plan 01: containerSettings DB Init and Display Refactor Summary

**ns.db.containerSettings schema initialized in Core.lua and Display.lua refactored to read bar/icon display settings from DB via RefreshContainerSettings() instead of hardcoded tables**

- **Completed:** 2026-03-29
- **Tasks:** 2 of 2

## Accomplishments
- Core.lua ADDON_LOADED now initializes `ns.db.containerSettings` with per-container defaults (bars + buffs sub-tables) if not present
- Display.lua hardcoded `cachedBarSettings`/`cachedIconSettings` table literals replaced with empty declarations populated by `RefreshContainerSettings()`
- `ns.RefreshContainerSettings` exposed on namespace so Plan 02 settings popup can trigger a cache refresh after writing to DB
- Visibility mapping translates new 4-value DB enum to existing `visibleSetting` + `hideWhenInactive` fields — `ShouldShow()` unchanged
- Deployed to WoW addons folder via install.bat

**Plan metadata:** (pending docs commit)

## Files Created/Modified
- `Core.lua` - Added `ns.db.containerSettings` init block in ADDON_LOADED handler
- `Display.lua` - Replaced hardcoded cached settings tables with empty declarations + `RefreshContainerSettings()` function

## Decisions Made
- Scale stored as integer percentage (100 = 1.0x) rather than float, for slider compatibility. Divided by 100 at read time in `RefreshContainerSettings`.
- `visibility=1` (Active Only) chosen as default to match old `hideWhenInactive=true` default per D-11.
- Used `RefreshContainerSettings` pattern (called once, not per-frame) rather than `GetBarSettings()`/`GetIconSettings()` (called per-UpdateDisplay) to preserve zero-allocation hot path per CLAUDE.md pattern guidance.
