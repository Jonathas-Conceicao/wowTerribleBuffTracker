**2. Add CreateSelectedOverlay function** (module-level, after CreateEditModeOverlay):
```lua
local function CreateSelectedOverlay(container)
    local overlay = CreateFrame("Frame", nil, container, "NineSliceCodeTemplate")
    overlay:SetAllPoints(container)
    overlay:SetFrameLevel(container:GetFrameLevel() + 11) -- above highlight (+10)
    overlay.ignoreParentAlpha = true
    NineSliceUtil.ApplyLayout(overlay, SELECTED_NINESLICE_LAYOUT)
    overlay:Hide()
    return overlay
end
```

**3. Add selection state variables** (module-level):

**6. Refactor OnEditModeEnter** to use click-vs-drag detection per D-03.

Replace the existing OnMouseDown/OnMouseUp scripts for both overlays with a `WireSelectableDrag` helper function that:
- `OnMouseDown("LeftButton")`: records `dragStartX, dragStartY = GetCursorPosition()`, calls `container:StartMoving()`

Apply `WireSelectableDrag` to both bar and icon overlays in `OnEditModeEnter`, passing the correct container and key.

Replace the stub `ShowSettingsPopup`/`HideSettingsPopup` from Task 1 with the full TBTSettingsPopup singleton implementation.

**1. Create the singleton popup frame** (module-level `CreateSettingsPopup` function):
- `CreateFrame("Frame", "TBTSettingsPopup", UIParent, "ResizeLayoutFrame")` per D-06
- frameStrata="DIALOG", frameLevel=200, ClampedToScreen=true
- Add `DialogBorderTranslucentTemplate` border child (set `border.ignoreInLayout = true`)
- Add title `FontString` using `GameFontHighlightLarge`, anchored TOP with offset -15
- Add `VerticalLayoutFrame` child as `popup.Settings` with `spacing = 2`, anchored below title
- Set `popup.widthPadding = 40` and `popup.heightPadding = 40` (matching EditModeSystemSettingsDialog XML)
- Create `popup.pools = CreateFramePoolCollection()`, register pools:
  - `popup.pools:CreatePool("FRAME", popup.Settings, "EditModeSettingDropdownTemplate")`
  - `popup.pools:CreatePool("FRAME", popup.Settings, "EditModeSettingSliderTemplate")`
- Store in module-level `tbtSettingsPopup`
- popup:Hide() initially

**2. Implement `ns:ShowSettingsPopup(containerKey)`** (replaces the stub):
- Lazily create popup via `CreateSettingsPopup()` if nil
- Release all controls: `popup.pools:ReleaseAll()`
- Set title: "TBT Bars" or "TBT Buffs"
- Read current settings from `ns.db.containerSettings[containerKey]`
- Use helper functions `AddDropdown(labelText, settingKey, options, containerKey)` and `AddSlider(labelText, settingKey, minVal, maxVal, stepSize, containerKey)`:

  **AddDropdown:** Acquire from `EditModeSettingDropdownTemplate` pool. Set `frame.Label:SetText(labelText)`. Set `frame.layoutIndex`. Wire `frame.Dropdown:SetupMenu` with `rootDesc:CreateRadio` options. The radio's `setSelected` callback writes directly to `ns.db.containerSettings[containerKey][settingKey]` and calls `ns:RefreshContainerSettings()` for real-time preview. Do NOT call `SetupSetting` (anti-pattern from RESEARCH.md Pitfall 1). `frame:Show()`.

  **AddSlider:** Acquire from `EditModeSettingSliderTemplate` pool. Set `frame.Label:SetText(labelText)`. Set `frame.layoutIndex`. Wire `frame.Slider.Slider` via callback registry: `frame.Slider:RegisterCallback(MinimalSliderWithSteppersMixin.Event.OnValueChanged, handler)` where handler writes to DB and calls `ns:RefreshContainerSettings()`. Initialize with `frame.Slider:Init(currentValue, minVal, maxVal, steps)`. `frame:Show()`.

  **Controls per container type (D-04):**
  - **Both containers:**
    - Orientation dropdown: "Vertical" (value=1), "Horizontal" (value=0)
    - Growth Direction dropdown: For bars: "Down" (0), "Up" (1). For buffs: "Right" (0), "Left" (1). When orientation is horizontal for bars, show "Right" (0), "Left" (1) instead.
    - Scale slider: min=50, max=200, step=5 (percentage). Use formatter that appends "%".
    - Padding slider: min=0, max=20, step=1
    - Visibility dropdown: "Always" (0), "Active Only" (1), "In Combat" (2), "Hidden" (3)
  - **Bars only:**
    - Bar Width slider: min=100, max=400, step=10

- Call `popup.Settings:Layout()` then `popup:Layout()` after all controls added (Pitfall 2)
- Anchor popup per D-07: `popup:SetPoint("LEFT", container, "RIGHT", 10, 0)`. If popup right edge would exceed `UIParent:GetWidth()`, anchor below instead: `popup:SetPoint("TOP", container, "BOTTOM", 0, -10)`.
- `popup:Show()`

**3. Implement `ns:HideSettingsPopup()`** (replaces the stub):
- If `tbtSettingsPopup` exists and is shown, hide it and release all pools.

**4. Wire real-time preview:** Each control's value-change callback writes to `ns.db.containerSettings[containerKey][settingKey]` then calls `ns:RefreshContainerSettings()`. The next OnUpdate tick of Display.lua picks up the cached values naturally — no explicit `UpdateDisplay()` call needed (per RESEARCH.md Open Question 2).

**5. Scale slider note:** DB stores integer percentage (50-200). Slider shows 50-200 with "%" suffix. `RefreshContainerSettings()` in Display.lua already divides by 100. So the slider value IS the DB value — no conversion needed in the popup.

**ANTI-PATTERNS TO AVOID (from RESEARCH.md):**
- Do NOT call `SetupSetting` on acquired template frames — it routes to EditModeSystemSettingsDialog
- Do NOT use `EditModeManagerFrame:SelectSystem` — TBT frames are not registered
- Do NOT hook `EditModeSystemSettingsDialog` — use TBT's own popup
