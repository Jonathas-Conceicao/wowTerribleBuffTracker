Interfaces from earlier plans (runtime `ns` calls; ReminderClick.lua loads right after Display.lua):
- `ns:MarkReminderClicksDirty()` (63-02) -- cheap, combat-safe, schedules one flush per dirty edge.
- ReminderClick's flush reads, per collected icon: `icon._clickKey` (tracker key), `icon.containerKey`,
  `icon.proc` (tooltip payload), `icon:GetRect()`, `GetEffectiveScale()`, `GetFrameStrata()`,
  `GetFrameLevel()`.

Interface this plan defines:
- `ns:CollectReminderClickIcons(out) -> count` -- wipes `out`, appends every pooled icon with a
  non-nil `_clickKey` that `IsVisible()`, walking `ns.CONTAINERS` and the file-local `pools`.

Hot-path rules (CLAUDE.md): `ns:UpdateDisplay` runs every UPDATE_INTERVAL (0.05 s). The stamp work
added to RenderIconContainer is a handful of comparisons per slot with no allocation, no API call and
no GetRect; the dirty call fires only on a change. The hidden-container path must not walk the pool
every tick: gate it on a per-container flag.

Edit Mode (Phase 61): do not add any call to an `EditModeManagerFrame` method. The popup's checkbox
frames come from TBT's own `popup.pools` (a TBT-created pool collection), so hooking their Button's
scripts is safe.

Source files are CRLF (`.gitattributes` eol=crlf). Edit with the Edit tool (or the scratchpad
node-script route: assert the old string occurs once, `split(old).join(new)`, `\r\n` endings; never
`sed -i`, never a redirect). Locate code by function/identifier name, never by line number.
File-local upvalue order trap: any new local helper in Display.lua must be declared ABOVE
RenderIconContainer / UpdateDisplay, its callers. `CHANGELOG.md` is never opened for writing.
