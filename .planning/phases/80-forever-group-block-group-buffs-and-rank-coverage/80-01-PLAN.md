<objective>
Make a group buff, a Greater Blessing or any rank of an existing Forever class buff hide its reminder
on WoW Forever, retire Blessing of Salvation and Blessing of Light, and leave retail exactly as it is.
Data-only: Providers.lua's reminder table changes; no matching, watch, cast or click code changes.

Purpose: today a Forever reminder shows while Arcane Brilliance, a Greater Blessing, or a rank the
player does not know (e.g. another mage's Arcane Intellect 10157 on a level-30 mage) is on the
player, because the rank family only joins ranks in the player's own spellbook (research §12.1).
The fix is one-way alternatives through the existing MetaReminderGroup. Several of the IDs (21562,
1459, 1126, 6673, 465) are also retail row IDs, so all Forever group calls go in one
`if ns.CLIENT_IS_FOREVER then … end` block (RALT-04).

Output: Providers.lua only, plus this plan's SUMMARY. The gate script
`.planning/phases/80-forever-group-block-group-buffs-and-rank-coverage/80-check-groups.js` was written
and tested by the planner (it fails on the current source and passes on a mock of the target, which
`stylua --check` accepts). The executor runs it and does not edit it.

Decisions implemented (80-CONTEXT.md has no D-NN numbers; decisions are cited by heading):
- "Scope rule": data through MetaReminderRow / MetaReminderGroup only; MetaReminderGroup unchanged;
  every ID from research §12.3.
- "The Forever block (RALT-04)": one block after the rows; the blessings call moves into it; the
  retail Devotion call stays outside; a comment above the block gives the reason.
- "Group buffs and ranks (RALT-05/06/07)": §12.3 calls verbatim for existing rows, no 1038/19979,
  no Blood Pact extra IDs; the armor, class-row and familiar groups are Phases 81-82's and are NOT
  added here; the header comment is updated.
- "Removed blessings (MREM-06)": delete the rows, add the internal note beside the Sanctuary note.
- "Claude's Discretion": comments on their own line above each call, never inside a multi-line call
  or trailing a call inside the block (stylua CRCRLF trap); verification by source trace.

Planner's placement choice: the block goes at the END of the table, directly after the retail
`MetaReminderGroup(465, 317920, 32223)` line and before `function ns:MetaReminderDef`. That is
"after the rows" for every row, including the Forever rows Phases 81-82 add above it, so those phases
only append calls inside the block. On Forever the retail rows are not registered, so the order
relative to the retail Devotion call has no effect.
