# Phase 40 — Plan 01: Mirror Data Source

**Created:** 2026-09-21
**Requirements:** STEAL-03, STEAL-05, STEAL-06

## Approach

This plan builds the data half of steal mode and nothing else. It renders nothing, hides nothing and
touches no Blizzard frame at all — every call it makes is into the `C_CooldownViewer` / `C_Spell`
namespaces, which the injection experiments proved readable from tainted addon code
(`.planning/research/TEST-PLAN-CDM-INJECTION-AND-COOLDOWNS.md`, "DIRECTION SET BY USER — mirror, do not
join": *"Which spells the user chose to track | `GetCooldownViewerCategorySet(category, allowUnlearned)`
| yes — namespace API, no frames"*).

**Everything lives in one new file, `StealMode.lua`.** That is deliberate and it is what makes
`STEAL-08`'s code-level half cheap: after Plan 03, `StealMode.lua` is the only file in the addon that
names a CDM viewer frame for steal purposes, so "TBT never writes to or calls into a CDM frame" is a
single-file diff read rather than a whole-repo audit. `install.ps1` derives the deployed file set from
the TOC (`INST-09`), so adding the file to `TerribleBuffTracker.toc` is the whole deployment change.

**Container → CDM category.** `ns.CONTAINERS` already carries `cdmViewerGlobal` per base def. This plan
adds the missing half, `cdmCategoryName`, as a **string** resolved against `Enum.CooldownViewerCategory`
at runtime. A string, not the enum value, because a file-scope `Enum.CooldownViewerCategory.Essential`
would be a load-time dependency on an enum that may not exist on every flavour; resolving by name behind
a nil check is the capability check `PROJECT.md` mandates, not a client-identity check.

| container key | kind | `cdmViewerGlobal` | `cdmCategoryName` | enum value on 12.1 |
|---|---|---|---|---|
| `buffs` | icon | `BuffIconCooldownViewer` | `TrackedBuff` | 2 |
| `bars` | bar | `BuffBarCooldownViewer` | `TrackedBar` | 3 |
| `essential` | icon | `EssentialCooldownViewer` | `Essential` | 0 |
| `utility` | icon | `UtilityCooldownViewer` | `Utility` | 1 |

Verified against `Blizzard_CooldownViewer/CooldownViewer.xml` lines 298-336, where each viewer frame's
`cooldownViewerCategory` KeyValue is set, and against
`Blizzard_APIDocumentationGenerated/CooldownViewerConstantsDocumentation.lua`. User containers never get
a `cdmCategoryName`, which is exactly what makes steal mode base-container-only with no extra branching.

**`STEAL-06` is structural, not a feature.** One flag, `ns.db.stealMode`, gates the whole refresh. There
is no per-category field to add, and `ns.stealSlots` is keyed by container so a per-category toggle would
require new storage that this plan deliberately does not create.

**What a mirrored entry is, and what it is not.** Each entry is a plain table shaped like a tracker entry
so `Display.lua` can render it through the existing widgets with no new code path:

```
key        = "cdm:<cooldownID>"    -- stable slot identity; string, cannot collide with a numeric DB key
spellID    = overrideSpellID or spellID
label      = spell name, or "" when unreadable
section    = container key
trackerType= "cooldown" for essential/utility, "buff" for buffs/bars
isStolen   = true
```

Mirror entries **never enter `ns.db.trackedBuffs`** and are never persisted — they are a read-only
projection of the CDM, rebuilt from scratch on every refresh. Nothing in TBT may reorder, move or delete
one; there is no code path that writes to a mirror entry after `ns:RefreshStealMirror` builds it.

**The known fidelity limit, stated up front.** `C_CooldownViewer.GetCooldownViewerCategorySet` returns
the game's **static** category set for the player's learned spells. The player's own re-ordering and
re-categorisation inside the CDM settings UI live in Blizzard's Lua data provider
(`CooldownViewerSettings:GetDataProvider():GetOrderedCooldownIDsForCategory`) and in the opaque
`C_CooldownViewer.GetLayoutData` blob. Reading the data provider would be a Blizzard Lua mixin call, which
this milestone forbids, so the mirror follows spec, talents, learned spells, spell overrides and hotfixes
but **not** manual re-categorisation. Filtering replicates what Blizzard's own provider does with the
same static data (`CooldownViewerSettingsDataProvider.lua:110-126, 249-260`): drop `isInvisible`, drop
`isKnown == false`, drop the `HideByDefault` flag.

**Hot path.** `ns:UpdateDisplay` runs at 20 Hz. Nothing in this plan runs on that path — the refresh is
event-driven, exactly like Phase 38's `ns.cooldownGeneration`. `Display.lua` (Plan 02) only ever indexes
`ns.stealSlots` and reads `#`. Table construction inside `ns:RefreshStealMirror` is fine and expected: it
runs on a spec change, not on a frame.

2. **`StealMode.lua` — new file: the mirror builder.**
   *Read first:* `Core.lua` lines 1-52 (registry shape) and 294-312 (`ns.cooldownGeneration` /
   `ns:MarkCooldownsDirty`, the event-driven-cache idiom to copy); `BuffEngine.lua` lines 20-30

   `.planning/research/TEST-PLAN-CDM-INJECTION-AND-COOLDOWNS.md` section "DIRECTION SET BY USER, 2026-09-20
   — mirror, do not join".
   Create `StealMode.lua` starting with `local addonName, ns = ...` (match `Core.lua` line 1; `addonName`
   may be discarded as `local _, ns = ...` in the style of `Display.lua` line 1 if unused).
   Open the file with a header comment stating the four prohibitions in one block: TBT never parents a
   frame into a Blizzard CDM frame, never writes a field on one, never calls a CDM mixin method, and never
   calls `C_CooldownViewer.SetLayoutData`. **Write API names in comments without a trailing `(`** so the
   negative call-form greps in Plan 03 stay meaningful.

   Build, in this order:
   - `ns.stealSlots = {}` and a file-scope loop over `ns.CONTAINERS` creating one empty array for every
     def that has a `cdmCategoryName`. This is the only creation site; the refresh only `wipe()`s. A
     container without `cdmCategoryName` keeps no array, so `ns.stealSlots[key]` is nil for user
     containers and `Display.lua` nil-guards it.
   - A local `ResolveCategory(def)` returning
     `Enum.CooldownViewerCategory and def.cdmCategoryName and Enum.CooldownViewerCategory[def.cdmCategoryName]`
     — nil on any client lacking the enum, which degrades the whole feature to a silent no-op rather than
     a load error.
   - A local `HIDE_BY_DEFAULT` resolved once as
     `Enum.CooldownSetSpellFlags and Enum.CooldownSetSpellFlags.HideByDefault`.
   - `function ns:RefreshStealMirror()`:
     - `for key, list in pairs(ns.stealSlots) do wipe(list) end` first, unconditionally.
     - Return immediately if `not ns.db` or `ns.db.stealMode ~= true` — off leaves every array empty,
       which is what makes the render path need no steal-mode branch at all.
     - Return immediately if `not C_CooldownViewer or not C_CooldownViewer.GetCooldownViewerCategorySet
       or not C_CooldownViewer.GetCooldownViewerCooldownInfo` (capability check, not a flavour check).
     - For each `def` in `ns.CONTAINERS` with a resolved category and an array in `ns.stealSlots`:
       call `C_CooldownViewer.GetCooldownViewerCategorySet(category, false)` — `false` is
       `allowUnlearned`, so the game does the learned-spell filtering. Guard the result with
       `ns:CanReadTable(ids)` before iterating.
       For each `cooldownID` in order: `local info = C_CooldownViewer.GetCooldownViewerCooldownInfo(cooldownID)`,
       guard with `ns:CanReadTable(info)`, then skip the entry when any of these hold —
       `info.isInvisible == true`, `info.isKnown == false`, or `HIDE_BY_DEFAULT` is set in `info.flags`
       (`bit.band(flags, HIDE_BY_DEFAULT) ~= 0`, only after `not issecretvalue(flags) and type(flags) == "number"`).
       These three filters mirror `CooldownViewerSettingsDataProvider.lua:110-126` and `:249-260`; add a
       comment saying so.
       Resolve the spell as `info.overrideSpellID or info.spellID`, and skip the entry entirely when that
       is not a readable number (`issecretvalue` first, then `type(...) == "number"`).
       Resolve the label via `C_Spell.GetSpellInfo(spellID)`; take `.name` only when
       `not issecretvalue(name) and type(name) == "string"`, otherwise `""`.
       `table.insert` an entry table of exactly the shape in **Approach** above, with
       `trackerType = (def.kind == "icon" and def.cdmCategoryName ~= "TrackedBuff") and "cooldown" or "buff"`
       — or any equivalent that yields `"cooldown"` for `essential`/`utility` and `"buff"` for
       `buffs`/`bars`. Do **not** branch on the container key string; branch on `cdmCategoryName`, per
       the Phase 35 registry contract.
       Set no `layoutOrder`: CDM order is preserved by insertion order, and Plan 02 appends mirrored
       slots after the user's own without re-sorting. Add a comment saying that.
   *Acceptance:* `grep -n 'function ns:RefreshStealMirror' StealMode.lua` matches once.
   `grep -n 'GetCooldownViewerCategorySet(' StealMode.lua` shows the call with a literal `false` second
   argument.
   `grep -n 'ns.db.trackedBuffs' StealMode.lua` returns nothing — mirror entries are never persisted.
   `grep -nE '_G\[|viewer' StealMode.lua` returns nothing in this plan — no CDM **frame** is referenced

   `grep -n 'issecretvalue' StealMode.lua` returns at least two hits (flags, spell name), each preceding

## Notes carried in from plan review

**The `STEAL-05` divergence is wider than re-ordering — put this in the code comment too.**

The live viewer’s displayed list comes from `CooldownViewerMixin:GetCooldownIDs()` →
`CooldownViewerSettings:GetDataProvider():GetOrderedCooldownIDsForCategory(category)`
(`CooldownViewer.lua:2066-2069`), which honours the player’s **persisted category overrides and
hidden-group overrides** (`SAVE_FIELD_ID_CATEGORY_OVERRIDES` / `SAVE_FIELD_ID_HIDDEN_GROUP_BUFFS`).
This plan’s source, `C_CooldownViewer.GetCooldownViewerCategorySet(category, false)`, returns the
**spec-default** categorisation and cannot see those overrides.

So the consequence is not merely “order may differ”. **A spell the player manually hid in the CDM can
still appear in the TBT mirror, and one they moved to another CDM category can appear in the wrong TBT
container.** Spec, talent, learned-spell, override and hotfix changes ARE followed correctly — the
common case, and the one the user’s decision text describes (“the player adds and removes spells there”).

Closing the gap needs a Blizzard mixin call, which the locked taint constraint forbids. Record
`STEAL-05` as **partially met**, and name the hide/recategorise case explicitly — not just ordering —
in the Risks section and in the comment above the mirror source.
## Risks

- **The mirror does not follow manual re-categorisation or re-ordering done in the CDM settings UI.**
  Established by reading `CooldownViewerSettingsDataProvider.lua:249-260` and
  `CooldownViewerSettingsDataStoreSerialization.lua:58-78`: that state lives in Blizzard Lua and in the
  opaque `GetLayoutData` blob, never in the C category-set API. Closing it would require calling
  `CooldownViewerSettings:GetDataProvider():GetOrderedCooldownIDsForCategory`, a Blizzard Lua mixin call,
  which this milestone forbids. Accepted for this phase and flagged to the user rather than worked around.
- **`GetCooldownViewerCategorySet` may return a set the viewer would further filter.** Mitigated by
  replicating Blizzard's own three filters (`isInvisible`, `isKnown`, `HideByDefault`) from the same
  source file. If the mirrored list still differs from what the CDM shows, the divergence is in those
  three predicates and is a one-line fix, not an architecture problem.
- **`TRAIT_CONFIG_UPDATED` and `PLAYER_SPECIALIZATION_CHANGED` may not exist on Forever.** Registration
  is pcall-guarded per event, so a missing event costs one silent `pcall` failure at load and nothing
  else. `SPELLS_CHANGED` and `PLAYER_ENTERING_WORLD` both exist on both flavours and already cover the
  realistic Forever cases.
- **A refresh can fire in combat** (`SPELLS_CHANGED` does). That is safe: the refresh reads namespace
  APIs and writes only TBT-owned tables. It touches no frame, so the combat gate belongs to Plan 03's
  visibility work and not here.
