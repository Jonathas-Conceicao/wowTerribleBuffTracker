# Phase 40 — Plan 02: Render the Mirror

**Created:** 2026-09-21
**Requirements:** STEAL-03, STEAL-04

## Approach

Plan 01 produced `ns.stealSlots[containerKey]` — an array of tracker-shaped entries, empty whenever steal
mode is off. This plan makes `Display.lua` draw them. It touches **no Blizzard frame and no Blizzard API**;
it reads one TBT table.

**The design goal is that there is no "steal mode" branch in the render path.** Off means the arrays are
empty, so the same code runs and appends nothing. The only new per-tick work is one table index, one `#`,
and one nil test per container.

**Mirror entries reuse the existing slot machinery rather than adding a fourth render kind:**

| container | mirror `trackerType` | branch it lands in | what the user sees |
|---|---|---|---|
| `essential`, `utility` | `"cooldown"` | the existing Phase 38 `ApplyCooldownSlot` branch | icon + engine-driven sweep + charge count, live in combat |
| `buffs` | `"buff"` | the placeholder branch, forced visible | icon + TBT styling, no countdown |
| `bars` | `"buff"` | the bar placeholder branch, forced visible | icon + spell name bar, no fill, no countdown |

**Why mirrored buff/bar slots carry no countdown, and why that is not a shortcut.** The only in-combat
aura source that exists for a tainted addon is a CDM item frame's `auraDataCached`
(`.planning/research/TEST-PLAN-CDM-INJECTION-AND-COOLDOWNS.md`, "VERDICT: P2.7"), and
`STEAL-02` hides the viewers. `CooldownViewerMixin:OnHide` unregisters `UNIT_AURA`,
`PLAYER_TARGET_CHANGED` and the rest, and `CooldownViewerMixin:RefreshLayout` only calls `RefreshData()`
`if self:IsShown()` — verified in `Blizzard_CooldownViewer/CooldownViewer.lua:1743-1755` and `:2055`. A
hidden viewer therefore stops producing aura data, and the direct `C_UnitAuras` route is a documented
hard error for tainted callers under restriction. Driving a mirrored buff slot from the spell's
**cooldown** instead would show a different number than the CDM shows and is rejected for the same reason
`CD-02` rejects the nominal-duration lie. So the mirrored buff slot is an honest configured-slot
indicator. Record this in a comment at the append site, with the two source-line citations.

**Ordering.** Mirror entries are appended **after** `table.sort(slots, ByLayoutOrder)` in both render
functions, never sorted into it. Two reasons: the user's own ordering is preserved exactly, and the CDM's
own order is preserved exactly, with no `layoutOrder` values to invent and no second `table.sort` per tick
(`table.sort` is not stable, so re-sorting the timers-only bar branch would jitter).

**Visibility.** A container whose only contents are mirrored items must still show.
`RenderIconContainer`'s `hasActiveIcons` and `RenderBarContainer`'s `hasActiveTimers` both need the
mirrored count folded in, or `hideWhenInactive` (on by default) hides the whole container and `STEAL-03`
fails in the default configuration. `cooldownSlotCounts` deliberately counts only `ns.db.trackedBuffs`
(Phase 38) and mirror entries are never in the DB, so the count must come from `#ns.stealSlots[key]`.

**Read-only.** Nothing in this plan writes to a mirror entry, and the CDM tab's drag-and-drop, delete
zone and reorder code in `CDMTab.lua` all operate on `ns.db.trackedBuffs` keys — a mirror entry's
`"cdm:<id>"` key is not in that table, so there is no path by which TBT can reorder, move or delete one.
This plan must not create one.

**Hot-path budget.** `ns:UpdateDisplay`, `RenderBarContainer` and `RenderIconContainer` currently contain
zero table constructors apart from the two pre-existing placeholder `proc = { ... }` lines already filed
for Phase 43. This plan adds **none**; the mirrored-entry branches assign `bar.proc = slot` /
`icon.proc = entry` directly, exactly the trick `ApplyCooldownSlot` already uses ("The DB entry itself is
the tooltip payload").

- `grep -c 'stealSlots' Display.lua` is 2, one per render function, and neither hit is inside

- `grep -n 'isStolen' Display.lua` — three hits total (two in `RenderIconContainer`, one in

- `grep -rn 'stealSlots\[' CDMTab.lua EditModeFrames.lua BuffEngine.lua Providers.lua` — no hits. Only

  CDM tab can reorder, move or delete a mirrored item.
- `stylua --check .` exits 0.
- No in-game check in this plan. Steal mode cannot be switched on until Plan 03 wires the toggle; all
  arrays are empty and the visible behaviour of the addon is unchanged. That "unchanged" is itself the
  check: `/tbt` still shows the four containers exactly as before.

## Risks

- **A mirrored slot could collide with a user tracker's slot identity.** Mirror keys are the string
  `"cdm:<cooldownID>"` and DB keys are numeric spell IDs, so `activeByKey[slot.key]` can never match a
  timer for a mirrored slot and `icon._cdKey` can never alias. Verified by reading how `entry.key = dbKey`
  is assigned in both render functions.
- **A pooled widget recycled from a user cooldown to a mirrored buff slot could keep a stale sweep.**
  The existing `if icon._cdKey then ... icon.cooldown:Clear() end` reset already guards the placeholder
  branch, and mirrored buff slots land in that branch. Confirm by reading, do not add a second reset.
- **Two containers could both grow by the mirror at once, changing Edit Mode hit areas.** That is
  intended: the containers size themselves from `#slots` and mirrored slots are real slots. No position
  is written, so no saved layout moves.
- **Mirrored buff and bar slots show no countdown.** Measured limitation, not a scope reduction —
  `CooldownViewerMixin:OnHide` kills the only in-combat aura source and `C_UnitAuras` hard-errors for
  tainted callers under restriction. Both citations are in **Approach** and must appear as a code
  comment. If the user wants countdowns there, the trade is leaving Blizzard's buff viewers visible,
  which contradicts `STEAL-02`.
