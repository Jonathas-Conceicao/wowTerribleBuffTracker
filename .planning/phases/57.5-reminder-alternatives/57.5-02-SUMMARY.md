# Phase 57.5 Plan 02: Reminder alternatives at runtime and the blessing data Summary

A reminder is now satisfied by its own buff or any alternative, whether that buff is present or its timer is running from a cast. Casting an alternative starts every reminder that lists it. The five paladin blessings satisfy each other, Righteous Fury is a built-in row, and Blessing of Sanctuary is gone (it takes the orphan path).

## Decisions (as planned)

- **Watched set.**
  - A reminder's own list is `ns.visibilityWatch[key]`, or `{ ns.visibilityAuraID[key] }` when that is nil.
  - Each alternative contributes `ns:CastRuleFamily(altID)`.
  - The union is deduplicated with a numeric `ListContains` loop and built only in `ns:RebuildVisibilityWatch`. It is published as both `ns.visibilityWatch[key]` and `ns.satisfiedByWatch[key]`.
  - A reminder with no alternatives keeps exactly its old list.
  - The existing content-compare invalidation runs on the final list. A content-equal combined list, such as after an in-combat SPELLS_CHANGED, therefore keeps its state.
- **`ns:CastRuleFamily`.** The cast rule's family expansion moved verbatim into one ns-level helper.
  - Forever: `ns.endRuleFamilies` cache.
  - Retail: a fresh `{ id }` plus the base/override IDs.
  - `ns:RebuildDetailedRuleIndex` uses it for both lists. The file-local `IndexFamily` (the old inner "already" loop) builds both indexes.
- **Cast index.** `ns.alternativeKeysBySpell[id] = { reminderKey, ... }` is built in the same walk as `ns.endKeysBySpell`, and only for loaded reminders.
  - OnTrigger does one lookup and skips `reminderKey` and `metaReminderKey`.
  - It calls `ns:StartReminderFromCast(altKey, tracked[altKey], true)` and redraws once if any reminder started.
- **Latest expiry.** The list loop in `ns:RefreshAuraStates` no longer breaks at the first present aura.
  - `seenAura` is the present aura with the latest readable expiry, or the first present aura when none has a readable expiry.
  - `present` and `allReadable` keep their meaning.
  - Reads go through `ReadWatchedAura`. Its memo tables are wiped at the start of each call and are never rebuilt.
- **The cast rule leaves reminders.** The endOnCast index condition is now `(buff-like and not reminder) or USER_CD`. `ns:ApplyEndOnCast(endKeys, startingCdKey, startingBuffKey)` only clears buff timers and resets user cooldowns.
- **Built-in data.**
  - The load-time `MetaReminderGroup(...)` is called once, for 20217, 25291, 25290, 1038 and 19979.
  - `ns:ApplyMetaReminderDef` writes `entry.alternatives = def.alternatives` when the reference differs. A row with no group, such as Righteous Fury, clears the field.
  - Sanctuary's row was deleted. `ns:IsOrphanMetaReminder` (57.4 WR-02) already greys a placed one with "no longer offered" and deletes no data.

## Why ScanActiveTimersForCancellation, VisibilityGate and the re-check need no change

- **`ns:ScanActiveTimersForCancellation`** ends a proc only when NONE of its `aliveBuffs` is readably present ("if ANY is present, the proc is alive"). A reminder with alternatives carries the combined list (`ns:FillUserBuffProc`), so its timer ends only when no aura in the set is on the player. When it ends, `ns.visibilityAuraID[key]` is set, so the state becomes false and the reminder shows.
- **`ns:VisibilityGate`** reads only `ns.auraState[key]` and the running timer. Both are written by the paths above, so the gate needs nothing new.
- **The post-cast re-check** (`ns:QueueCastAuraRecheck`, 57.4 CR-01) is still queued by `ns:StartReminderFromCast` for every reminder an alternative starts.
  - When it runs, `ns:RefreshAuraStates` reads the whole combined set. If none of it is on the player (the blessing went to someone else), the grace has passed, the timer ends and the state becomes false, so the reminders come back about 0.6 s later.
  - `ns:ScanActiveTimersForCancellation` reaches the same conclusion from `aliveBuffs`.

## Performance notes

- **Cast path.** A miss costs one extra table lookup (`ns.alternativeKeysBySpell[spellID]`). A hit costs a numeric loop over a prebuilt array and one redraw. Nothing is allocated.
- **`ns:FillUserBuffProc`** gains one table lookup.
- **`ns:RefreshAuraStates`** calls `wipe` twice per call and reads each watched ID at most once per call. It builds no table.
- **Family expansion** (`ns:CastRuleFamily`) runs only at rebuild time.
