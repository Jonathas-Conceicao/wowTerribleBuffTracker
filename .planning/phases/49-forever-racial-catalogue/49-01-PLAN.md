<objective>
Replace the two-slot racial model (`racial` / `racial2`) with a per-racial, spellID-keyed model,
and add the no-duration guard that everything else in this phase depends on.

Purpose: **D-4 / RACE-10** requires one tracker entry per racial, visible only to its own race.
The two fixed slots cannot express that. This plan builds the whole addressing and resolution
layer — the key namespace, the per-race resolvers, the race-visibility predicate, the provider
rewrite and the no-duration guard — so that plans 02-04 only add data, UI and lifecycle on top of
it. **D-7** retires the "not yet supported" tooltip constants as dead code in the same pass, since
the tile they live on is exactly what this plan deletes.

Output: five new `ns:` functions, one new key namespace, a rewritten `RacialProviderMixin`, and six
deleted symbols. **No new race data is added here** — that is plan 02, which must not run until the
no-duration guard below exists (FOREVER-RACIALS.md, open questions 2 and 6: four of the collected
racials apply no aura at all, and `now + nil` raises on the first cast).

**Known intermediate state, closed by plan 03.** After this plan, `keyToProvider` no longer maps
`"racial"` / `"racial2"`, and nothing mints `racial:<spellID>` keys yet. A player who already
tracks a racial sees a question-mark placeholder until 49-03's migration re-keys their entry. This
is expected; do not add a compatibility shim for it.

Locked decisions implemented here:

| ID | Decision |
|----|----------|
| D-4 | Every racial becomes its own race-gated tracker, keyed like `item:<itemID>` |
| D-7 | RACE-09 is obsolete; `RACIAL_SUPPORTED_LINES` / `RACIAL_UNSUPPORTED_LINES` are deleted |
| — | The no-duration guard in `StartRacialProc` (FOREVER-RACIALS.md open question 2) |
</objective>
